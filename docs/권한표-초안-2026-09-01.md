# 역할별 쓰기 권한표 초안

> 최신 결정은 [`권한정책-결정표-2026-09-07.md`](./권한정책-결정표-2026-09-07.md)를
> 우선한다. 이 문서의 `결정 필요` 표시는 당시 감사 시점의 기록이다.

2026-09-01. **정책 SQL을 만들기 전 합의용 문서**다. 운영 DB는 읽기만 해서
현재 정책·grant·컬럼을 확인했고, 클라이언트 쓰기 호출은 TypeScript AST로 셌다.

## 실측

- 역할: `user`(봉사자) / `leader`(인도자) / `admin` / `developer`
- 직접 쓰기: **30개 표 · 176개 호출** (`insert/update/delete/upsert`)
- RPC: **39종 · 42개 호출**
- 현재 쓰기 관문: TEMP 83개 + 역할별 최종 정책 6개
- `admin`과 `developer`는 서버의 `request_is_admin()`에서 같은 관리자군으로 본다.

⚠ 예전 문서의 “30개 표 · 287곳”은 현재 코드와 맞지 않는다. 287은 오래된 수치다.

## 표 읽는 법

- **A**: `admin` 또는 `developer`
- **L**: `leader`
- **U**: `user`
- **본인**: 현재 세션 사용자와 행의 소유자가 같음
- **담당**: 현재 사용자가 배정받았거나 인도하는 카드/일정
- **결정 필요**: 화면 동작만으로 업무 정책을 확정할 수 없음

화면에서 버튼을 숨긴 것은 권한 근거가 아니다. 특히 관리자는 `viewMode`로 다른 역할
화면을 볼 수 있으므로, 서버는 반드시 세션의 **실제 역할**을 사용해야 한다.

## 표 밖의 쓰기: RPC 39종

표 정책만 좁혀도 `security definer` RPC는 RLS를 우회한다. 운영 함수 본문을 감사한 결과:

- 사전 로그인 공개 2종: `auth_login`, `signup_tx`
- 세션 없이 읽기만 하는 2종: `preview_data_cleanup`, `count_old_visit_histories`
- 나머지 35종: 세션 또는 역할 검사 존재

단, “검사 문자열이 있다”는 사실만으로 권한이 맞다는 뜻은 아니다. 역할별 전환 때
아래 변이 RPC를 표와 함께 매트릭스로 검증한다.

| RPC 묶음 | 목표 권한 |
|---|---|
| `create_notice_tx`, 관리·정리 RPC | A |
| `update_calendar_event*_tx` | A 또는 해당 일정 인도자 |
| `assign_cards_bulk_tx` | A 또는 해당 일정 인도자 |
| `import_building_tx`, `merge_duplicate_buildings_tx` | A 또는 승인된 L 범위 — **결정 필요** |
| 채팅 send/delete/read RPC | 해당 일정 참가자·인도자·A |
| 알림·push·읽음 RPC | 본인 |
| 이름 변경·정리 RPC | A |

### 제거해야 할 클라이언트 폴백

`assign_cards_bulk_tx`가 없을 때 클라이언트가 세 배정 표에 직접 쓰는 레거시 폴백이
남아 있다. RPC 권한 오류에는 폴백하지 않도록 고쳤지만, 새 회중에서 함수가 빠지면
다시 직접 쓰기 경로가 활성화된다. 마이그레이션이 필수인 지금은 폴백을 제거하는 편이
안전하다. [eventAssignments.ts](../src/hooks/storeMutations/eventAssignments.ts#L124)

## 제안 순서

1. **P1 완료**: `special_periods`와 `login_logs` 열린 직접 쓰기를 2026-09-01 운영에서 차단.
2. **도구 파일럿 `chat_room_mutes` 완료**: 소유권 매트릭스·변형·운영 API smoke 통과.
3. **다음: 첫 실사용 파일럿 `comments`**: 운영 데이터가 있고 실패가 눈에 보인다. nullable 소유권은 위의 fail-closed 계약으로 처리.
4. **관리자 전용 단순 표**: `territory_regions`, `service_suggestions`, `informal_groups`, `phone_surveys`는 운영 적용 완료.
5. **일정 묶음**: `calendar_events` + 참가자 + 세 종류 배정. RPC 중심.
6. **구역 묶음**: cards/buildings/units/visits. 업무 정책 합의 후 마지막.

한 표마다 테스트 DB에서 `U/L/A × SELECT/INSERT/UPDATE/DELETE × 본인/남의 행`
매트릭스를 통과시킨다. SELECT는 기존 공개 범위와 Realtime 실제 이벤트 수신을 함께
확인한다. 그 기능의 실제 API smoke와 `npm run smoke:all` 전체 회귀를 본 뒤 운영에
적용한다. GitHub CI는 DB 비밀값을 받지 않으므로 이 수동 관문을 대신하지 않는다.
