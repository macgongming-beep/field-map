# 역할별 권한 정책 결정표

2026-09-07 기준 공유·구현용 문서다. 확정된 업무 규칙과 아직 결정하지 않은 제안을
구분한다. 화면에서 버튼을 숨기는 것만으로 권한을 제한하지 않고, 서버 RLS와 RPC가
같은 계약을 강제해야 한다.

## 역할

- **U**: 일반 사용자
- **L**: 인도자
- **A**: 관리자 또는 개발자
- **담당**: 배정받은 구역·일정 또는 정기방문·재방문의 지정 담당자

## 확정된 결정

### 건물·세대 구조

| 작업 | U | L | A | 서버 계약 |
|---|---|---|---|---|
| 건물 등록 | 허용 | 허용 | 허용 | 승인된 로그인 사용자만 |
| 기존 건물에 세대 등록 | 허용 | 허용 | 허용 | 승인된 로그인 사용자만 |
| 건물 이름·주소 수정 | 요청 | 허용 | 허용 | L/A 전용 RPC |
| 건물 종류 수정 | 불가 | 허용 | 허용 | L/A 전용 RPC |
| 세대 호수·장소 종류 수정 | 요청 | 허용 | 허용 | L/A 전용 RPC |
| 세대 삭제 | 요청 | **직접 허용** | 직접 허용 | L/A 삭제 RPC만 사용 |
| 건물 삭제 | 요청 | **직접 허용** | 직접 허용 | L/A 삭제 RPC만 사용 |

인도자의 구조 수정·삭제 범위는 **회중 전체 구역**으로 확정한다. 일정 배정 권한과
장소 자료 정비 권한은 서로 다른 업무이므로, 인도자가 오늘 인도하는 일정이나 본인에게
배정된 카드로 장소 정비 범위를 제한하지 않는다.

### 일반 사용자의 등록과 취소

일반 사용자는 건물 등록, 기존 건물의 세대 등록과 일괄 추가를 할 수 있다. 기존 자료의
건물명·주소·종류·소속 구역, 세대 호수·장소 종류는 직접 바꾸지 않고 수정 요청을 보낸다.

자신이 잘못 등록한 자료는 다음 조건을 모두 만족할 때 **등록 후 10분 안에 취소**할 수 있다.

- 현재 세션 사용자와 서버에 저장된 등록자 ID가 같다.
- 등록 후 10분이 지나지 않았다.
- 방문기록·정기방문·재방문·식당/일정 배정 등 연결 자료가 없다.
- 건물 취소라면 포함된 세대도 모두 같은 등록 작업에서 새로 만들어졌고 연결 자료가 없다.

일괄 추가에는 서버가 생성한 묶음 ID를 저장한다. 취소할 때는 그 묶음에서 새로 생성된
세대만 지우며, 등록 전에 존재하던 세대와 중복으로 건너뛴 세대는 건드리지 않는다.
시간이 지났거나 연결 자료가 생겼으면 일반 삭제로 전환하지 않고 수정·삭제 요청을 보낸다.
등록자·등록 시각·묶음 ID는 클라이언트가 주장하는 값을 믿지 않고 서버 RPC에서 기록한다.

## 삭제와 감사 기록

인도자에게 건물·세대 삭제를 허용하더라도 표의 직접 `DELETE` 권한은 열지 않는다.
삭제는 토큰과 실제 역할을 검사하는 `SECURITY DEFINER` RPC 한 경로로만 처리한다.

삭제 RPC는 한 트랜잭션 안에서 다음 순서를 지킨다.

1. 대상 행을 잠그고 실제 역할이 L/A인지 확인한다.
2. 건물·세대와 연결 자료의 영향 범위를 다시 계산한다.
3. `service_logs`에 행위자, 대상, 사유, 영향 건수와 복구용 스냅샷을 기록한다.
4. 대상과 계약상 함께 지워지는 자료를 삭제한다.
5. 장소 변경 신호를 한 번 발행한다.

### 감사 로그 내용

| 항목 | 저장 내용 |
|---|---|
| 행위자 | 사용자 ID·표시 이름·실제 역할 |
| 작업 | 건물/세대 추가·수정·삭제 |
| 대상 | 대상 ID·건물명·주소·호수·카드 ID/이름 스냅샷 |
| 변경 | 수정 전·후 값 또는 삭제 전 최소 복구 스냅샷 |
| 영향 | 세대·방문기록·정기방문·재방문·식당/일정 배정 건수 |
| 사유 | 삭제·중요 수정 시 필수 입력 |
| 시각 | 서버에서 기록한 작업 시각 |

`service_logs`는 이미 일정·카드·행위자 스냅샷을 보존하고 관리자 조회 RPC를 제공한다.
장소 변경용 action과 details 계약을 추가해 재사용한다. 로그 기록 실패 시 실제 삭제도
실패해야 하며, 클라이언트가 로그를 별도로 보내는 방식은 사용하지 않는다.

## 데이터 관리 화면 후속 작업

관리자 PC의 데이터 관리에 **자료 변경 기록** 보기를 추가한다.

- 기본 목록: 시각, 작업 종류, 대상, 행위자, 영향 건수
- 필터: 기간, 추가/수정/삭제, 건물/세대, 행위자
- 상세: 변경 전·후 값, 삭제된 연결 자료 종류와 건수, 입력 사유
- 관리자·개발자만 전체 로그를 열람
- 인도자는 기존 계약대로 본인 담당 카드의 봉사 로그만 열람하며, 관리자용 데이터 관리
  화면에는 접근하지 않는다

복원 버튼은 감사 화면과 함께 바로 만들지 않는다. 먼저 스냅샷으로 수동 복구가 가능한지
검증하고, 자동 복원은 중복 ID·현재 자료와의 충돌 계약을 별도로 정한 뒤 추가한다.

## 정기방문·재방문 소유권

정기방문과 재방문은 등록자가 아니라 **현재 지정된 담당자**가 소유한다.

| 작업 | U | L | A |
|---|---|---|---|
| 본인 담당 항목 등록 | 허용 | 허용 | 허용 |
| 타인 담당 항목 등록 | 불가 | 허용 | 허용 |
| 본인 담당 항목의 메모·방문기록 관리 | 허용 | 허용 | 허용 |
| 본인 담당 항목 종료·활성 목록에서 제거 | **허용** | 허용 | 허용 |
| 타인 담당 항목 종료 | 불가 | 허용 | 허용 |
| 타인 담당 항목 재배정 | 불가 | 불가 | 허용 |
| 종료된 항목을 본인이 다시 맡아 재활성화 | 허용 | 허용 | 허용 |
| 항목과 과거 방문기록 영구 삭제 | 불가 | 불가 | 유지보수 경로만 |

일반 사용자의 `제거`는 활성 정기방문·재방문 목록에서 빠지는 **종료 처리**를 뜻한다.
담당 연결과 종료 사유·시각은 남기고, 기존 방문기록은 삭제하지 않는다. 담당자가
전출하거나 계정이 삭제되면 장소와 기록을 보존한 채 `재지정 필요` 상태로 전환한다.

## 일정·신청·배정

| 작업 | U | L | A |
|---|---|---|---|
| 일정 등록·삭제 | 불가 | 불가 | 허용 |
| 일정 내용 수정 | 불가 | 본인이 인도하는 일정만 | 허용 |
| 본인 봉사 신청·취소 | 허용 | 허용 | 허용 |
| 다른 참가자·손님 추가·제외 | 불가 | 본인이 인도하는 일정만 | 허용 |
| 일정별 구역·비공식·식당 배정 | 불가 | 본인이 인도하는 일정만 | 허용 |
| 상시 카드 담당·인도자 지정 | 불가 | 불가 | 허용 |

일정 인도자 권한은 계정 역할이 실제로 `leader`이고 해당 일정의 `leader_name` 목록에
본인 이름이 있을 때만 인정한다. 이름만 일정에 들어 있거나 인도자 화면을 열었다는 이유로
권한을 주지 않는다. 일정 수정과 일괄 배정 RPC도 같은 조건을 서버에서 다시 검사한다.

## 방문기록 수정·삭제

방문기록의 소유자는 기록에 저장된 방문자 이름이 아니라 **작성자 사용자 ID**로 판정한다.
기존 이름 기반 기록은 마이그레이션 전까지 현재 사용자 이름과 안전하게 연결하되, 앞으로
생기는 기록에는 작성자 ID를 서버에서 저장한다.

| 작업 | U | L | A |
|---|---|---|---|
| 방문기록 추가 | 허용 | 허용 | 허용 |
| 본인이 작성한 기록 수정 | **시간제한 없이 허용** | 허용 | 허용 |
| 다른 사람이 작성한 기록 수정 | 불가 | 사유 입력 후 허용 | 사유 입력 후 허용 |
| 기록의 방문자 변경 | 불가 | 사유 입력 후 허용 | 사유 입력 후 허용 |
| 본인이 작성한 기록 무효 처리 | **시간제한 없이 허용** | 허용 | 허용 |
| 다른 사람 기록 무효 처리 | 불가 | 사유 입력 후 허용 | 사유 입력 후 허용 |
| 기록 영구 삭제 | 불가 | 불가 | 유지보수 경로만 |

일반 화면의 `삭제`는 행을 지우지 않고 **잘못 기록함**으로 무효 처리한다. 원본 내용,
작성자, 수정·무효 처리자, 처리 시각과 사유를 보존한다. 기록을 무효 처리하면 세대의
현재 상태와 방문 시간 집계는 남아 있는 가장 최근 유효 기록을 기준으로 한 트랜잭션에서
다시 계산한다. 유효 기록이 없으면 미방문 상태로 돌아간다.

전체 백업 복원은 service role 유지보수 경로로 실행하며 `created_by_user_id`와 무효 처리
메타데이터를 백업값 그대로 복원한다. 데이터 관리 CSV에서 기록 ID가 없는 행은 복원이
아니라 **새 유효 기록 추가**이며, 삭제 표시가 있는 기존 행은 재삽입하지 않고 무효 처리한다.

## 보안 전환 적용 원칙

- 공지는 등록과 삭제만 지원한다. 수정 기능은 두지 않으며, 내용을 바꿀 때는 삭제 후 다시
  등록한다. 추후 수정 기능을 만들면 관리자 전용 서버 계약과 영향 행 검사를 함께 추가한다.
- 이번 전환은 INSERT·UPDATE·DELETE만 다루고 SELECT 정책은 변경하지 않는다.
- 건물·세대의 직접 DELETE 정책과 삭제 RPC를 같은 묶음에서 검증한다.
- U/L/A 각각 추가·수정·삭제 허용 및 차단을 실제 API로 시험한다.
- 관련 `SECURITY DEFINER` 함수가 동일한 역할 계약을 지키는지 함께 시험한다.
- 적용 묶음마다 preflight, 최근 백업, rollback, 실제 앱 저장 확인을 둔다.
