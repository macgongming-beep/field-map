# 모바일 일정 닫기·홈 정리·중국어 제목 및 조회 점검

- 결정일: 2026-11-18
- 상태: 데모 검증 중. 운영 변경 금지, 저녁 별도 승인 후 검토.
- 기반: 운영 코드 `3b848dd`와 전환 기록이 있는 `52fe6d5` 위의 전용 수정 브랜치.

## 변경

- 모바일 일정 상세에서 편집을 열 때 상세 ID를 지우지 않는다. 편집 중에는 상세를 감추고 X/취소 시 같은 상세로 복귀한다. 기존 편집기에도 별도의 뒤로가기 층을 둔다.
- 관리자 홈의 운영 현황과 관련 집계만 제거한다. 같은 컴포넌트를 쓰는 PC 홈에도 적용한다. 구역 관리·통계 데이터 및 권한은 변경하지 않는다.
- 새 일정 목록의 제목은 버튼의 600에서 `strong`의 상대 굵기로 900이 되던 것을 기존 제목과 같은 600으로 고정한다. 중국어 제목은 `zh-Hans`와 기기 기본 중국어 글꼴을 지정한다. 한국어 제목은 기존 글꼴을 유지하며 외부 글꼴 다운로드는 추가하지 않는다.
- 모바일 홈의 유효한 `openEvent` 상세는 캘린더와 동일한 건물 이름·세대 번호 조회를 사용한다. 미확인 주소/PC 홈은 그대로 두고, 구역 배정 편집기의 `FullBuildingGate`는 유지한다.
- DB·권한·배정 저장·알림·운영 환경변수는 변경하지 않는다.

## 실측과 한계

실제 운영 기능 설정을 사용하되 DB는 데모에만 연결한 로컬 빌드로 측정했다. 운영 부하 시험은 하지 않았다.

- 수정 전 집단 상세 → 수정 → X가 상세를 잃는 현상을 브라우저에서 재현했다. 수정 후 Chromium과 WebKit에서 상세 복귀를 확인했다.
- 인도자 계정의 홈 → 상세 조회: 11건/37,901B → 11건/20,208B. 건물 응답은 32,115B → 10,290B. 비압축 응답 본문 기준이며 운영 전체 트래픽 수치가 아니다.
- **대기시간 개선이 입증된 것은 아니다.** 측정 스크립트의 단계 시간에는 안정화 대기가 포함되어 있고, 네트워크 편차도 있다.
- 나의 봉사는 여전히 전체 건물 자료와 단계별 일정 조회를 기다린다. 상세에서 전체 건물을 미리 받지 않으므로 그 비용이 나의 봉사 첫 진입에 남는다. 전체 화면이 빨라졌다고 결론 내리지 않는다.
- 캘린더 재방문에서는 기존 캐시로 일정 재조회 0건을 확인했다. 캐시를 없애거나 전체 조회를 강제하는 변경은 하지 않았다.
- Mac Chromium에서 실제 목록 스타일에 중국어 제목을 넣은 렌더 검사는 두 글자 모두 `PingFangSC-Semibold` 한 글꼴, 굵기 600이었다. 물리적 아이폰 검증을 대신하지 않는다.

## 검증

- 전체 자동 시험 2,539개 통과. lint 통과, 운영 설정 + 데모 DB 빌드 통과.
- 기존/새 편집기 X·뒤로가기 회귀 시험, 홈 통계 제거 시험, 중국어 제목 언어 표기 시험.
- 홈 상세의 건물 조회 범위, 옵션 OFF, 잘못된 링크, PC 범위, 전체 배정 편집 보호에 대한 기존/추가 시험.
- 상세 ID 삭제와 전체 건물 조회를 다시 넣는 변이 검증에서 관련 시험 5건이 실패함을 확인하고 수정 상태로 복원했다.
- 증거: `scratch/nov18-*-navigation.json`, 화면 캡처 `scratch/nov18-*.png`. 이 파일들은 데모 측정용이며 운영 자료가 아니다.

## 후속

- 아이폰 데모에서 X 복귀·중국어 제목 확인.
- 나의 봉사 첫 진입과 느린 기기에서의 화면 준비 시간을 별도 개선 대상으로 유지한다. 필요한 상태/메모 자료를 확인하지 않고 조회를 생략하지 않는다.
- 운영 중인 봉사에는 영향을 주지 않는다. 저녁 배포도 자동 예약하지 않으며 사용자 확인 후 진행한다.
