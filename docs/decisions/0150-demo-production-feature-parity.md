## 범위

직전 데모 `a1f4011`과 운영 소스 사이의 차이는 시험/문서뿐이었다.
이번에는 운영의 정확한 소스를 추출하고, 실제 운영 환경에서 읽은 기능 설정
46개를 그대로 사용해 데모를 빌드했다. 데모 프로젝트에 별도로 켜진 전시대
신청은 가져오지 않아 운영과 같이 OFF다. `VITE_DEMO_MODE=false`로 데모
자동 기본값이 운영 기능 설정을 덮지 않게 했다.

DB/anon 키, 푸시 공개 키, 지도 키, 앱 주소와 DEMO 식별 문구는 데모용을
유지한다. 오류 수집은 운영 수집처와 섞이지 않게 꺼 둔다. 자료/계정/DB 스키마를
복사하거나 변경하지 않았다. 원격 Vercel 환경변수도 바꾸지 않았으므로 다음
데모 빌드도 같은 방식으로 운영 기능 설정과 데모 연결 설정을 조합해야 한다.

## 검증

- 운영 활성 배포와 소스 확인, 배포 전후 운영 배포 ID 및 양쪽 원격 설정 동일.
- 정확한 소스로 TypeScript/Vite 빌드 성공. 기존 큰 청크/폐기 예정 옵션 경고 유지.
- 관련 기능/집단 후보/목록/지도 시험 6파일 30개, 배포 도구 시험 8개 통과.
- 데모 DB와 기존 데모 푸시 키 포함, 운영 DB 주소 미포함 확인.
- 단일 `deploy:demo` 경로로 prebuilt 결과물 1회 배포.
- 데모 별칭의 HTML/SW/manifest/JS/CSS 25개 해시가 검사한 결과물과 일치.
- 새 배포 주소에서 DEMO 로그인 화면 정상 표시. 로그인/신청/저장/푸시 송신은
  수행하지 않았으며 이번 확인을 인증 후 업무 화면 검증으로 표현하지 않는다.

기존 Chrome 프로필의 데모 별칭은 과거 SW의 시작 파일을 읽으며 로고에 머물렀다.
새 배포 주소는 정상으로 열렸다. 사용자 저장소/캐시를 강제로 지우거나 SW를
강제 교체하지 않았다. 설치 앱의 새 버전 적용은 사용자 확인 사항이다.

준비 중 Vercel이 민감 환경값을 빈 값으로 반환해 첫 검증이 중단됐다. 기존 로컬
환경의 프로젝트별 연결값으로 보충했다. 이후 빈 운영 푸시 값의 문자열 포함
검사도 중단되어 해당 검사를 값이 있을 때만 실행하게 정정했다. 두 중단 모두
배포 전이며, 완성된 결과물의 데모 연결/푸시 키를 별도로 확인한 뒤 배포했다.
