- 상태: 데모 검증, 운영 미적용
- 결정일: 2026-11-18
- 기준: `5342c84`

## 요청과 확인

일정 추가/수정의 자주 쓰는 시간 옆 톱니바퀴가 기존 앱과 다르게 보인다는 요청이다.
회중 봉사의 수정/삭제가 보이지 않는다는 후속 질문은 사용자가 인도자 계정으로
확인했기 때문이라고 확인했다. 권한 오류가 아니므로 권한은 변경하지 않는다.
회중 봉사의 편집/삭제와 집단 봉사의 일정 수정/일정 삭제 문구 차이만 통일한다.

## 변경

- 문자 톱니바퀴를 MobileMap 등의 기존 수정 아이콘과 같은 선형 연필로 교체한다.
  18px, currentColor, 1.8px 선이며 버튼 32px 크기는 유지한다.
  시간 설정 툴팁, 접근성 이름, 펼침 상태, 열기/닫기/저장 동작은 그대로다.
- 모바일/PC 회중 봉사 메뉴를 `일정 수정` / `일정 삭제`로 맞춘다.
  집단 봉사의 기존 문구와 중국어/영어 번역을 그대로 사용한다.
- 관리자/개발자의 일정 수정·삭제 권한과 인도자의 배정 권한을 바꾸지 않는다.
  조회, 저장, 삭제 확인, 반복 일정 범위 선택, 알림, DB 변경은 없다.

## 캡처에서 추가로 확인한 PC 대비 문제

첫 배포 후 DOM의 메뉴 존재/열기 검사는 통과했지만 PC 캡처에서는 일정 수정 글씨가
흰 배경과 같은 흰색이었다. `.detail-title-row button`이 `.event-dots-item`보다
구체적이어서 색과 패딩을 덮었다. 삭제는 danger 규칙이 더 구체적이라 보였다.
따라서 위 첫 검사의 통과를 두 문구가 실제로 잘 보였다는 근거로 해석하지 않는다.

메뉴 기본 선택자를 `.event-dots-dropdown .event-dots-item`으로 한정해 기존 글씨색과
8px 패딩이 적용되게 한다. 다른 헤더 버튼은 변경하지 않는다. CSS 계약 시험과 실제
브라우저의 글씨색/배경색 차이, 패딩/높이 검사를 추가했다. 옛 선택자로 되돌리면
CSS 시험이 실패한다. 수정본 전체 2,598개 시험과 lint 통과.

수정 전 실제 데모 PC를 새 대비 검사로 다시 확인하면 글씨와 배경 모두
`rgb(255, 255, 255)`여서 실패했다. 최초 재실행은 모바일의 대화 방법 조회가
페이지 이동 중 접근 제어 오류로 끝나 PC 검사 전에 중단됐고, PC만 재실행해 위
대비 실패를 확인했다. 이 일회성 네트워크 오류를 권한 정책 변경으로 처리하지 않았다.

보완 앱 커밋 `dabfcab`, 데모 배포 `dpl_C7Rme6hH6qT4i1Tfc61UzJ2BmTtm`에서
WebKit 390px/1365px 관리자 검사를 다시 통과했다. PC 수정 메뉴 글씨색/패딩/높이,
두 문구, 편집 닫기 복귀, 연필 아이콘과 시간 설정 열기/취소, pageerror 0건을 확인했다.
원본: `scratch/schedule-actions-after-contrast-ui.json`. 실제 저장/삭제는 실행하지 않았다.

## 후속 리뷰: 번역 누락 지적 확인

작업 시작 시 브랜치는 `codex/nov18-mobile-service-fixes`, HEAD는 `689df0f`였으며
추적 파일 변경이 없었다. 리뷰어가 알린 일시적인 detached HEAD 상태는 남아 있지 않았다.

번역 누락 지적은 현재 코드와 다르다. `messages.zh.ts`와 `messages.en.ts`는 각각
6행에서 groupService 사전을 import하고 11행에서 spread로 합친다. 두 메뉴 문구는
`groupService.ts`에 이미 있으며 중국어는 `修改安排` / `删除安排`, 영어는
`Edit event` / `Delete event`다. `msg()`는 이 합쳐진 실제 사전을 사용한다.
따라서 중복 번역 항목을 추가하거나 앱 코드를 바꾸지 않는다.

`EventScheduleActions.i18n.test.tsx`에 모바일/PC x 회중/집단 x 중국어/영어의
8가지 실제 메뉴 렌더 시험을 추가했다. msg나 사전은 mock하지 않는다. 집단 조회와
댓글/연락처 등 메뉴와 무관한 데이터 의존성만 대체하며 DB 권한 검증 시험은 아니다.
합쳐진 사전을 통해 두 번역이 표시되고 한국어 fallback이 없음을 확인한다.

- 기존 코드 그대로 새 시험 8개 통과.
- 두 언어에서 두 번역 항목을 임시 제거하면 8개 모두 수정 문구 검사에서 실패.
- 수정 번역은 두고 삭제 번역만 제거해도 8개 모두 삭제 문구 검사에서 실패.
- 변이 복구 후 사전/앱 코드 diff는 0개. 관련 6파일 53개 시험, TypeScript, lint 통과.
- 이번 후속 변경은 시험과 문서뿐이다. 운영/데모 DB 및 배포는 변경하지 않는다.
