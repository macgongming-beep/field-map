## 설치 본문 대조

21개 선행 함수와 추가 5개, 총 26개 본문/실행권한을 수집했다. 운영 rename/purge/merge는 데모의 보존된 private core에 대응시켰다. 19개 본문이 정확히 일치했고 다음 차이는 따로 확인했다.

- 참가자 정리와 배정 권한: 이번 준비 묶음이 의도적으로 변경할 부분이다. 정리 함수의 치환 위치 네 곳은 각각 정확히 한 번 존재한다.
- 단일/반복 일정 수정과 일정 알림: 후보의 권한 분리 및 알림 변경 대상이다. 데모 단일 일정 수정에는 별도의 전시대 칼럼 처리도 있으므로 운영과 본문이 같다고 가정하지 않는다.
- 댓글 알림: 운영에는 전시대 수신자 분기가 없다. 운영 원문에서 댓글 링크 삽입 위치가 정확히 한 번이고 기존 `&comment=`는 없다. 운영 본문을 보존한 채 링크만 추가하는 예상 결과를 로컬에 저장했다.
- `verify_session`: 운영은 사용 시 만료를 30일 연장하지만 데모 본문은 last_used_at만 갱신한다. 준비 묶음은 이 함수를 재정의하지 않는다. 운영의 세션 연장 동작을 유지하며 데모 인증 본문을 복사하지 않는다. 이번에 함수 실행으로 만료를 갱신하지 않았다.

기존 카드/건물/세대/비공식 자료 FK의 CASCADE와 세션 FK의 SET NULL을 확인했다. 이는 이번 유지보수 예외 설계와 일치한다. 이름 변경/사용자 정리/건물 병합 본문은 검증된 데모 private core와 정확히 일치한다.

기존 댓글 인덱스 3개, 카드 배정 인덱스 2개, 봉사 세션 인덱스 2개를 기록했다. 신규 `comments_event_page`는 아직 없고 준비 묶음의 생성 대상이다. 실제 운영에서 EXPLAIN ANALYZE나 부하 시험을 실행한 것은 아니다.

## 운영 원문을 사용한 로컬 시험

운영에서 읽은 댓글 알림, 참가자 정리, 단일 일정 수정의 실제 정의 세 개를 합성 PGlite fixture에 넣었다. 그 로컬 DB에 후보의 19개 준비 묶음을 한 트랜잭션으로 적용했다. 운영/데모 DB에는 적용하지 않았다.

- 설치 후 첫 배포 준비 검사 8개 모두 true.
- 댓글 본문은 원래 운영 본문에 의도한 링크 처리만 추가된 것과 정확히 일치.
- 참가자 정리 본문은 검증된 데모의 보완된 본문과 정확히 일치.
- 단일 일정 수정은 운영 본문의 권한 확인 함수만 교체한 결과와 정확히 일치. 전시대 처리는 가져오지 않음.
- 설치 묶음: `0a1d33285c61c14f6f2605735e6aee0b33b2971e31f3b66dcf00eef07b180b54`, 기존 후보와 동일.

첫 로컬 시험은 단일 일정 수정 결과를 데모 본문과 완전히 같다고 기대해 실패했다. 차이는 데모에만 있는 전시대 처리였다. 올바른 계약인 "운영 본문 보존 + 권한 확인만 교체"로 기대값을 수정한 뒤 통과했다. 제품 코드/SQL을 바꾸거나 실패를 운영에서 재현하지 않았다.

이 시험은 운영 전체 스키마/자료 복제나 실제 수신자 알림 시험이 아니다. 기존 전체 후보 시험과 화면 검사는 0111의 결과이며 이번에 다시 실행한 것으로 주장하지 않는다.
