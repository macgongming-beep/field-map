# 장소 즐겨찾기 복구와 작은 모임 표시

- 결정일: 2026-11-19
- 상태: 데모 적용 완료, 운영 배포 한도로 보류

새 ServiceEventEditor는 시간 즐겨찾기만 연결하고 기존 장소 즐겨찾기를 누락했다.
운영 app_settings를 읽기 전용으로 확인하여 calendar_place_presets에 3개가 남아 있음을 확인했다.
등록된 자료를 생성/변환/삭제하지 않고 기존 키와 resolvePlacePresets를 재사용한다.
서버 목록 우선, 없을 때 기존 로컬 목록, 명시적인 빈 목록은 빈 상태로 유지한다.

생성/수정 화면에서 자주 쓰는 장소 선택은 장소명과 지도 링크만 채운다. 모임 방식을 임의로 바꾸지 않는다.
연필 버튼에서 최대 10개를 추가/이름·링크 수정/삭제하며, 장소 설정 저장은 일정 저장과 분리한다.
취소하면 폐기하고 서버 저장 실패는 기존 목록/로컬 캐시를 유지하며 초안과 오류를 보여 준다.
기존 공유 설정 저장 콜백만 사용하고 추가 읽기/RPC/권한 변경은 없다.

목록의 모임 방식은 인도자 이름 뒤에서 제목 옆 작은 现场/线上 표시로 이동한다.
없음이면 표시하지 않고, 옛 hasMeeting 자료는 현장으로 해석한다. 명시적인 meetingMode가 우선한다.
합쳐진 집단 일정은 모두 같은 방식일 때만 공통 표시한다. 서로 다르면 상세에서 선택한 집단의 방식을 표시한다.
기존 화상 일정의 장소 숨김은 유지한다. 모임 정보 펼침과 접속 정보 권한은 변경하지 않는다.

검증: 서버/로컬 우선순위, 선택 시 지도 링크, 추가·수정·삭제·취소·실패, 일정과 분리 저장,
모임 없음/현장/화상/옛 자료/집단 혼합을 시험한다.
로컬 격리 화면에서 390px/1440px 제목 표시와 장소 선택을 확인했다.
모바일 편집기 clientWidth/scrollWidth는 모두 390px로 가로 넘침이 없다.
확인 화면의 세 장소는 예시이며 운영 자료를 복제하거나 저장하지 않았다.
