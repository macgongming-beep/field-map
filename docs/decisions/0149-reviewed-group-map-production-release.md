기존 운영은 `30d068f` 및 `dpl_D3oxZLwjVmHp3JQ1jbP8QgdgW4hP`였다.
배포 직전 이 배포가 여전히 활성인지 확인했다. 이번 소스는 기존 운영의
후손이며, 그 사이 앱 변경은 검토한 0146~0148 범위뿐이다.

`main`은 `5a62d23`으로 앞서 있고 main 작업 폴더에는 다른 작업의 미커밋

검토 브랜치의 정확한 커밋**을 archive하여 배포했다. main 포인터와 그 작업
폴더는 변경하지 않았다. 다음 main 기반 배포 전에는 이 운영 반영분도 통합하고
다시 검증해야 한다. main HEAD가 현재 배포 소스와 같다고 가정하면 안 된다.

## 배포와 확인

1. 정확한 커밋을 격리된 업로드 폴더로 추출하고 운영 프로젝트 연결을 확인했다.
2. 운영 환경변수를 읽기 전용으로 확인했다. 집단 구역/집단 봉사/배정 수정번호
   설정 모두 정확히 `true`이며 기존 환경변수는 바꾸지 않았다.
3. 전체 292개 파일 2,911개 시험과 lint 통과. 기존 시험의 act 경고는 남는다.
4. `vercel deploy --prod --skip-domain`으로 **1개** 배포를 만들었다.
   운영의 기존 환경변수로 TypeScript/Vite 클라우드 빌드가 통과했다.
   기존 큰 청크 경고는 남는다. 이 동안 운영 주소는 이전 버전을 유지했다.
5. 새 배포의 JS 17개를 조회하여 운영 DB 주소, 데모 DB 주소 미포함,
   집단 구역 활성값, 새 필터/목록/아이콘 코드 포함을 확인했다.
6. 검사한 배포를 `vercel promote`로 운영 주소에 연결했다. 재빌드하지 않았다.
7. 운영 주소의 JS 17개 해시가 검사한 배포와 전부 동일함을 확인했다.
   환경변수 목록/값, Git 자동 배포 OFF가 전후 동일하고 활성 배포 ID도 확인했다.
8. WebKit 390px, Chromium 1440px에서 홈/캘린더/지도/배정 주소가 로그인
   화면으로 정상 연결됨을 확인했다. 가로 넘침, 페이지 오류, 정적 파일 실패 없음.
   운영 로그인/업무 쓰기는 하지 않았고, 브라우저는 DB 쓰기를 차단했다.

배정 화면 자체의 운영 로그인 상태 확인과 실물 아이폰 업데이트 확인은 사용자
확인 대상이다. 앞선 데모 검증을 운영 실기기 검증이라고 표현하지 않는다.
