# 댓글 리뷰 후속: 무효 세션과 빈 목록 구분, 재연결 재조회 보장

- 상태: 데모 DB 적용, 새 화면 배포 검증 중. 운영 미적용
- 결정일: 2026-11-17
- 이전 결정: [0101 집단별 댓글](0101-demo-group-event-comments.md)

## 확인된 문제와 변경

1. RLS가 무효 세션에 0행을 반환하면 클라이언트가 댓글 없음/삭제로 해석했다.
   `read_group_event_comments` RPC가 승인된 활성·미만료 세션을 먼저 검사한다.
   실패는 SQLSTATE `42501`, 고정 메시지 `COMMENT_SESSION_REQUIRED`다. 실제 anon HTTP 응답은 401이다.
   화면은 빈 목록으로 바꾸지 않고 재로그인 안내를 표시하며 자동 구독/재시도 및 새 댓글 등록을 멈춘다.
   일반 권한 오류·배포 누락·통신 실패는 로그인 만료로 취급하지 않고, 전역 강제 로그아웃도 하지 않는다.
2. 이전 글을 읽는 동안 발생한 재연결의 `sync`가 버려졌다.
   진행 중이면 재조회 예약을 한 번 남기고, 읽기가 끝나면 최신 정보를 다시 확인한다.
   화면 이탈·계정 변경·세션 거부 시 예약과 늦은 응답도 폐기한다.
3. 같은 일정의 인원 갱신 중에는 기존 컨텍스트를 유지해 열린 댓글이 없어졌다가 접히지 않게 한다.
   다른 일정/계정의 컨텍스트는 재사용하지 않고, 조회 실패 시 기존 명단 권한을 계속 유지하지 않는다.
4. 같은 알림을 다시 누르면 별도 진입 키로 다시 해당 집단/댓글을 연다.
   알림 진입만으로 집단 컨텍스트를 불필요하게 다시 읽지 않는다. 삭제/미존재 댓글에는 안내를 표시한다.
5. 댓글 초안은 계정이 바뀌면 지운다. 원래 계정으로 돌아와도 이전 초안을 복구하지 않는다.

## 서버 읽기 계약

- 새 RPC는 approved session 검사를 하는 읽기 전용 definer다. PUBLIC execute를 회수하고 anon/authenticated에만 허용한다.
- 새 집단 일정만 대상으로 하고, `event_id`, `target_type='calendar_event'`, 삭제 여부를 서버에서 제한한다.
- 페이지는 최대 20개, ID 묶음도 최대 20개다. 잘못된 ID/동시 커서 입력은 거부한다.
- 반환 칼럼을 고정하며 다른 집단의 신청자·배정 표는 조회하지 않는다.
- 기존 직접 SELECT RLS도 유지한다. 새 RPC 배포 누락 시 직접 SELECT로 우회하지 않는다.

## 알림 함수 보존 확인

- 데모 최초 백업 `backups/group-tabs-demo-1794881397831/rollback.sql`의 함수 본문과 현재 `pg_get_functiondef`를 비교했다.
- 예상한 댓글 링크 삽입만 차이가 있고, 전시대 대상 UNION을 포함한 나머지 본문은 완전히 동일했다.
- `scripts/groupTabsDemo.mjs audit-comments --confirm-demo`는 데모 환경 확인 후 이 비교와 새 읽기 함수의 권한을 검증한다. 결과는 `scratch/group-comment-notification-audit.json`에 저장한다.
- 별도 rollback 트랜잭션에서 **전시대만 신청한 합성 사용자**에게 실제 설치 함수가 댓글 알림을 생성하는 것도 확인했다.
- 1400 마이그레이션의 치환 조건을 공백에 관계없이 정확히 한 곳일 때만 허용하도록 보강했다. 이미 적용된 1400 전체를 재실행하지 않았다.
- 신규 회중 설치용 전시대 스키마/알림 마이그레이션 누락 정리는 이번 범위 밖이다. 현재 데모의 정상 동작과 신규 설치 재현성을 혼동하지 않는다.

## 검증 및 비용

- 실제 세션 helper를 사용한 PGlite 시험: 누락·오형식·미등록·만료·회수·비활성·미승인 세션이 빈 배열 대신 오류를 반환한다.
- 세션 검사를 의도적으로 제거한 mutation은 실패했다. 두 곳 이상 알림 치환, 서버 오류 분류, 배정과 무관한 새 조회 범위도 시험한다.
- 클라이언트 시험: 이전 글 읽는 중 재연결 예약, 만료 시 기존 댓글을 삭제로 처리하지 않음, 동일 알림 재진입, 인원 갱신 중 댓글 유지, 계정별 초안 초기화.
- 전체 2,580개 시험 및 lint/build 통과. 실제 데모 DB의 새 RPC 권한 감사와 기존 배정 definer 목록 감사도 통과했다.
- 로컬 화면 + 데모 DB 브라우저 시험 33항목 통과. 만료 세션을 넣은 HTTP 요청과 재로그인 안내, 전시대 알림, 실제 소켓 재연결을 포함한다.
- 최초 20개와 복귀 시 20개 조회는 약 5.6KB/1회였다. 40개를 읽은 뒤 복귀/재연결은 약 11.2KB/2회였다. RPC JSON 형식 변경으로 0101의 약 5.3KB와 다르다.
- 복귀 시험은 Chromium에서 visibilitychange를 제어한 것으로 실제 휴대폰의 장시간 앱 중단 시험은 아니다. 소켓 재연결은 실제 Supabase WebSocket을 끊고 복구한다.
- 복귀/재연결의 **나머지 HTTP 응답과 WebSocket 송수신량도 별도로 기록**한다. 소켓 재연결에는 기존 캘린더 복구 조회가 있을 수 있으므로 댓글 2회만을 앱 전체 비용이라고 하지 않는다.
- 합성 데이터의 압축 전 응답 본문/소켓 payload 크기이며, 청구 전송량·월간 사용량·운영 규모 성능을 의미하지 않는다.

## 배포와 남은 절차

- 데모 백업: `backups/group-tabs-demo-1794883701057/`. 1500을 단일 트랜잭션으로 추가했다.
- 새 앱보다 RPC를 먼저 추가한다. 기존 데모 화면은 이 추가만으로 중단되지 않는다.
- 롤백은 먼저 클라이언트를 이전 버전으로 돌린다. 추가 RPC는 남겨도 되며, 더 이상 사용하는 앱이 없을 때만 제공된 drop 스크립트를 실행한다. 기존 privacy 정책/신호 표는 유지한다.
- 운영 DB/배포/플래그는 변경하지 않았다. 운영 적용 전 함수 본문 대조, 구버전 영향, 운영 규모 EXPLAIN ANALYZE, 실제 기기 복귀/푸시 수신은 별도 검증한다.
