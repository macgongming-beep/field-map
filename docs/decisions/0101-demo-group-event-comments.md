# 집단별 댓글: 승인 사용자 공개, 정확한 알림, 필요할 때만 조회

- 상태: 데모 검증 중. 운영 미적용
- 결정일: 2026-11-17
- 관련 결정: 0079 채팅 종료, 0085 알림 목록, 0096 집단별 탭

## 결정

- 새 집단 탭 일정의 댓글은 정확한 `event_id`에 속한다. 다른 시간대/집단과 합치지 않는다.
- 승인된 활성 로그인 사용자는 다른 집단 댓글도 읽고 쓸 수 있다. 신청자 명단과 배정 조회 권한은 넓히지 않는다.
- 댓글은 기본 접힘이다. 펼쳤을 때만 조회/구독하며, 접기·탭 이동·화면 이탈·백그라운드에서는 구독을 해제한다.
- 최신 20개부터 표시하고 이전 글은 명시적으로 20개씩 읽는다. 댓글 수정/삭제 권한은 기존 작성자/관리자 정책을 유지한다.
- 작성 중인 새 댓글은 상세 화면 안에서 집단별로 보관해 접기/탭 이동 후 복원한다. 화면을 완전히 닫으면 저장하지 않는다.
- 읽기 권한과 알림 대상은 별개다. 다른 집단 댓글을 볼 수 있다고 전원에게 알리지 않는다.

## 알림

현재 설치된 `notify_on_comment`의 대상/설정/푸시 로직을 보존하고 링크만 확장한다.

- 해당 일정 신청자(기존 전시대 신청자 포함), 일정에 등록된 인도자, 명시적으로 언급한 사람의 합집합.
- 작성자는 제외하고, 겹친 대상은 언급 알림 한 번으로 처리한다. 단순히 인도자 역할이라는 이유로 전원 발송하지 않는다.
- 일반 댓글 푸시는 유지한다. 0085대로 일반 댓글은 알림함 목록에서 제외하고 언급 알림은 표시한다.
- 링크는 `/calendar?openEvent=<집단 일정 ID>&comment=<댓글 ID>`다. 모바일/PC 모두 소속 집단보다 링크 대상을 우선하여 탭과 댓글을 연다.
- 다른 탭을 직접 고른 뒤 인원 정보가 갱신되어도 이전 알림 탭으로 강제 복귀시키지 않는다.
- 수정/삭제로 새 댓글 알림을 재발송하지 않는다. 기존 사용자 알림 수신 설정은 그대로 적용된다.

## 조회와 보안

- `comments` SELECT에 restrictive 정책을 추가한다. 새 집단 일정과 부모가 없는 일정 댓글은 승인된 앱 세션이 필요하다. 기존 공지/회중 일정 댓글의 읽기 정책은 이번 범위에서 바꾸지 않는다.
- Realtime에는 앱의 사용자 세션 헤더를 전달할 수 없어 본문을 보내지 않는다. 공개 `group_comment_signals`에는 `event_id`, `comment_id`, `revision`만 둔다. 변경 시점과 식별자 노출은 허용하지만 이름·본문은 포함하지 않는다.
- 본문은 세션 헤더가 있는 HTTP 요청으로만 받는다. 읽는 중 계정이 바뀌거나 화면이 닫히면 늦은 응답을 적용하지 않는다.
- 변경 신호는 180ms 동안 묶고 바뀐 댓글 ID만 최대 20개씩 읽는다. 댓글 변경으로 캘린더·참가자·배정을 다시 받지 않는다.
- 본인 저장은 반환된 행을 반영한다. 서버 신호 도착 순서에 따라 해당 ID 1개를 추가 확인할 수 있으나 전체 이력은 다시 받지 않는다.
- 재연결/앱 복귀는 최신 20개와 이미 화면에 불러온 행만 확인한다. 오래된 알림 대상은 그 ID만 추가 조회한다. 복귀 중 놓친 글이 20개를 넘더라도 이전 글 버튼으로 읽을 수 있게 커서를 최신 페이지부터 다시 잡는다.
- 정기 polling과 전 집단 댓글 수 조회는 없다. 선택하지 않은 집단의 본문도 미리 받지 않는다.
- 대상/ID 순서의 부분 인덱스 `comments_event_page`를 사용한다. 비용은 열린 댓글 수·실제 변경 수·사용자가 읽은 페이지 수에 비례하며 0이라고 주장하지 않는다.

## 검증

- PGlite에서 실제 마이그레이션 실행: 익명/미승인/비활성 차단, 다른 집단 승인 사용자 허용, 정확한 알림 합집합, 수정/삭제 신호, 신호 쓰기 금지.
- 익명 차단 조건을 일부러 제거하면 테스트가 실패하는 것을 확인했다.
- 클라이언트 테스트: 닫힌 상태 0조회, 페이지/ID 범위, 계정 변경 응답 폐기, 0행 저장 실패, 백그라운드 해제, 늦은 응답의 최신 수정 덮어쓰기 방지, 초안 복원, 재연결 후 누락 페이지 접근.
- `scripts/checkGroupCommentsDemo.mjs`: 데모 전용 합성 사용자/일정/댓글로 모바일·PC, 알림 클릭, 실제 API 및 Realtime, 조회량/본문 바이트, 좁은 화면을 검증한다. 시험 후 만든 자료만 정리한다.
- 푸시는 트랜잭션 내 발송 큐 생성 후 rollback하여 일반 댓글/언급 두 경로를 확인한다. 실제 휴대폰 수신 시험을 했다는 뜻은 아니다.
- 기존 배정 함수 목록/권한 감사도 데모 DB에서 통과했다. 운영 규모 성능 시험을 대신하지 않는다.

## 실측과 배포

로컬 새 화면 + 실제 데모 DB에서 최신 45개가 있는 합성 일정으로 측정:

| 동작 | 댓글 HTTP 조회 | 읽은 행 | JSON 본문 크기 |
| --- | --- | --- | --- |
| 접힌 상태 | 0회 | 0 | 0 |
| 처음 펼치기 | 1회 | 20 | 약 5.3 KB |
| 이전 글 보기 | 1회 | 20 | 약 5.3 KB |
| 새 댓글 수신 | 1회 | 1 | 약 0.31 KB |
| 댓글 수정 수신 | 1회 | 1 | 약 0.31 KB |
| 댓글 삭제 수신 | 1회 | 0 | 2 B |
| 접은 뒤 새 댓글/다른 탭의 댓글 | 0회 | 0 | 0 |

이는 합성 본문의 압축 전 JSON 크기다. 청구 전송량이나 월간 절감액으로 환산하지 않는다. 초기 앱 로딩/알림함/신호/푸시 비용은 별도다.

- 데모 백업: `backups/group-tabs-demo-1794881397831/`. public/private 덤프 및 원래 알림 함수 저장.
- 최초 적용은 알림 함수의 공백 형식 차이를 안전장치가 거부하여 전체 rollback했다. 공백에 독립적인 제한적 치환으로 고친 뒤 단일 트랜잭션 적용했다.
- 롤백 시 원래 알림 함수만 복구한다. 이미 작성된 집단 댓글을 익명에게 열지 않도록 추가한 privacy 정책/신호 표는 유지한다.
- 운영 DB·운영 배포·운영 기능 플래그는 변경하지 않는다. 운영 전환은 별도 리뷰와 승인이 필요하다.
