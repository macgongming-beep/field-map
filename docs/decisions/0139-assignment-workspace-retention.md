# 배정 중 선택 조건과 지도 위치 유지

- 상태: 운영 적용 완료 (2026-11-19). 아래 데모 단계의 미적용 표시는 당시 기록이다.
- 결정일: 2026-11-19
- 관련 기능: 팀 구역 배정, 지도 표시

## 배경과 결정

팀을 바꿀 때마다 주택/상가를 다시 선택하고 지도가 전체 범위로 돌아가는 불편을 줄인다.
배정 편집기 한 번을 사용하는 동안에만 화면 상태를 기억한다. 계정/일정을 넘나드는
영구 저장은 하지 않는다.

- 아직 범위를 정하지 않은 빈 팀은 마지막 선택한 봉사 형태를 기본 표시한다.
  카드를 실제 배정할 때 범위를 함께 반영하며, 한 번의 실행 취소로 둘 다 되돌린다.
- 기존 범위가 있는 팀은 그 범위를 유지한다. 범위가 없는 옛 배정도 전체로 유지한다.
  팀을 보기만 했다고 배정값을 쓰거나 기존 카드를 지우지 않는다.
- 팀 구성 화면에 다녀와도 지역, 검색, 미배정 필터, 지도/목록, 봉사 형태, 중국어 필터를 유지한다.
- 지도는 처음만 범위를 맞추고 이후 팀/필터 변경에는 위치와 줌을 유지한다.
  지도/목록 전환 및 팀 구성 왕복으로 지도가 새로 생겨도 같은 위치와 줌으로 연다.
- 동작하지 않던 건물 추가 버튼 대신 기존 지도와 같은 중국어 사용 세대 표시 토글을 둔다.
  원본 세대, 카드 경계선, 배정 대상/저장 내용은 바꾸지 않고 핀 표시만 거른다.

## 보호 범위

`AssignmentEditorContent`가 작업 화면 기억을 소유한다. 새 편집기를 열면 초기화한다.
`MapCanvas`의 새 기억 옵션은 배정 화면만 사용한다. 일반 지도는 이전처럼 선택 구역에 맞춘다.
기존 권한 검사, 저장 RPC, 충돌 리비전, 공유, 팀원 처리, DB 정책은 변경하지 않는다.
이미 배정된 카드가 없는 신규 팀에만 상속 범위를 반영한다.
화면 종료 뒤 늦게 오는 지도 idle 신호는 새 화면의 위치 기억을 덮지 못한다.

## 검증

- 전체 Vitest: 278파일, 2,710개 통과. 전체 lint와 TypeScript/데모 빌드 통과.
- 새 지도 시험은 실제 MapCanvas에 최소 SDK 대역을 제공해 위치 유지와 일반 지도 자동 맞춤을 검증한다.
- 배정 시험은 범위 상속, 기존 범위 보존, 실행 취소, 읽기 전용, 중국어 표시의 원본 비변경,
  팀 구성 왕복 기억을 검증한다.
- 분리한 임시 복사본에서 자동 맞춤 방지, 카메라 복원, 중국어 필터, 화면 기억,
  새 팀 기본 범위를 각각 제거하면 해당 새 시험이 실패했다.
- 실제 Naver SDK + 합성 자료 화면: Chromium 1440x900, WebKit 390x900 통과.
  줌 17/중심 37.244,127.181에서 팀/필터/지도-목록/팀 구성 왕복 후 같은 카메라를 확인했다.
  가로 넘침과 페이지 오류가 없고, 필터 활성 표시와 실제 지도 타일을 스크린샷으로 확인했다.
- 로컬 지도 키 허용 주소 제한을 피하려고 브라우저 안에서 데모 주소 요청을 로컬 정적
  검증 파일로 응답했다. 배포된 데모나 운영 파일을 이 검사로 수정한 것은 아니다.
  첫 개발 서버 기반 검사는 HMR 오류로 중단하고 정적 검증 서버에서 다시 통과했다.

검증 기록: `scratch/assignment-workspace-browser.json`,
`scratch/assignment-workspace-mutations.json`, `scratch/assignment-workspace-{chromium-1440,webkit-390}.png`.
검증용 파일은 앱 배포 산출물에 넣지 않는다.

## 사용량과 한계

추가 DB 요청/구독/저장 API는 없다. 기존에 읽은 자료와 편집기 메모리만 사용한다.
합성 화면 검사의 DB 요청은 0건이다. 이는 전체 앱의 전후 사용량 실측을 대신하지 않는다.
지도 이동/확대/재생성에 따른 지도 제공자 타일 요청은 여전히 발생한다.
실제 아이폰/안드로이드 기기 조작은 사용자 확인이 남아 있다.

## GPS 후속 보완 (2026-11-19)

사용자가 GPS 버튼으로 현재 위치를 확인할 때도 기존 확대 비율을 유지하도록 요청했다.
공통 MapCanvas의 GPS 성공 경로에 있던 `morph(latLng, 16)`을 `panTo(latLng)`으로 바꿨다.
위치만 이동하며 GPS 응답을 기다리는 동안 사용자가 바꾼 줌도 되돌리지 않는다.
화면 종료 후 늦게 도착한 GPS 응답은 무시한다. 위치 표시와 기존 권한 거절 안내는 유지한다.
GPS 클릭당 위치 요청 한 번이라는 동작과 DB 요청 수는 바뀌지 않는다.

- 전체 278파일/2,712개 시험, 전체 lint, TypeScript/데모 빌드 통과.
- 기억 옵션 유무 각각에서 줌 19 유지, 위치 대기 중 줌 13으로 변경 후 유지,
  현재 좌표 반영, 반복 클릭, 종료 후 늦은 응답 무시를 검증했다.
- 고정 줌 16으로 되돌리는 변이에서 새 시험 2개가 실패했다.
- 실제 Naver SDK를 쓰는 Chromium 1440px/WebKit 390px 화면에서도 줌 19 유지와
  응답 대기 중 바꾼 줌 18 유지를 확인했다. 위치 응답은 합성 좌표로 제공했다.
  실제 기기의 GPS 정확도나 권한 팝업을 검증한 것은 아니다.
- 첫 브라우저 검사는 이동 애니메이션 중간 좌표를 비교해 실패했다. 최종 좌표 도착을
  기다리도록 검사만 수정한 후 통과했다. 기록: `scratch/assignment-gps-browser.json`.
- 운영은 미적용. 같은 단일 데모 배포 경로로 보완한다.

GPS 보완 코드 `28e66b8`의 데모 배포 `dpl_GrK4HejnUm7Mn72akk6vQmyVc9Ed`가 READY로 완료됐다.
데모 정식 별칭에 연결했으며 운영 배포는 변경하지 않았다.

## 리뷰 후 보완 (2026-11-19)

마지막 선택은 사용자가 봉사 형태 버튼을 누른 경우에만 바뀐다. 기존 팀을 눌러 보거나
그 팀에서 팀 구성 화면을 왕복하는 것만으로 기본값을 바꾸지 않는다.
범위가 있는 팀은 그 저장값을 계속 표시하고, 새 미설정 팀만 마지막 명시적 선택을 따른다.

리뷰의 서버 복원 변경 제안은 이번에 적용하지 않았다. `buildDraftFromServer` 앞의
`toCalendarEvent` (`storeTransforms.ts`)에서도 없는 범위를 이미 '전체'로 채우고 있고,
저장 경로도 빈 범위를 '전체'로 저장한다. 따라서 현재 자료만 보고 이것을 사용자가 고른
'전체'와 구분할 수 없다. **이미 '전체'로 저장된 빈 팀을 미설정으로 재해석하지 않는다.**
저장 규칙/공유 payload/DB를 바꾸지 않고 이번 세션의 선택 기억만 보완한다.

첫 배정 지도 맞춤은 선택 범위의 경계선과 건물 좌표를 함께 포함한다. 경계선이 없는
카드의 건물이 빠지지 않게 하되, 첫 맞춤 이후 지역/팀/필터 조작 시 위치 유지 규칙은 그대로다.
일반 지도 자동 맞춤은 변경하지 않는다. GPS 줌 유지도 공통 MapCanvas에서 계속 적용한다.

검증:
- 전체 279파일/2,717개, 전체 lint 및 데모 빌드 통과.
- 실제 AssignmentEditor에서 A의 지역/검색 기억과 B의 초기화를 검증한다.
  기억을 모듈 싱글톤으로 바꾸면 새 시험이 실패한다.
- 중국어 필터를 켠 상태의 실제 후보 경계 선택과 `draftToAssignments` 결과를 비교한다.
  `chineseOnly`일 때 카드 ID 집합을 비우는 변이는 3개 시험에서 실패한다.
- 범위 없는 옛 카드 배정의 '전체' 표시를 제거하면 새 시험이 실패한다.
- 팀 선택 또는 화면 재진입에서 기본값을 덮어쓰는 변이는 각각 새 시험이 실패한다.
- 첫 맞춤에서 경계선 없는 건물을 제외하면 새 시험이 실패한다.

`5abed518b08eec0d1665079bcced5c868e118bbe`를 운영 후보로 사용했다.

  다른 로컬 main 작업 폴더의 미완성 변경은 건드리거나 포함하지 않았다.

  `supabase` 및 잠금 파일 변경은 없다. 0138의 배포 정책/도구 변경도 함께 main에 보존했다.
