# 집단별 신청과 배정을 분리하고 시간대별 탭으로 표시한다

- 상태: 데모 적용, 운영 미적용
- 결정일: 2026-11-16
- 관련: 0093, 0094, 0095

## 사용자 결정

연합 봉사 대신 각 집단이 신청자를 보고 자체 마련을 한다. 캘린더는 같은 시간대의
집단 봉사를 한 줄로 보여 주고, 상세는 동탄·신갈·처인·동백 탭으로 전환한다.
집단 감독자는 담당 집단 신청자만 조회·배정한다. 관리자는 모든 집단을 관리한다.
알려 준 담당 관계는 동탄 민경체, 신갈 도완오, 처인 석대성, 동백 엄민석이다.

## 저장과 권한

- 새 집단 일정은 `group_service_scope=true`, 집단 코드 하나를 가진 별도 event_id로 저장한다.
  기존 팀 저장은 event_id의 배정을 교체하므로 네 집단이 한 행을 공유하지 않는다.
- 같은 날짜·시작·종료 시간의 독립 집단 일정만 화면에서 묶는다. 같은 집단·날짜·시작 시간은
  부분 유일 인덱스로 중복을 막는다. 시간이 달라진 집단은 별도 시간대로 표시된다.
- 시간대는 하나 이상 자유롭게 추가한다. 반복 series는 집단과 시간대마다 따로 둔다.
  생성 폼은 네 집단을 기본 선택하고, 선택한 집단만 독립 생성한다. 인도자는 비워 둘 수 있다.
- 감독자 매핑은 `private.service_group_supervisors(group_code,user_id)`다. 이름·프로필 집단으로
  관리 권한을 추측하지 않는다. 활성·승인·leader 역할과 명시적 매핑이 모두 필요하다.
- 기존 `private.user_can_manage_event`를 경유하는 팀/구역배정 RPC와 참가자 쓰기에 적용한다.
  scoped 일정에서는 다른 집단 leader_name에 이름이 있어도 권한이 생기지 않는다.
  일정 종류/대상 집단/scoped 표시를 바꿔 기존 권한으로 우회할 수 없도록 소유 범위를 고정한다.
- 참가자, 카드 배정 2종, 비공식·식당 배정, 파생 봉사 세션 SELECT에 제한 정책을 더한다.
  감독자는 관리 집단, 일반 성원은 프로필 집단, 관리자는 전체를 본다.
  다른 집단에 신청한 본인의 행은 조회·취소할 수 있다. 소속 없는 사람도 신청할 수 있다.
- `get_group_service_context`는 승인된 로그인 사용자에게 인원수·집단·권한만 반환한다.
  다른 집단 이름을 내려받아 화면에서만 숨기지 않는다. 새 폴링이나 전체 이력 조회는 없다.
- Realtime에는 REST의 세션 헤더가 없으므로 제한된 명단을 직접 구독해서는 갱신되지 않는다.
  `group_participant_signals`에 event_id/revision만 공개하고 기존 캘린더 채널로 구독한다.
  변경된 일정의 명단만 세션 권한으로 재조회하고 열린 탭의 인원수도 갱신한다.
  이름·연락처·화상 정보는 신호에 없으며 클라이언트의 신호 쓰기는 금지한다.
- 재방·연구는 집단별 인원에 포함하되 기존대로 팀 배정 후보에서 제외한다.
  다른 집단/시간 중복 신청 확인과 타임별 취소 계약을 유지한다.

## 화면

모바일·PC가 같은 탭 상세를 사용한다. 담당/소속 집단을 기본으로 열고, 없는 경우 첫 집단을 연다.
다른 집단은 일정과 인원수·신청 버튼만 보이고 명단·배정 도구는 열리지 않는다.
모임 정보와 공유된 배정 결과는 접어서 둔다. 배정은 기존 AssignmentEditor로 들어가며
선택한 집단의 event_id만 넘긴다. 관리자 삭제는 기존 단일/반복 삭제 확인을 사용한다.
기존 회중 봉사와 연합 일정은 그대로다. 기존 자료를 자동 변환하거나 삭제하지 않는다.

## 데모와 복구

데모 DB에는 위 네 실명과 정확히 일치하는 계정이 없어 실제 계정을 추정 연결하지 않았다.
4개 테스트 감독자와 성원/무소속 테스트 계정으로 검증한다. 실제 계정 매핑은 계정 확인 후 별도 적용한다.
11월 18일 14:30/17:00에 집단별 8개 시험 행을 만들었다. 캘린더에는 두 줄로 표시한다.
기존 11월 25/28일 시험 및 사용자가 작성한 일정은 변경하지 않았다.

마이그레이션 1200/1210/1220은 정확한 데모 프로젝트 ID를 검사하는 `scripts/groupTabsDemo.mjs`로
public/private 백업 후 `psql --single-transaction` 적용한다. 적용 직전 함수 정의를 포함한
rollback.sql을 각 `backups/group-tabs-demo-*`에 저장한다. 복구 시 이전 앱으로 전환하고
1220 복구, 1210 복구, 1200 복구 순서로 실행한다. 복구는 새 권한 경계를 없애므로 운영에 임의 적용하지 않는다.
운영 DB, 운영 배포, main은 변경하지 않는다. 토큰 포함 fixture는 scratch 로컬 전용이다.

## 검증

- PGlite: 감독자/관리자/무소속/비활성, 소유 집단 변경 거부, 중복 슬롯 거부,
  명단과 배정·파생 세션 읽기 제한, 비로그인 RPC 거부, 기존 일정 호환.
- 권한 검사/명단 정책을 제거한 변형에서 해당 시험 실패 확인.
- React: 네 집단 독립 생성, 집단·시간별 반복 series, 캘린더 한 줄 표시, 정확한 신청 대상,
  다른 탭 명단·배정 버튼 숨김, 조회 실패 시 닫힌 상태와 재시도.
- 데모 실제 API: 네 감독자 각각 담당 집단만 조회, 변조한 타 집단 배정/참가자 삽입 거부,
  담당 집단 팀 공유 성공, 무소속 신청·취소, 배정 결과 읽기 범위.
- Playwright: 모바일 430px, 320px/125%, PC 1440px, 탭 전환과 기존 배정 화면 연결.
- 별도 성원 세션에서 신청/취소했을 때 감독자 화면이 새로고침 없이 갱신됨을 검증한다.
  신호 생성 제거 변형에서도 SQL 시험이 실패하는지 확인한다.

## 남은 범위

실제 감독자 계정 연결, 기존 연합 일정 전환, 운영 반영은 하지 않았다.
인도 횟수/실제 수행 통계나 자동 배정 알고리즘을 추가하지 않는다.
