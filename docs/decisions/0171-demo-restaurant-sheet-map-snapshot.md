- 날짜: 2026-11-23
- 브랜치: `claude/perf-progressive-nov23`(앞선 기록: 0170)

  - SQL·권한·저장 의미·설정 변경 없음. 데모 DB에 쓰기 없음.

## 원인 (소비 필드별)

- 0170에서 식당 시트 관문은 '전체 건물'(`full`)을 요구했다.
  - 그래서 지도용 건물(`map`)을 이미 받은 뒤에도 시트를 열 때 전체 건물·카드·지역·방문 기록·세션을 다시 받았다.
  - 측정값: 6건 / 37 KB, '불러오는 중' 약 0.4초.
- `RestaurantServiceSheet`(와 `RestaurantCatalog`)가 실제로 읽는 값과 그 출처:

| 소비 | 필드 | 지도 단계에 있나 |
|---|---|---|
| 목록·검색·이름 | 건물 `name, address, isRestaurant`, 세대 `id, number, isRestaurant` | 있음 |
| 지역 묶음 | 건물 `cardId` → 카드 `region` | 있음(지도 단계도 같은 카드 조회) |
| 이전 기록·최근 방문 | `visitHistories`의 `unitId, visitedAt, visitor, visitType, memo` | 있음(지도·전체 단계가 같은 방문 기록 조회) |
| 봉사 시작 payload | `buildingId, unitId, name, address` | 있음 |
| 결과 저장 | `onAddRestaurantVisit(unitId, memo)` | 저장소 건물 불필요 |
| 추가 신청 | 입력값 + 이미 있는 `cardBoundaries` | 건물 불필요 |

- 전체 단계에만 있는 값은 건물·세대·출입 기록의 `memo`이다. 시트는 이 값을 읽지 않는다.

## 결정

1. `FullBuildingGate`에 `tier`(`'map' | 'full'`, 기본 `full`)를 둔다.
   - 식당 시트는 `tier="map"`이다. '지도 이상' 자료가 있으면 열고, 없으면 지도 단계를 요청한다(`requestMap`).
   - 펼친 정기방문 목록과 추가 시트는 그대로 `full`이다.
2. 저장소의 도구 요청은 `null | 'map' | 'full'` 하나다.
   - 경로 단계보다 높을 때만 올린다.
   - 지도 요청은 이미 있는(진행 중 포함) 전체 요청을 낮추지 않는다(`current ?? 'map'`).
3. `mapReady`는 받은 단계가 지도·전체일 때만 참이다. 캘린더·구역 축약 자료는 지도로 치지 않는다.
4. 하지 않은 것
   - 부분 자료를 완전한 `Building`으로 바꾸지 않는다.
   - 지도에 식당용 자료를 미리 싣지 않는다(지도 조회 열·크기 그대로).
   - 새 조회나 열을 만들지 않는다.

- 새·바뀐 시험

    - 지도 자료가 있으면 추가 조회 없이 시트를 연다. 같은 상태에서 정기방문 목록은 계속 기다린다.
  - 격리 시험(DB 없음)
    - 지도 자료만으로 식당 목록과 이전 기록을 보인다.
    - 시작 payload `{buildingId: 7, unitId: 71, name, address}`를 저장한다.
    - 결과 저장 `onAddRestaurantVisit(71, memo)`를 부른다.
  - 저장소
    - 지도 요청은 지도 열만 읽고 메모가 없다. 같은 요청을 다시 하면 읽지 않는다.
    - 전체 요청은 따로 읽고, 그 뒤 지도 요청은 낮추지 않는다(다음 새로고침도 전체 단계).

    - 진행 중인 전체 요청과 지도 요청이 겹치는 경우(같은 동작 안, 전체 응답 보류 중)에도 전체가 유지·완료된다.
- 변이: 엄격 실행기(`mut171b.py`)로 판정했다.
  - 기준 통과를 먼저 확인했다.

## 대가와 한계 (숨기지 않음)

- P(운영과 같은 앱) 대비 남는 대가
  - 지도를 열 때 약 0.35초를 더 기다린다(P는 나의 봉사 진입 때 이미 받음).
  - 식당 시트를 먼저 열 때 약 0.4초를 더 기다린다.
  - 요청은 지도 여정이 +3건이다. 지도 단계 조회가 따로 나가기 때문이다. KB는 P보다 적다(41.4 대 44.8 KB).
- 첫 진입만 하고 나갔다가 다시 오면 이름표를 다시 읽는다(3건 / 0.3 KB, 약 0.19초). 0170부터 있던 대가이고 이번에 바꾸지 않았다.
- 봉사자 전역 첫 로딩, 관리자 보기 전환, PC 진행률은 이번 범위가 아니다.
- 구역 → 식당 시트는 지도 단계를 새로 받는다(구역 축약 자료는 메모·좌표·출입 기록이 없다).
