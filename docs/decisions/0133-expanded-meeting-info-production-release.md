- 상태: 사용자 운영 적용 승인, 배포 전 검증 완료
- 결정일: 2026-11-18
- 선행: [0130](0130-saved-service-labels-and-compact-calendar.md), [0131](0131-stable-service-group-directory.md), [0132](0132-add-groups-from-existing-service-event.md)

## 표시 계약

- 집단 상세에 모임 정보가 있으면 기본으로 펼친다. 사용자가 접는 동작은 남긴다.
- 인도자/장소/메모가 공백이고 모임 방식도 없으면 영역 자체를 생략한다.
- `in_person` 방식 자체도 정보다. 장소 미등록이어도 현장 모임 표시를 보여 준다.
- 한국어/중국어 UI의 모임 방식은 `线上` / `现场`, 영어는 `Online` / `In person`으로 표시한다.
- 저장 값 `virtual` / `in_person`, 선택 사항인 접속 링크/회의 번호/비밀번호, 승인 세션 조회 권한은 그대로다.
- 펼침으로 새 조회를 추가하지 않는다. 기존에도 details 내부 접속 정보 컴포넌트는 마운트되어 있었다.
- 목록의 모임 표시, 일정 편집 선택란, 접속 정보 제목도 같은 표현을 쓴다.

## 운영 전환 절차

`scripts/releaseServiceGroupDirectory.mjs`는 운영 프로젝트/DB 사용자를 고정 검사한다.
비밀 값은 로컬 저장소 제외 `backups/nov18-service-directory-release`에만 둔다.

1. `inspect`: 배포 SHA, 실제 환경변수, 그룹/소속, 선행 함수 6개와 배정 함수 권한을 읽기 전용 확인.
2. `apply-db --confirm-production`: 위 시점과 자료가 같을 때 public/private 백업 및 목록 읽기 검증.
   동일 SQL을 롤백 리허설하고 전후 자료가 같음을 확인한 뒤, `psql --single-transaction`으로 설치.
   5초 잠금 제한/60초 문장 제한을 적용한다.
3. 일정/신청/카드 배정 두 표/모임 접속 정보 5개 표의 전체 해시 및 기존 함수 6개 본문 해시를 비교한다.
   내부 관리 함수 공개 실행 차단, 사용자 집단 연결, 배정 함수 목록을 감사한다.
4. DB 준비 완료 후에만 feature HEAD를 main에 fast-forward push한다. 운영 Git 자동 빌드는 기존 비밀 환경변수를 유지한다.
5. `verify-release <SHA>`로 운영 별칭의 READY/정확한 SHA, 환경변수 동일, 설치/권한 상태를 재확인한다.

DB 설치와 앱 업데이트 사이 구버전 관리자의 집단 목록 저장은 거부된다. 신청·배정 기능은 유지한다.
백업은 목록 검사까지이며 실제 복원 시험은 하지 않았다. 새 관리 동작이 생긴 후 전체 백업 복원을 자동 실행하지 않는다.
문제 시 기능을 멈추고 수정 앱으로 복구한다. 옛 앱만 되돌리면 집단 관리까지 복구된다고 주장하지 않는다.

## 적용 기록

운영 DB/앱 변경 결과와 배포 식별자는 실제 적용 후 별도 기록한다.
