# 지도 범위별 건물·방문 기록 실시간 동기화

- 상태: 운영 적용 (2026-09-30, 복구 방식은 0009로 대체)
- 결정일: 2026-09-30
- 관련: `20260930_2200_territory_realtime_signals.sql`, `useTerritoryRealtime`, `territorySync`

복구 범위/비용 결정은 [0009](0009-territory-recovery-watermark.md)로 대체한다.
아래 과거 신호 전체 복구와 실측 수치는 첫 구현의 기록이며 현재 동작이 아니다.

## 배경과 결정

기존 `unit_creation_signals`는 새 세대만 알린다. 부재/만남/취소와 빈 건물 추가는
다른 기기에 늦게 나타났다. 지도 화면에 한해 현재 선택된 카드들의 변경 신호를
받고, 해당 건물·세대·최근 1년 방문 기록만 다시 읽는다. 모바일·PC가 같은
store callback을 사용하며 필터/선택 건물/지도 위치/시트 상태는 바꾸지 않는다.

## 권한과 저장 계약

- 원본 테이블을 Realtime publication에 추가하거나 원본 RLS를 넓히지 않는다.
- 신호에는 건물 ID·카드 ID·트랜잭션 revision만 있다. 이름, 주소, 호수, 방문자,
  결과, 메모, 세션 토큰은 없다. 원본 내용은 기존 HTTP 세션/RLS로 읽는다.
- WebSocket에는 앱의 `x-session-token`이 없으므로 기존 생성 신호처럼 메타데이터
  SELECT만 anon/authenticated에 허용한다. 쓰기와 private 함수 EXECUTE는 금지한다.
- 신호는 `(building_id, card_id)`별 한 행을 UPSERT한다. 방문 횟수만큼 늘지 않는다.
  건물 이동은 양쪽 카드에 신호를 남긴다. 건물/카드 삭제 시 FK cascade로 지워진다.
- 같은 트랜잭션의 여러 세대/이력 변경은 한 번으로 합친다. 구버전 호환을 위해
  기존 생성·삭제 채널과 트리거를 유지한다.
  건물 삭제 알림은 이 표가 아니라 기존 `place_change_signals` 채널이 담당한다.

## 사용량과 복구

- 지도 범위의 카드 ID로 서버에서 필터링한다. IN 필터당 최대 100개씩 나눈다.
- 350ms 동안 같은 건물 신호를 합치고 최대 20개 건물씩 직렬 조회한다.
- 새 신호 기능이 켜진 지도에서는 옛 생성 채널의 중복 전체 조회를 끈다.
- 지도 이탈/백그라운드에서는 새 채널을 닫는다. 구독/재구독/복귀 시 해당 카드의
  신호 목록을 한 번 읽어 빠진 변경을 복구한다. 주기적인 전체 폴링은 없다.
- 복구 시에는 그 카드에 과거 신호가 남은 건물도 읽는다. 일반 전체 지도에서는
  최초/복귀 때 읽는 양이 커질 수 있다. 반복 방문 기록은 해당 건물 자료만 읽는다.
- 1,000행 제한에 걸리지 않도록 세대와 방문 기록을 각각 페이지 조회한다.
- 요청 실패는 최대 3회 시도한다. 이후 재접속/지도 재진입 때 복구한다.
- 늦게 끝난 이전 지도의 응답은 더 최신 응답을 덮어쓰지 못한다.
- 동시 접속자/변경 수에 따라 Realtime 메시지는 늘어난다. "무료" 혹은 사용량이
  전혀 증가하지 않는다는 보장은 하지 않는다. 지도 타일은 이 동기화와 별개다.

## 지도 진입 범위

검색 결과로 이동할 때 `scope`와 `cardIds`를 `assignmentMap`, `assignmentCard`,
`return`과 함께 보존한다. 지역·상태 같은 표시 필터만 초기화한다. 내 카드와
정기방문 지도가 일반 지도로 풀리는 문제를 재현하는 URL 회귀 시험을 추가했다.

## 검증

- URL 보존을 되돌리면 내 카드/정기방문 신규 시험 2개가 실패한다.
- 실시간 큐를 제거하면 묶음/진행 중 재수신 시험 2개가 실패한다.
- store 시험: 새 빈 건물, 다른 건물 보존, 상태/이력 갱신, 취소, 실패 시 보존,
  역순 응답 방어. 조회 시험: 범위 필터와 1,001세대 페이징.
- `_TEST_territory_realtime_signals.sql`: 권한, 빈 건물 신호, 같은 트랜잭션 합치기,
  카드 이동 양쪽 신호, 삭제 정리. 시험 자료는 내부 예외 블록으로 롤백한다.
- `scripts/smokeTerritoryRealtime.mjs`: 데모 DB만 허용하며 합성 일정/건물로 두
  브라우저에서 부재/취소/빈 건물/첫 세대/복귀/다른 카드 제외/검색 범위를 확인한다.
  마지막에 합성 자료를 삭제한다. 운영 자료로 시험하지 않는다.

2026-09-30 데모 실측: 동일 봉사자 계정의 독립 브라우저 2개에서 위 항목 통과.
부재 203/204, 취소, 빈 건물, 첫 호수, 백그라운드에서 변경을 놓친 뒤 재구독 복구,
범위 밖 카드 생성 무조회, 두 지도 검색 범위를 확인했다. 지도 중심/줌/시트 높이는
방문 상태 동기화 전후 같았다. 첫 부재 반영 1,058ms, 이 작은 시험의 수신 브라우저
조회 19건 응답 본문 합계 5,719바이트였다 (첫 로딩·지도 타일·HTTP/WS 오버헤드 제외).
이 수치는 운영 사용량 상한이 아니다. 1,061 tests / 148 files, lint/build 통과.
특정 건물 직접 진입은 최초 진입 때만 지도를 이동한다. 갱신 때 반복 이동하는
가드를 제거한 변형에서는 새 회귀 시험이 실패함을 확인했다.

실행 예:
```sh
PLAYWRIGHT_ALLOW_WRITES=true DEMO_ENV_FILE=/absolute/path/.env.test.local \
PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs \
node scripts/smokeTerritoryRealtime.mjs
```

## 배포와 복구

1. 대상 DB를 백업하고 마이그레이션을 `psql --single-transaction`으로 적용한다.
2. 해당 Vercel 프로젝트에서 `VITE_TERRITORY_REALTIME_ENABLED=true`를 설정하고 배포한다.
3. 데모 검증 후 2026-09-30 운영 적용 완료. 상세 배포 기록은 0009를 참조한다.
4. 복구 시 플래그를 끄고 앱을 배포한 뒤 전용 rollback SQL을 실행한다.
   원본 방문/건물 데이터와 구버전 생성·삭제 채널은 그대로 유지된다.

데모 사전 백업: `backups/2026-09-30-demo-realtime/before-realtime.dump` (비공개).
