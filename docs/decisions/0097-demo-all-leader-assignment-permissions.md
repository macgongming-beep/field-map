# 모든 인도자의 배정 관리와 관리자 일정 편집을 분리한다

- 상태: 데모 적용, 운영 미적용
- 결정일: 2026-11-17
- 관련: 0096의 감독자 전용 권한을 대체한다. 집단별 독립 일정·신청 탭은 유지한다.

## 사용자 결정

회중·집단 봉사 모두 활성·승인된 인도자 이상이면 신청자 관리, 팀 구성, 구역 배정,
공유를 할 수 있다. 일정의 인도자 이름에 포함될 필요는 없다. 날짜·시간·제목·장소·
모임 정보 등 일정 자체의 생성·수정·삭제는 관리자/개발자만 한다.
집단 감독자 매핑은 권한에 사용하지 않고, 기본 탭은 본인의 소속 집단으로 정한다.
이름 목록은 실제 인도자 표시용이며 배정 권한의 기준이 아니다.

## 서버 계약

- `private.user_can_manage_event`: 존재하는 모든 일정의 배정 관리(승인·활성 leader/admin/developer).
- `private.user_can_edit_event`: 일정 편집(admin/developer). 새 일괄 저장, 단일 수정,
  반복 수정 wrapper 모두 이 판정을 쓴다. 직접 일정 쓰기의 기존 관리자 RLS도 유지한다.
- 기존 회중 일정도 배정 권한을 넓힌다. 일반 성원의 기존 회중 조회 범위는 바꾸지 않는다.
- 새 집단 일정 명단은 모든 인도자에게 공개한다. 이는 이전 감독자 전용보다 의도적으로 넓어진 범위다.
  일반 성원은 소속 집단 명단과 본인 행을 조회한다. 배정은 공유된 본인/같은 일정의 같은 팀까지만
  조회한다. 다른 팀과 공유 전 배정은 서버에서도 숨긴다. 소속 없는 사람의 신청을 막지 않는다.
- 감독자 매핑 표는 이전 데모 복구를 위해 남기되 권한·기본 탭 판정에서 제외한다.
- 다른 집단 대신 배정할 때 막히지 않도록 데모 배정 편집기에서는 인도자도 전체 구역 카드를 선택한다.

## 동시 편집 보호

공유 시각만 비교하면 두 명이 공유 전 초안을 저장할 때 모두 null이라 덮어쓴다.
별도 `private.event_assignment_revisions`에 일정별 버전을 두고, event 행 잠금 아래 버전을
비교하여 저장한다. 신청·취소, 팀 배정, 개인 비공식/식당 배정 변경도 버전을 올린다.
버전은 공개 일정의 computed field로 읽지만 이름·접속 정보는 포함하지 않는다.
참가자 변경마다 calendar_events를 수정하지 않아 전체 일정 변경 방송을 늘리지 않는다.

- 새 저장은 `save_event_assignments_versioned_tx`로만 한다. 이전 bulk RPC와 팀원 제거 RPC의
  클라이언트 실행 권한을 회수하고 직접 카드 배정 쓰기도 차단한다. 구버전은 실패하도록 한다.
- 참가자 추가/제거는 `manage_event_participant_versioned_tx`에서 버전을 비교한다.
  본인 신청 취소는 허용하고, 배정과 관련 세션은 정리하되 세션 ID/방문 이력은 보존한다.
- 편집기 진입 시 일정과 버전을 먼저 읽고 배정 행을 읽는다. 이후 다른 저장이 생기면 충돌로
  처리한다. 실시간 갱신으로 열린 편집기의 기준 버전을 몰래 새 값으로 바꾸지 않는다.
- 기기 임시 저장도 기준 버전을 기억한다. 충돌 때 임시 저장은 남기며, 사용자가 최신 내용을
  확인한 뒤 다시 열거나 명시적으로 이어서 편집한다.
- 실제 저장자의 이름은 기존 `assigned_by`에 기록한다.

## 갱신과 화면

집단 신청 신호는 캘린더 재사용 설정과 무관하게 해당 일정 명단만 재조회한다.
재연결과 앱 복귀 때 열린 시간대의 집단별 인원수를 다시 확인한다.
null/빈 종료 시각은 같은 값으로 묶는다. 중복 신청을 사람 수로 오인하지 않게 합계는 `신청 N건`이다.
회중·집단 상세의 일정 수정은 관리자만, 배정·참가자 관리 도구는 모든 인도자에게 표시한다.
모바일과 PC는 같은 권한 함수를 사용한다. 공유된 배정은 기본으로 펼친다.

## 검증과 남은 범위

- 전체 자동시험 2,523개, 빌드, lint 통과. SQL 권한/버전 검사를 제거한 변형은 해당 시험이 실패한다.
- 데모 실제 API 21개 검증: 이름에 없는 인도자의 회중·타 집단 배정, 이름에 있는 인도자도
  일정 수정 차단, 관리자 편집, 동시 초안 저장 1건 성공/1건 충돌, 우회 RPC 차단,
  외부 집단 참가자의 공유된 팀원 조회, 팀원 제거/본인 취소/버전 증가, 실제 저장자 기록.
  검증 전용 일정은 종료 후 삭제했다. 기존 데모 일정은 보존한다.
- Playwright: 모바일 430, 320/125%, PC 1440, 신청/취소 실시간 갱신, 타 집단 배정 진입,
  두 인도자가 연 편집기의 두 번째 공유 충돌 및 임시 저장 보존. 이름에 없는 회중 인도자의
  배정 편집 진입과 일정 수정 숨김도 확인했다. 화면 오류 없음.
- 새 definer 실행권한 감사 완료. 이전 직접 저장 진입점은 anon/authenticated에게 닫혀 있다.
- 데모 권한 조회 EXPLAIN ANALYZE: 배정 10행/세션 33행 규모에서 약 1~4ms.
  **운영 규모의 성능 검증은 아니다. 운영 사본에서 누적 세션 규모로 별도 측정해야 한다.**
- 인도 횟수 통계, 자동 배정, 채팅 권한 재설계는 추가하지 않았다.

## 적용과 복구

운영 DB·운영 배포·main은 변경하지 않는다. 데모 프로젝트 주소를 검사하는 기능 플래그와
`scripts/groupTabsDemo.mjs apply-review --confirm-demo`로만 적용했다.
마이그레이션은 `20261117_1000`, `20261117_1010`이며 public/private 백업 후 한 트랜잭션으로 적용한다.
직전 함수/정책 복구 SQL은 `backups/group-tabs-demo-1794873320714/rollback.sql`이다.
복구 시 이전 데모 앱과 함께 되돌린다. 새 앱은 구 DB에 직접 쓰기로 우회하지 않는다.

재검증: `groupTabsDemo.mjs review-smoke`, `checkGroupTabsUi.mjs`, `auditAssignmentReviewDemo.mjs`.
환경 파일·토큰 포함 fixture·감사 결과는 로컬 전용이며 커밋하지 않는다.
