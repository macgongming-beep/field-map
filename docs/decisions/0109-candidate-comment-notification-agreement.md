# 운영 후보의 댓글 알림 계약

- 날짜: 2026-11-17
- 상태: 사용자 승인, 후보 코드 반영. 운영 미적용.
- 기준 후보: `b1cfa90`, 브랜치 `codex/group-service-release-candidate`.

## 결정

사용자가 재확인한 기존 합의대로 일반 댓글은 푸시만 보내고 알림함 목록과 안 읽음 숫자에서 제외한다. @멘션은 푸시와 알림함에 남는다. 공지/일정 변경/배정 등 다른 알림 종류는 그대로다. 사용자 수신 설정과 작성자 제외/수신자 중복 제거도 바꾸지 않는다.

집단 봉사만의 클라이언트 필터가 아니라 기존 0101/0085 방향의 공통 알림함 계약이다. SQL에서 `type <> 'comment'`를 LIMIT보다 먼저 적용한다. 일반 댓글 60건 때문에 더 오래된 멘션이 조회 밖으로 밀리지 않는다.

## 구현

- 검증된 `20261110_1600_notification_feed_without_comments.sql`과 SQL 회귀 시험을 후보에 추가했다.
- 새 앱은 목록/배지/정기 갱신 모두 `get_my_notification_feed`를 사용한다. 추가 환경변수나 데모 기본값에 의존하지 않는다. 집단/리비전 설정이 모두 꺼진 첫 배포에서도 같은 알림 계약이다.
- 기존 `get_my_notifications`와 저장된 알림은 보존한다. 이 변경은 댓글 알림 생성/푸시 함수를 변경하거나 기존 알림을 삭제하지 않는다. 구버전 앱은 기존 목록을 계속 읽는다.
- 새 RPC가 없으면 기존의 재시도 가능한 로딩 오류가 되며, 조용히 옛 목록으로 후퇴하지 않는다. 따라서 첫 배포 전 준비 DB 확인이 필수다.
- 준비 묶음에 새 SQL을 포함해 19개가 되었다. notifications의 필수 칼럼을 선행 검사하고, 첫 배포 관문은 새 RPC와 anon/authenticated 실행권한도 검사한다.
- 호환 기간의 실제 생성 SQL을 실행하는 시험에서 일반 댓글 제외/본인 멘션 유지/타인 알림 차단을 확인한다. 엄격 단계에서도 알림 조회 권한은 유지한다.

## 검증 범위

- 전체 자동 시험 260파일 / 2,531개, lint, TypeScript/Vite 빌드 통과.
- SQL의 일반 댓글 제외 조건 제거 시 2개, 본인 조건 제거 시 1개 시험이 실패했다. 정상 원본의 전체 시험은 통과했다.
- 클라이언트 조회를 옛 RPC로 고의 되돌리면 새 알림 계약 시험이 실패했다. 정상 코드 복구 후 3개 시험이 다시 통과했다.

로컬 SQL 및 React 시험으로 일반 댓글 제외, 멘션/다른 알림 유지, 서버 필터의 LIMIT 순서, 본인 세션 범위, 누락/만료 세션 거부, 읽기와 푸시 생성 분리, 원본 행 보존을 검증한다. 새 읽기 함수는 최대 100건, 앱 요청은 기존대로 50건이다. 배지는 본문 없이 읽는 기존 최적화를 유지한다.

일반 댓글 필터 또는 본인 조건을 고의 제거한 SQL 변형은 시험에서 실패한다. 집단/리비전 설정 true/false 모두에서 배지·목록·polling이 새 함수를 쓰는 시험도 추가했다.

운영/데모 DB·배포·환경변수는 이번 변경에서 만지지 않았다. 실제 휴대폰 푸시 재수신을 확인했다고 주장하지 않는다. 운영 설정 읽기 전용 대조, 실제 설정으로 재빌드, 호환 DB + 새 앱의 기능 OFF 화면 검사는 별도 남은 관문이다. 이 변경의 알림 조회 시험이 그 전체 화면 검사를 대신하지 않는다.
