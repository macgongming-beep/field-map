# 데모 지도 축소 중 표시 교체와 스타일 갱신 절감

- 날짜: 2026-11-22
- 상태: 로컬 검증 완료, 데모 반영 대상. 운영 미적용.
- 기준: 운영 소스 `1fe6b3e`, 작업 시작 `5581470` (앱 코드 동일).
- 범위: 공용 MapCanvas와 줌 종료 판정. 조회, 권한, 저장, 집단 후보, GPS, 기능 설정은 변경하지 않는다.

## 원인과 결정

클로드 측정 묶음 `~/Downloads/fieldmap-perf-20261122.zip`의 관리자 x47 현상을
같은 빌드 설정으로 재현했다. 추가 호출 시각 기록에서는 다음 순서가 확인됐다.

1. 배율 15에서 idle이 와서 120ms 뒤 표시 갱신을 예약한다.
2. SDK의 getZoom은 이미 14로 바뀌었지만 다음 zoom_changed는 아직 오지 않는다.
3. 옛 예약이 실행되면서 중간 화면용 표시 1,184개를 만든다.
4. 배율 13의 구/동 표시가 적용되면서 방금 만든 표시 1,184개를 제거한다.

예약 때의 배율과 실행 때의 배율이 다르면 그 작업을 건너뛰고 다음 idle을 기다린다.
dirty 상태는 지우지 않는다. 일반 건물 지도에서도 다음 배율이 15 미만이면 최종
클러스터를 갱신해야 하므로, 이동과 줌을 구분한다. 낮은 배율의 단순 이동은 기존처럼
재계산하지 않고, 줌 변경은 갱신한다. 구/동 집계 표시는 부모가 정하는 기존 경로를 유지한다.

경계선 스타일은 각 폴리곤 객체에 마지막으로 적용한 속성을 WeakMap으로 기억한다.
선택, 팀 색, 선/채움, map, clickable이 모두 같을 때만 SDK 호출을 생략한다.
숨김/복원이나 새 폴리곤은 다시 적용한다. 지도 중심/배율을 변경하는 코드는 추가하지 않는다.

## 전후 측정

운영과 같은 기능 설정 46개, 데모 DB, Chromium 390x844, CPU 4배 감속,
서비스워커 OFF, 앱 파일 로컬 제공, 실제 Naver SDK. 각 역할/버전 3회 순차 실행이다.
동작은 드래그, 확대 휠 3회, 축소 휠 5회이며, 빠른 연속 조작 중 예약의 경쟁을 포함한다.
아래 시간은 50ms 넘는 메인 스레드 작업의 **합계 중앙값**이지 실제 아이폰 로딩 시간이 아니다.

| 관리자 긴 작업 합계 | 4,139ms | 146ms |
| 관리자 마지막 긴 작업 종료 시점 (조작 시작 기준) | 5,026ms | 1,121ms |

최종 관리자 3회는 148/146/145ms, 변경 전은 4,072/4,139/4,146ms다.
인도자 계정의 현재 데모 진입은 집단 구역 0개 표시 뒤 전체 지도로 열렸다.
따라서 클로드의 이전 "인도자 내 집단" 수치와 직접 비교하지 않는다.
내 집단 기능은 별도의 609개/담당 118개 화면 fixture로 확인했다.

x47은 카드 611개, 건물 2,115개, 세대 3,478개, 경계선 329개로,
실제 운영보다 건물이 많고 경계선은 적다. 운영에서 4초가 0.15초가 된다고 단정하지 않는다.
지도 타일 전송량/과금과 실물 아이폰/안드로이드 성능은 별도 확인 대상이다.

## 사용량과 안전

- 관리자 지도 진입: 전후 모두 15요청, 응답 원문 1,572.6KiB. 인도자: 15요청, 1,509.1KiB.
- 드래그/확대/축소는 전후 모두 DB 요청 0건, 응답 0바이트. 홈과 구역 진입의 요청 수/원문 크기도 동일하다.
- 원문 크기는 압축 전이며 네트워크 청구량과 같지 않다. 앱 JS 17개 합계는 2,508,901 → 2,509,120바이트(+219),
  gzip 합계는 708,616 → 708,707바이트(+91)다. 파일 수/추가 요청은 같지만 코드 전송 크기가 완전히 같다고 하지는 않는다.
- 데모 표 쓰기/Storage 쓰기를 차단하고 RPC는 기존 측정에서 관측된 이름만 허용했다.
  자동 세션 정리 RPC는 실제 실행하지 않고 응답을 대체했다. 로그인/자동 로그인 RPC의 데모 세션·로그 기록은 발생한다.
- 운영 DB에는 접속하지 않는다. 운영 배포/환경변수와 두 보류 최적화 설정도 변경하지 않는다.
- 배정 저장/권한/담당 범위/색 의미를 바꾸지 않으며 실제 배정 공유나 운영 자료 저장은 이번 검증에 포함하지 않는다.

## 후속

이번 변경은 홈 최초 진입의 직렬 조회나 화면 코드 선로딩을 개선하지 않는다.
0140의 두 최적화 설정도 여전히 보류한다. 지도 개선을 리뷰한 뒤 홈 경로를 별도 비교한다.
공개 MapCanvas의 `selectedCardIds`가 내부 Naver 부품에 전달되지 않는 기존 경로도 읽기 중 발견했다.
이번 스타일 최적화와 별개이며, 다중 선택 강조 보완은 별도 변경으로 다룬다.
