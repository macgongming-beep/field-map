## 배경

- 사용자 요청: 나의 봉사는 먼저 보일 것만 준비하고 나머지는 필요할 때 받는다.
- Codex 설계 검토: 전체 조회를 늦게 하는 것이 아니라 필요한 것만 조회한다. 한 번에 하나씩 바꾼다.
- 첫 묶음은 그 전제 조건이다.
  - 지금 오늘 배정 줄은 카드 객체를 공용 `cards`에서 찾는다. 카드가 아직 없으면 `filter(Boolean)`으로 빠져 '배정 카드 없음'이 보일 수 있다.
  - 식당 줄은 건물이 없으면 `if (!b) return null`로 조용히 사라진다.
  - 이것을 고치지 않고 화면 관문을 풀면 미조회 상태가 '없음'으로 보인다.

## 결정

1. **카드 이름표**
   - 오늘·미래 배정 줄은 배정 카드 번호를 배정 순서대로 들고 있는다(`assignmentCardIds`).
   - 이름은 공용 저장소 카드가 있으면 그것을 쓴다.
   - 하나라도 없으면 그 줄들에 필요한 번호 전체로 `readCardDirectory(ids)`(`cards` `id,name`)를 한 번 읽는다.
     - 읽는 도중 저장소가 채워져도 다시 읽지 않는다.
   - `useSharedCardNames`는 쓰지 않았다(`shared` + `ScopedCardContext` 조건 전용).
2. **식당 이름표 (`readPlaceLabels`)**
   - 건물: `id,card_id,name,address,lat,lng`
   - 세대: `id,building_id,number`
   - '길찾기'가 쓰는 좌표·카드 번호를 포함하고, 메모·출입 기록·정기방문은 읽지 않는다.
   - 저장소 건물이 있으면 그것을 쓴다. 건물은 있는데 세대가 없으면 예전처럼 건물 이름만 보인다.
   - 이름표 조회에서 세대가 없을 때도 같다.
3. **표시 원칙**
   - 이름이 아직 없는 줄은 빼지 않는다. `···` 자리와 `aria-busy`를 두고 개수에도 넣는다.
   - 실패하면 그 줄에 '다시 시도'를 보인다.
   - 조회가 끝났는데 없는 카드·건물(삭제됨)은 예전처럼 빠진다.
   - 이름표는 공용 저장소에 넣지 않는다. 합계 없는 `TerritoryCard`/`Building`을 만들지 않는다.
4. **검증**
   - 두 조회는 함께 시작해 둘 다 끝난 뒤 실패를 알린다.
   - 세션이 바뀌면 거부한다. 요청 번호 밖 행, 다른 건물의 세대, 카드 없는 건물, 중복 행도 거부한다.
   - 늦은 응답은 키·재시도 회차 검사와 `active` 표시 두 겹으로 버린다.
5. **진행률:** 나의 봉사 오늘 배정 줄에 보이던 진행률(%)을 뺐다(사용자 결정).
   - 관리자 전용 카드 목록(`role === 'admin'`)의 건물 수·완료 숨기기·정렬은 그대로다.
   - 구역·배정 편집기·PC 화면의 요약과 완료 판정도 그대로다.
   - PC 나의 봉사(`DesktopMyService`)의 진행률·세대 수·상태 표시는 이번에 바꾸지 않았다(결정 대기).
6. **바꾸지 않은 것**
   - 화면 관문(인도자 `/territory`의 전체 건물 대기, 전역 첫 로딩)
   - 지난 봉사(접힌 목록)의 카드 이름 경로, 정기방문·재방문, 식당 시트
   - 공용 `serviceSessions`
