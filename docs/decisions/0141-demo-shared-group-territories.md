# 공동 담당 가능한 집단 구역

- 상태: 데모 적용. 운영 미적용.
- 결정일: 2026-11-20
- 선행: 0131 집단 목록, 0139 지도 기억, 0140 화면별 로딩

## 결정과 범위

구역을 복제하지 않고 구역 ID와 집단 코드를 다대다로 연결한다. 한 구역에
여러 집단이 연결될 수 있고, 한 집단 해제는 다른 집단의 연결을 지우지 않는다.
회중 전체 구역은 모든 구역이고, 집단 구역은 그중 해당 집단이 담당하는 부분이다.
집단 이름은 설정의 실제 이름을 표시한다. 이름 변경은 코드 연결을 바꾸지 않는다.

- 관리자/개발자: 배정 화면에서 집단 선택, 구역 추가/해제. PC 구역 표에서도 가능.
- 인도자: 전체 구역 조회 유지, 본인 소속 집단을 기본으로 표시하고 다른 집단/전체 선택 가능.
- 소속 없는 인도자: 전체를 기본 표시. 일반 봉사자 개인 배정 범위는 변경하지 않는다.
- 소속 집단은 사용자 명단의 `groupName`과 기존 집단 디렉터리를 연결해서 구한다.
- 집단 목록/지도 필터는 표시 범위다. 인도자의 기존 전체 구역 조회 권한을 확장하지 않는다.
- 당일 봉사 신청, 팀 편성, 구역 배정, 공유, 세션/방문 기록은 기존 경로를 유지한다.
- 기존 `card_leader_assignments`, `card_assignments`, `cards.leader_name/status`는 보존한다.
  개인 담당을 집단 담당으로 추측해 자동 이관하지 않는다. 기능을 끄면 기존 화면이 복원된다.
- 지도 중국어 필터와 집단 필터는 함께 적용된다. 설명은 잠깐 표시한 뒤 사라진다.
  선택 상태는 버튼과 집단 선택에 남는다. 기존 GPS/수동 확대 처리 코드는 변경하지 않았다.
- 빈 집단에서 지도를 열어도 전체로 확대되지 않는다. 지도에서 전체 선택은 명시적 동작이다.
- 집단 비활성화는 담당 이력을 삭제하지 않는다. 새 배정은 막고 기존 연결 해제는 허용한다.

## 저장과 권한

`20261120_1600_territory_group_assignments.sql`은 추가형 변경이다.

- `card_group_assignments(card_id, group_code)` 복합 PK, 역방향 인덱스.
- `cards.group_assignment_revision`: 각 구역의 집단 연결 변경마다 증가.
- `set_territory_group_assignments_tx`: 활성/승인 관리자 또는 개발자만 실행.
  1~500개 구역을 오름차순 잠근 뒤 화면의 리비전을 전부 대조한다. 하나라도 오래됐거나
  구역이 없으면 전부 실패한다. 선택한 집단만 추가/해제한다.
- 집단 관리와 같은 advisory lock으로 집단 비활성화/이름 변경과 순서를 맞춘다.
- 직접 INSERT/UPDATE/DELETE는 anon/authenticated 모두 차단한다.
- SELECT는 승인/활성 인도자 이상만 허용한다. 본인 역할이 일반 봉사자이거나
  세션이 없는 경우 연결 명단을 읽지 못한다. definer helper 자체에서 역할을 검사한다.
- 작성자 삭제는 `assigned_by`만 비우고 담당 연결을 유지한다. 구역 삭제는 FK로 정리한다.
- 배정 저장 실패/충돌은 화면에 알리고 카드 자료를 다시 확인한다. 성공 뒤에도 카드만 다시 읽는다.
- 실제 데모 DB 감사: 기존 배정 definer 13개와 실행권한 그대로, 새 trigger 실행권한 닫힘.

## 조회와 사용량

`VITE_GROUP_TERRITORY_ENABLED=true`를 명시한 빌드만 새 카드 관계를 조회한다.
데모 모드만으로 켜지지 않는다. 일반 봉사자는 새 관계를 요청하지 않는다.
기존 카드 조회에 집단 코드/리비전을 함께 받으므로 별도 초기 요청은 추가하지 않는다.
응답에 새 메타데이터가 포함되므로 **전송량이 완전히 같다고 주장하지 않는다.**

실제 데모 자료, 로컬 WebKit 화면에서 집단/중국어 필터를 바꾸고 요청이 600ms 동안
조용해질 때까지 측정했다. 진행 중 응답도 추적하며 30초를 넘기면 실패한다.

- 모바일: 기존 실시간 범위 복구 2건(`territory_sync_clock`, `territory_change_signals`),
  응답 원문 합계 35~36바이트. 헤더/소켓/지도 타일은 이 수치에 포함하지 않는다.
- PC: 해당 필터 구간 REST 요청 0건.
- 두 경우 모두 `buildings`, `units`, `cards`, `visit_histories` 전체 재조회 없음.
- 집단 담당 변경을 다른 기기에서 확인하는 기존 새로고침/복귀 경로는 유지한다.
  별도 집단 구독 채널은 추가하지 않았다. 즉시 반영 시간을 보장하지 않는다.

## 검증 기록

- 실제 migration을 PGlite에서 실행: 공동 담당/한 집단 해제/리비전 충돌/일괄 원자성,
  잘못된 입력, 집단 이름 변경/비활성화, 역할/세션, 직접 쓰기 차단, FK 정리.
- 실제 데모 API: 인도자 조회 성공/쓰기 42501, 일반 성원/무세션 연결 조회 0행,
  일반 성원 쓰기 42501. 익명 execute 감사와 기존 배정 definer 목록 대조.
- 데모 설치 전 public/private 백업을 만든 뒤 pg_restore 목록 검증.
  설치/예시 추가/브라우저 저장 뒤 기존 11개 표의 해시를 대조했다.
  `cards`는 새 리비전만 제외, 기존 인도자/봉사 기록/팀 배정 등은 동일.
- 브라우저: 관리자 모바일에서 공동 구역의 한 집단 해제/다른 집단 유지/복구를 실제 RPC로 실행.
  WebKit 320/390/1440, 관리자/인도자/봉사자/개발자 화면 확인.
- 로컬 네이버 지도는 허용 도메인 인증 제한이 있어 타일 실물 확인은 배포 후 데모 주소에서 별도로 한다.
- 초기에 발견한 실패: 기존 title 속성을 기대하던 시험 2개는 사라지는 설명 계약으로 변경.
  기능 OFF에서도 새 디렉터리를 계산하던 부분을 조건부로 만들어 기존 App 시험 호환 유지.
  개발자 모바일 배정이 캘린더로 넘어가던 기존 역할 분기는 새 기능 ON에서만 수정.
- 분리한 임시 복사본에서 변이 7개 모두 검출:
  다른 집단까지 삭제 1개, 오래된 리비전 허용 2개, 인도자 저장 허용 1개,
  봉사자 조회에 관계 추가 1개, 지도 건물 필터 해제 2개, 빈 집단 전체로 열기 1개,
  설명 자동 숨김 제거 1개 실패. 작업본/DB는 변이 시험에서 수정하지 않았다.
- 전체 시험 284개 파일 / 2,833개 통과, lint 통과, TypeScript/빌드 통과.
  최종 지도 기억/GPS와 집단 기능 관련 23개 시험도 통과했다.
- WebKit 역할/크기 조합 8개 및 Chromium 3개 통과. 최종 선택 메뉴 모양은
  WebKit 320px에서 추가 확인했다. 실물 iPhone/Android 조작은 사용자 확인이 남아 있다.

## 운영과 되돌리기

운영 DB/환경변수/배포/main 병합은 이번 요청 범위가 아니다.
운영 적용은 별도 코드 리뷰와 실제 기기 확인 후 결정한다.
데모를 되돌릴 때는 이전 검증 artifact 또는 플래그 false 빌드를 배포하고 PWA를 업데이트한다.
추가한 표/열은 남겨 집단 담당 이력을 보존한다. 새 클라이언트가 남아 있을 때 표나 RPC를
삭제하지 않는다. 예전 개인 담당 자료를 집단 배정으로 자동 덮어쓰지 않는다.
