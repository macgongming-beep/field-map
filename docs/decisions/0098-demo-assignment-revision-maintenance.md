# 배정 충돌 검사와 기존 관리 작업을 분리한다

- 상태: 데모 검증 완료, 운영 미적용.
- 결정일: 2026-11-17
- 관련: [0097](0097-demo-all-leader-assignment-permissions.md)의 버전 증가·취소·직접 쓰기 계약을 보완한다.
- 추가 보완: [0099](0099-demo-merge-and-substitute-application-guards.md)의 건물 병합·세션 0행 처리·대신 신청 마감/전시대 중복 검사.

## 유지하는 권한

회중·집단 봉사 모두 활성·승인된 인도자 이상이면 신청자 관리·팀 편성·구역 배정·공유가
가능하다. 일정의 인도자 명단에 이름이 없어도 된다. 일정 자체의 생성·수정·삭제는
관리자/개발자만 한다. 감독자 연결 표는 복구용이며 권한에는 사용하지 않는다.
일반 성원의 소속 명단·본인·같은 팀의 공유 배정 조회 범위는 변경하지 않는다.

## 리뷰 반영

1. **이름 변경·사용자 정리:** 현재 배포된 rename/purge 구현을 private core로 보존하고
   원래 인증·권한 검사를 유지한다. wrapper 내부의 관리 작업 표시가 있는 동안에는
   정리를 허용하되 배정 버전을 올린다. 방문 기록 보존 등 이후 추가된 기존 수정도 유지한다.
   관리자의 임의 직접 배정 쓰기까지 허용하지 않는다. private core 실행권한은 닫는다.
2. **카드·장소 삭제:** 실제 FK 부모가 사라진 연쇄 삭제만 허용하고 버전을 올린다.
   단순히 트리거가 중첩됐거나 호출자가 관리자라는 이유로 검사를 건너뛰지 않는다.
   일정 삭제는 부모 일정이 없어졌으므로 통과한다.
3. **신청과 취소:** 새 신청은 기존 팀을 바꾸지 않으므로 배정 버전을 올리지 않는다.
   본인의 `신청` 취소는 버전 비교 없이 처리하고 배정·자동 세션 정리와 버전 증가는
   같은 트랜잭션에서 한다. 타인 제거·역할 변경은 버전 검사를 유지한다.
4. **비공식·식당:** 개인 배정도 일정 잠금과 버전 검사를 하는 RPC를 사용한다.
   직접 쓰기·직접 참가자 UPDATE·타인 참가자 직접 추가는 차단한다. 새 개인 배정 대상은
   현재 일정의 봉사 참가자여야 한다. 재방·연구 참가자는 배정하지 않는다.
5. **신원:** 참가자 추가/역할 변경 RPC가 기존 `event_participant_identity_allowed`를
   직접 호출한다. 없는 계정을 신청자로 넣거나 실제 사용자를 게스트로 넣을 수 없다.
6. **봉사 기록:** `service_sessions` UPDATE/DELETE에 본인 또는 관리자 제한을 추가한다.
   인도자의 배정 권한을 다른 사람의 시간·구역 이력 편집 권한으로 확대하지 않는다.
   기존 definer의 자동 배정 세션 종료·사용자 정리는 계속 가능하며 기록 ID는 보존한다.
7. **편집기:** 개인 배정 성공분만 정확히 한 버전씩 기준에 반영하고 임시 저장/되돌리기에도
   기록한다. 다른 사람의 최신 버전을 자동 수용하지 않는다. 실패한 저장은 기준을 올리지 않는다.
   저장 후 조회 실패를 저장 실패로 오인하지 않는다. 충돌 안내는 재조회 성공 여부와 무관하게 표시한다.

`fetchAll`이라는 의존성 이름은 이 경로에서 전체 앱 조회가 아니라 캘린더 또는 자료 조회에
연결돼 있었다. 충돌 때는 해당 일정 갱신을 우선하고 재조회 실패로 충돌 결과를 바꾸지 않는다.
기간 창/캐시 화면은 전체 권한 스냅샷이 아니므로 기존 단일 일정 수정용 갱신 함수를 그대로
재사용할 수 없다. 배정 갱신은 해당 일정만 완전히 읽어 교체하고 전체 스냅샷의 완전성을 올리지 않는다.

## 검증

- 전체 자동시험 2,540개, lint, TypeScript/배포 빌드 통과.
- 실제 SQL을 실행하는 단위시험: 권한·버전·관리 작업·FK 삭제·신원·기록 제한.
  관리 작업 예외를 제거하면 관련 3개 시험, 신원 검사를 제거하면 해당 시험이 실패한다.
- 데모 API `groupTabsDemo.mjs review-smoke`: 21개 통과. 동시 초안 저장 1건 성공/1건 충돌,
  일정 편집 차단, 공유 팀원 조회, 새 신청의 버전 유지, 본인 취소 및 실제 저장자 기록.
- `checkAssignmentMaintenanceDemo.mjs`: 데모의 실제 rename/deactivate 함수와 카드·장소 FK
  삭제를 포함한 18개 통과. 최신 버전을 붙여도 제거된 팀원을 되살리는 저장은 거절한다.
  모든 시험 데이터 변경은 한 트랜잭션 안에서 롤백했다.
- 편집기 시험: 두 사람 개인 배정의 버전 순서, 실패 시 기준 유지, 이후 공유 버전,
  되돌리기 기준 유지, 충돌 후 좁은 재조회 실패 처리.
- Playwright: 모바일 430px, 320px/125%, PC 1440px 확인. 별도 세션의 신청·취소 갱신,
  새 신청 후 열린 편집기의 정상 공유, 두 인도자의 공유 충돌 안내/초안 보존,
  이름에 없는 회중 인도자의 배정 진입을 확인했다. 화면 오류 0개.
- definer 실행권한 감사 통과. 복사한 private 관리 함수는 anon/authenticated에게 닫혀 있다.
- 성능 재측정은 데모 10개 배정/33개 세션뿐이다. **운영 규모 성능 검증은 미완료다.**

## 운영 전환은 별도 작업

데모는 이미 엄격한 버전 저장 경로를 사용한다. 안전하지 않은 옛 저장을 다시 열거나,
새 RPC가 없을 때 직접 쓰기로 우회하는 폴백은 추가하지 않는다.
**운영에 1000/1010/1100을 그대로 순서대로 적용해서는 안 된다.** 운영 전환안은 별도 준비한다.
아래는 전환 순서안이다. 운영 사본 규모 성능·복구 검증과 사용자 승인은 실제 운영에서
1단계를 시작하기 전 선행 조건이며, 아래 5단계까지 미뤄도 된다는 뜻이 아니다.

1. 기존 앱과 공존할 수 있는 추가형 준비 마이그레이션을 만든다. 아직 옛 RPC를 회수하지 않는다.
2. 서버 기능을 확인해 새 경로를 쓰는 앱을 배포한다. 기능 플래그와 저장 경로의 의존성도 제거한다.
   여러 표를 순서대로 직접 지우는 옛 참가자 제외 경로는 이 단계에서 제거한다.
   새 원자적 RPC가 없으면 업데이트/서버 준비 안내로 중단하며 직접 쓰기로 돌아가지 않는다.
3. 실제 앱 버전/유효 세션과 구버전 쓰기 사용 여부를 확인한다. 이 공존 기간은 완전한 동시 저장
   보호가 된 것으로 안내하지 않는다.
4. 업데이트 보급 확인 후 직접 쓰기 차단·옛 RPC 회수를 별도 적용한다. 구버전에는 업데이트 안내가 필요하다.
   선행 조건은 2단계 앱의 배포·보급과 옛 참가자 제외 경로의 미사용 확인이다.
5. 운영 사본 규모의 RLS 성능과 전환/복구 시나리오를 다시 리뷰하고 사용자 승인 후 적용한다.

각 DB 전환 단계 전후에 실제 DB 카탈로그를 읽어 definer 목록·실행권한을 대조하고
결과를 보관한다. 단계별 승인 목록과 다르면 다음 단계로 진행하지 않는다. 운영용 목록은
현재 운영을 읽기 전용으로 확인해 만들고 데모 전용 `reset_demo_environment_tx`는 분리한다.
데모 감사 스크립트의 프로젝트 제한을 풀거나 데모 목록에서 임의 항목을 무시하는 방식으로
운영 검사를 대신하지 않는다. 이 운영용 도구·목록은 아직 준비/검증 전이다.
