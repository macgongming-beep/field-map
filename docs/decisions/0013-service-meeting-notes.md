# 봉사 모임 정리: 일정 삭제와 게시글 보존 분리

- 상태: 1차 구현, 데모 검증 중
- 결정일: 2026-10-01
- 작업 브랜치: codex/service-meeting-notes
- 운영 상태: 변경 없음. DB 마이그레이션은 데모에만 적용.

## 목적과 화면

전용 모음으로 묶은 봉사 모임 내용을 다시 읽는 기능이다. 공지, 댓글, 전체 알림을
복원하지 않는다. 모바일과 PC 홈에서 오늘 봉사 아래에 기간별 모임 정리 카드를
보여주고, 날짜별 목록과 한국어/중국어 게시글 화면으로 연결한다.
PC 일정 상세에서 관리자가 두 언어를 나란히 작성하고 미리보기한다.
한국어가 기본 원문이며 중국어가 없으면 한국어로 대체한다. 중국어 없이 저장할
때 확인한다. 제목과 본문의 언어를 각각 일관되게 대체한다.

홈 위치(오늘 봉사 아래/맨 위), 기간 중 대화 방법 제안 접힘은 회중 공통 설정이다.
글이 없는 기간에는 빈 카드를 노출하거나 기존 제안을 불필요하게 접지 않는다.
여러 모음의 기간이 겹치면 모음별로 구분하고 관리자가 글의 모음을 명시적으로 고른다.

## 승인된 보존 규칙

- 일정 삭제는 모임 정리 글 삭제가 아니다.
- 일정이 삭제돼도 글과 당시 날짜, 시간, 장소, 인도자 정보를 보존한다.
- 글 삭제는 관리자에게만 제공하는 별도 작업이다.
- 모음의 홈 표시 종료일까지 홈에 표시하고, 이후 홈에서만 숨긴다.
  홈 표시 종료일의 기본값은 모음 종료일 + 14일이다.
  게시글 데이터 자체를 만료 처리하거나 지우지 않는다.

## 데이터 설계

service_meeting_collections를 별도로 만든다. 특별봉사 통계용 special_periods와
FK, 생성 동작, 기간 판정 로직을 공유하지 않는다. 모음 생성·수정은 방문의
special_period_id, 특별봉사 배너, 지도, 캘린더 시즌 표시에 영향을 주지 않는다.

모음 필드: id, name_ko, name_zh, start_date, end_date, home_visible_until,
home_position, collapse_suggestions, created_at, updated_at, archived_at. 날짜는 서울 기준 달력 날짜이며 시작일과
표시 종료일은 포함한다. start_date <= end_date <= home_visible_until을 검증한다.
모음은 영구 삭제 대신 보관하며, 글이 연결된 모음을 CASCADE 삭제하지 않는다.

service_meeting_notes는 독립적인 id를 기본키로 둔다.
event_id는 nullable unique FK이며 calendar_events 삭제 시 SET NULL로 한다.
CASCADE로 게시글을 지우거나 event_id를 게시글 기본키로 사용하지 않는다.
같은 일정에는 한 게시글만 연결된다. 일정이 삭제된 여러 글은 각자의 id로 남는다.

필드 초안:

- id, event_id, collection_id (모음 FK, NOT NULL, ON DELETE RESTRICT)
- title_ko, title_zh, body_ko, body_zh
- excerpt_ko, excerpt_zh, reading_minutes_ko, reading_minutes_zh
- event_date_snapshot, event_time_snapshot, event_place_snapshot, event_leader_snapshot
- author_user_id, created_at, updated_at, archived_at

작성자는 사용자 ID로 기록하고 클라이언트가 임의 작성자 ID를 넣지 못하게 한다.
작성자 삭제는 게시글 삭제로 이어지지 않는다. 인도자 이름 스냅샷은 작성자와 별개인
역사적 표시 정보이며 권한 판단에 사용하지 않는다. 사용자 삭제·전출 시 이름과
게시글은 보존한다(결정 0001과 동일한 보존 원칙).
이름 정정 시에는 rename_user_name_references가 event_leader_snapshot도 갱신한다.
인도자는 쉼표 목록일 수 있으므로 기존 rename_in_name_list를 재사용하며 부분 문자열
치환은 금지한다. 일정 연결이 끊긴 글과 보관 글도 이름 정정 대상이다.
기존 인증·역할 검사와 알림 억제를 유지하고, 권한을 넓히지 않는다.

연결된 일정이 존재할 때는 서버가 일정 생성/수정 값을 스냅샷에 동기화한다.
일정 삭제 직전에도 서버가 최종 메타데이터를 확보한 뒤 FK 연결만 끊는다.
클라이언트에서 삭제 버튼을 누르기 전에 복사하는 방식에 의존하지 않는다.
모임 내용 저장 자체는 calendar_events를 수정하거나 알림 RPC를 호출하지 않는다.

period_*_snapshot은 저장하지 않는다. 기간과 이름은 보존되는 전용 모음이 소유한다.
모음을 보관하면 홈에서 숨기되 글과 일정 스냅샷은 유지한다.

관리자 글 삭제는 archived_at을 이용한 보관으로 구현한다. 복원 화면과 관리자
보관 목록의 고도화는 2차로 미룬다. 1차에서는 영구 삭제하지 않으며 보관 전에
현재 화면에서 다시 열 수 없다는 점을 알린다. 영구 삭제와 보관 데이터 정리는 범위 밖이다.

## 조회와 권한

- 로그인한 사용자만 읽고, 관리자/developer만 작성·수정·보관한다.
- 기존 세션 검증 및 역할 검사 패턴을 재사용한다. 화면 숨김만으로 권한을 막지 않는다.
- 메타 조회는 본문을 select하지 않는다. 발췌·읽기 시간은 서버가 저장 시 계산한다.
- fetchAll에 새 슬라이스를 추가하지 않는다.
- 홈 진입 시 표시 중인 모음 메타만 조회한다. 모음이 없으면 글 메타·본문은
  조회하지 않는다. 전용 모음을 발견하기 위한 경량 조회까지 0건이라고 주장하지 않는다.
- 홈 진입 시 메타를 조회하고 동일 진입의 렌더링은 요청을 공유한다.
  visibility/focus 타이머, 실시간 구독을 추가하지 않는다.
- 본문은 글을 열 때만 받고, 계정별 메모리 캐시를 사용한다. 로그아웃 시 비운다.
- 읽음은 사용자 ID와 글 ID/updated_at을 키로 단말에 저장한다. 본문 수신 성공 후
  표시하며, 다른 기기와의 읽음 동기화는 이번 범위에 넣지 않는다.
- 동시 관리자 수정은 updated_at 비교로 충돌을 알리고 조용히 덮어쓰지 않는다.

## 안전한 본문 표시

원문 텍스트를 저장한다. 문단, ## 소제목, - 목록, > 인용만 지원한다.
HTML 삽입과 임의 스크립트/링크 실행을 허용하지 않는다. 사용자 입력은 React
텍스트 노드로 렌더링한다. 줄바꿈을 유지하며 기존 글씨 크기 설정을 따른다.

## 기존 코드에서 확인한 사항

20260827_1000_series_update_tx.sql의 반복 일정 수정은 UPDATE이며 행 재생성이
아니다. calendar mutation의 단일/반복 삭제는 DELETE이다. 따라서 SET NULL과
서버 스냅샷 보존을 단일/반복 삭제 모두에 대해 시험해야 한다.
실제 구현 전 최신 main과 이후 추가된 일정 변경 경로를 다시 확인한다.

## 외부 리뷰 반영

special_periods는 visits.ts에서 방문 기록의 special_period_id를 결정하며,
DesktopStats.tsx의 regular 범위는 specialPeriodId가 없는 기록만 포함한다.
따라서 단순 게시 기간에 재사용하는 초기 설계는 철회한다.
최신 확인된 rename RPC 정의는 20260905_1700_restaurant_registration_details.sql이다.
일정 인도자의 쉼표 목록 이름 변경 규칙을 게시글 스냅샷에도 적용한다.

## 1차와 2차 범위

1차: 모음 관리, 관리자 글 작성·수정·보관, 홈 카드, 목록, 본문,
일정 삭제 후 보존, 동시 수정 충돌 알림, 안전한 렌더링과 권한 시험.
2차: 보관 글 복원 화면, 관리자 보관 목록의 검색·정렬 등 편의 기능.
보존·권한·충돌 검사·전송량 계약은 일정이 급해도 2차로 미루지 않는다.

## 구현 순서와 통과 조건

1. 스키마·권한·스냅샷 트리거와 역방향 SQL 작성. 데모에만 원자적 적용.
2. 메타/본문 분리 API, 입력 검증, 동시 편집 충돌 처리.
3. 모음 관리와 관리자 작성 화면, 홈 카드, 날짜별 목록, 게시글 화면 연결.
4. 기간 경계, 번역 대체, 읽음, 서식 안전성, 권한, 단일/반복 삭제 후 보존,
   연결 해제·보관 글의 이름 정정, 모음 생성이 특별봉사 통계에 영향 없음을 시험.
5. 변형 시험으로 권한 및 보존 가드를 제거했을 때 실패하는지 검증.
6. 데모에서 큰 글씨·아주 큰 글씨, 긴 제목/본문, 목록의 본문 미조회,
   저장 시 알림 미발송, 일정 삭제 후 글 접근을 확인.
7. 외부 리뷰와 사용자 확인 후 운영 배포 여부를 별도로 결정.

## 1차 구현 및 검증 기록

- 전용 feature API/Provider를 사용한다. useStore/fetchAll에는 추가하지 않았다.
- VITE_SERVICE_MEETING_NOTES_ENABLED=true인 배포에서만 활성화한다. 운영 기본값은 꺼짐.
- PC 일정 상세의 '모임 내용'에서 모음 관리 및 한·중 작성·미리보기를 연다.
  일정이 삭제된 글은 게시글 화면에서 관리자가 수정할 수 있다.
- 기존 rename RPC를 private로 이동하고 인증을 그대로 수행하는 public wrapper에서
  글 스냅샷을 추가 갱신한다. private 원본은 PUBLIC/anon/authenticated 실행권한을 회수했다.
- 데모 DB 적용 전 public/private 전체 custom dump를 확보했다.
  백업: backups/meeting-demo-2026-10-01T14-39-27.260Z/before.dump (비공개, 커밋 제외).
- 실제 PostgreSQL 트랜잭션 시험: 관리자 작성, 작성자 위조 방지, 동시 수정 충돌,
  일정 수정/삭제 후 보존, 연결 해제 및 보관 글 이름 정정, 사용자 삭제 후 보존,
  무인증 읽기/쓰기 차단, 일반 사용자 쓰기 차단 및 읽기 허용, 알림 미발송.
  시험 후 ROLLBACK으로 fixtures/DDL을 모두 되돌렸다.
- DB 변형 시험: SET NULL→CASCADE, 관리자 검사 제거, 충돌 검사 제거 각각 실패 확인.
  앱 변형 시험: 중국어 공백 대체 제거 시 해당 시험만 실패(나머지 4개 통과).
- 로컬 앱 + 실제 데모 DB에서 UI 작성/저장 및 모바일 한·중 읽기 확인.
  390×844, 아주 크게에서 dialog 390×844 및 가로 넘침 요소 0개 확인.
- 보관 복원 UI는 2차 범위이며, 운영 반영은 외부 리뷰/사용자 확인 전 진행하지 않는다.
