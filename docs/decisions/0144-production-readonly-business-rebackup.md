- 상태: 운영 읽기 전용 백업·파일 검증 완료. **운영 데이터 쓰기·복원·배포 없음**.
- 사용자 승인: `a90c250` 리뷰 승인 후 누락 3개 항목을 운영에서 다시 백업한다. `restore --write`는 실행하지 않는다.
- 선행: [0143 원자적 복원과 누락 범위 보완](0143-atomic-restore-rehearsal.md)

## 실행 범위

- 승인된 작업 브랜치 `a90c250`의 `backup.js`와 helper를 내용 변경 없이 별도 로컬 실행 폴더에 복사했다.
  코드 SHA-256을 원본과 대조했다. 기존 `backups/2026-11-20`을 덮어쓰지 않기 위한 실행 위치 분리다.
- 전체 백업을 다시 받아 새 업무 자료와 함께 보관했다. 백업 데이터는 새 폴더에 한 번 기록하고
  화상 접속 정보는 다른 위치로 복사하거나 출력하지 않았다. 비밀 환경 파일도 복사하지 않았다.
- API·DB 연결 대상이 같은 운영 프로젝트인지 확인했다. 암호는 환경변수로만 전달하고 명령줄에 넣지 않았다.
- 읽기 스냅샷과 전후 행 수 조회는 `SET TRANSACTION READ ONLY`로 실행했다. 전후 확인에서 `transaction_read_only=on`.
- REST 요청은 운영 호스트의 `/rest/v1/` GET/HEAD만 허용하는 실행 제한을 추가했다.
  private 병합 감사 자료는 기존 `pg_dump --data-only` 경로로 읽었다.
- 운영의 소유자 읽기 전용 백업 자체는 앞선 11/20 실행에도 있었다. 이번에는 누락 업무 표 3개를
  처음 포함한 새 백업이며, 운영에 집단 담당 마이그레이션을 적용한 작업이 아니다.
