- 날짜: 2026-11-17
- 상태: 운영 미적용. 후보 작성 및 로컬 후보/실제 데모 DB 재검증.

- 운영 기준: `f8ccae471b22fe3dcff1c694d56592b43e49ef78` (작업 시작/종료 전 origin 갱신으로 확인).
- 기능 원본: `21a725c2a91141d2d7b773296b0179774fe6e811..586cbdb8960273c2fb165c604d5ed553858d030a`.

## 이식 범위

전체 데모 브랜치를 병합하지 않았다. 최초 집단 기능 이전/이후의 차이 중 앱 코드, 관련 시험, 신규 SQL 18개, 준비/감사 도구만 main 위에 적용했다. 직접 충돌한 `calendarParticipants`, `useCalendarRealtime` 및 그 시험은 main의 기존 경량 조회를 유지하고 집단 신호/리비전 읽기만 연결했다.

main의 App 경로, Sentry/DSN, useNotifications, 의존성/잠금 파일은 변경하지 않았다. 기존 지연 조회·캐시 시험도 포함해 다시 실행했다. 데모 전용 참가자 신호 중복 제거, 관리자 기록 지연 조회, 댓글 제외 알림 피드는 이식하지 않았다. 데모 reset 함수/로그인 기능의 신규 변경, 실제 계정/일정, 키, 백업, 데모 실행 도구는 후보에 추가하지 않았다. SQL 단위 시험의 합성 fixture는 포함한다.

과거 결정 기록 0093~0107은 합의와 변경 이력을 보존하기 위해 포함했다. 그 안의 과거 테스트 숫자/배포 주소는 이 후보의 결과가 아니다.

## 후보 보강

- 준비 전에 기존 함수 21개의 정확한 서명, 필요한 칼럼, 참가자 정리/일정 알림/댓글 알림 트리거, 실시간 publication을 검사한다. 누락 시 신규 집단 스키마를 만들기 전에 중단한다.
- 읽기 전용 점검은 각 함수의 본문 해시·반환형·실행권한도 기록한다. **해시를 기록했다고 운영 본문이 검토된 것은 아니다.** 운영의 실제 정의·정책 비교는 다음 관문이다.
- 준비 묶음 식별자에 선행 검사 내용까지 포함한다. 이전 데모 manifest로 새 후보의 엄격 전환을 승인하지 않는다.
- 데모 모드를 끈 시험에서도 집단 신호는 관련 일정 명단만 갱신한다. 집단 UI가 꺼지고 리비전만 켜진 경우도 신청 종류/버전을 보존한다.
- CLAUDE.md에 관리 작업의 비공개 core 수정 규칙과 준비 DB 전 main 병합 금지를 추가했다.

## 재검증 환경

main의 잠금 파일로 `npm ci --ignore-scripts`를 실행했다. 후보 앱을 로컬 production build/preview로 실행하고 실제 데모 DB `itjlykpjmlcvanqpmkmc`에만 연결했다. 운영 DB에는 접속하지 않았다. 운영/데모 대표 주소의 앱 배포나 환경 설정도 바꾸지 않았다.

빌드에서 `VITE_DEMO_MODE=false`, `VITE_ASSIGNMENT_REVISION_ENABLED=true`, `VITE_GROUP_SERVICE_ENABLED=true`, `VITE_CART_APPLICATIONS_ENABLED=false`, `VITE_CHAT_DISABLED=true`를 명시했다. 캘린더 window/navigation reuse/cached screen/event refresh/application refresh, 건물 demand/calendar-zone demand, 사용자 private reads, recipient scope, territory realtime, recent sessions, meeting notes, restaurant browse, notification badge only를 명시적으로 켰다. 이는 주요 운영 조합의 검증이며 실제 운영 환경변수 전체를 복제했다는 뜻은 아니다. Sentry 전송/실기기 푸시 등록은 로컬 빌드에서 켜지 않았다.

데모 실행 도구는 원본 `586cbdb`에서 `scratch/candidate-harness`로 추출해 실행했다. 토큰이 든 fixture, 결과 원문, 스크린샷은 커밋하지 않는다. 두 화면 도구는 같은 날짜를 사용하므로 순차 실행한다. 최초 겹친 실행은 댓글 시험의 임시 일정 때문에 캘린더 2행 기대가 3행이 되어 실패했고, 댓글 정리 완료 뒤 전체 화면 검사를 다시 통과했다. 앱 결함으로 취급하거나 실패 기록을 숨기지 않는다.

- 후보에서 실제 아이폰 푸시를 다시 받은 것은 아니다. 이전 아이폰 성공은 0106의 이전 데모 근거로만 남긴다.
