# 건물 등록을 공통 RPC로 모은다

날짜: 2026-09-20

## 결정

- 승인된 로그인 사용자는 역할과 관계없이 건물을 직접 등록할 수 있다.
- PC와 모바일의 직접 등록은 `create_building_tx`를 사용한다.
- 주소 후보 판정은 식당 등록과 같은 `restaurant_address_key`,
  `same_building_location`(200m), advisory lock을 사용한다.
- 기존 건물 한 개가 확인되면 새 건물을 만들지 않고 그 ID를 반환한다.
- 여러 개면 자동 선택하지 않고 후보 ID를 반환한다.
- 이번 단계에서는 INSERT 차단 트리거와 주소 유니크 인덱스를 만들지 않는다.
- CSV 가져오기와 과거 백업 복원은 기존 계약을 유지한다.

## 이유

운영 중복은 등록 권한보다 여러 화면의 주소 판정이 서로 달라 생겼다. 권한을
줄이지 않고 생성 경로의 판정을 통일한다. INSERT 트리거나 유니크 인덱스는 병합 전
백업 복원과 CSV 가져오기를 막을 수 있으므로, 모든 앱 경로가 RPC로 옮겨진 뒤 직접
INSERT 정책을 닫을지 별도로 결정한다.

## 다음 단계

- CSV가 기존 주소를 만났을 때 세대와 기록을 어떻게 재사용할지 계약을 정한다.
- 신규 건물 등록 요청은 기존 `building_missing`과 섞지 않고 별도 유형으로 만든다.
- 직접 INSERT 우회 여부와 도로명 기준 중복 후보를 일정 기간 관측한다.
- 직접 INSERT 정책을 닫기 전 병합 전 백업으로 빈 DB 복원 리허설을 한다.
