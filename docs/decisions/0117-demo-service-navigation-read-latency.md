# 일정 상세·나의 봉사 조회 대기 축소

- 결정일: 2026-11-18
- 상태: 데모 검증 중. 운영 변경 금지.
- 기반: `bdd2ae5` 화면 수정이 반영된 데모.

## 범위와 계약

화면 구성·신청·배정 저장·알림·권한은 유지한다. 데이터 일부를 받지 않았는데 빈 목록이나
완료된 상태로 표시하지 않는다. 운영 DB·환경변수·main·운영 배포는 변경하지 않는다.

## 구현

1. 이미 홈을 정상적으로 읽은 인도자/관리자가 일정 상세·캘린더의 이름 자료를 처음 요청할
   때에는 건물·세대 이름만 추가로 읽는다. 홈과 캘린더는 모두 서버의 완전한 카드 집계를
   사용하므로 같은 카드 집계·지역·봉사 세션·방문 이력을 다시 받지 않는다.
2. 나의 봉사 등 더 풍부한 자료가 필요한 화면으로 이동할 때에는 카드 원본 조회와 건물
   조회를 겹쳐 실행한다. 카드 진행률 계산·공개는 반드시 건물 완료 뒤, 방문 이력 조회도
   건물 완료 뒤에 실행한다. 기존 복구 시점 확보·실패·재시도·편집기 준비 검사는 유지한다.
3. 카드 조회에서 서로 독립적인 지역 라벨과 카드 원본을 함께 요청한다. 변환은 둘 다
   완료된 뒤에 한다. 지역 실패 시 기존 기본값, 카드 실패 시 오류 처리는 그대로다.

나의 봉사에서는 식당 지도 이동, 정기방문 메모, 주소 대조에 건물 좌표와 상세 자료를
사용한다. 이번에는 전체 건물 자료 자체를 축소하지 않는다. 또한 일정과 배정의 읽기
순서를 유지해 새 버전에 옛 배정이 연결될 위험을 만들지 않는다.

## 측정 방법

- 데모 DB에만 연결한 동일 설정 로컬 정적 빌드 전후 비교. 브라우저마다 새 세션으로
  로그인하고 홈 → 상세 첫 진입/재진입 → 나의 봉사 첫 진입/재진입을 비교한다.
- Chromium 모바일 390px. 각 역할/화면 3회. 데이터 요청에 120ms를 추가한 지연 조건과
  추가 지연 없는 조건을 따로 기록한다. 운영·실제 휴대폰 측정은 아니다.
- 브라우저의 실제 클릭부터 준비된 신청 버튼 또는 오늘 배정 영역이 표시되고 다음
  화면 프레임까지의 시간을 잰다. 네트워크 안정화 대기는 측정 시간 밖에 둔다.
- 처음 만든 측정의 Playwright 요소 대기 시간에는 폴링 오차가 있어 비교에서 제외했다.
  `*-frame.json`만 시간 비교에 사용한다. 요청 수·바이트에는 같은 전환 중의 부가 요청도
  포함되며, WebSocket·압축 전송량이나 운영 전체 사용량을 뜻하지 않는다.
- 측정의 `admin` 로그인은 기존 데모 개발자 계정이다. 실제 admin 역할의 데이터 준비
  계약은 자동 시험으로 확인하고, 개발자 화면 수치를 admin 최적화 성과로 주장하지 않는다.

## 검증 기록

- 이름만 추가하는 전환에서 요청 범위·카드 집계 보존 및 전체 상세로 승격할 때 메모 복구.
- 느린 건물 응답 중 카드 조회는 시작하지만 합계와 방문 기록은 먼저 공개하지 않음.
- 지역 라벨이 느려도 카드 요청은 시작하되 둘 다 준비되기 전 완료 처리하지 않음.
- 기존 편집기 준비/실패 재시도, 늦은 응답 무시, 신청자·공유 배정·수정 X 복귀 시험 유지.
- 이름 조회 실패 후 재시도에서도 기존 카드 합계 보존 및 준비 전 화면 차단.
- 최적화를 되돌린 변이에서 새 시험 3개가 실패함을 확인하고 복원했다.
- 전체 2,546개 시험(262개 파일) 통과. 데모 빌드 통과.

## 전후 결과

각 3회의 중앙값(ms). 추가 지연은 각 데이터 요청 시작에 120ms를 적용한 것으로,
특정 이동통신망이나 실제 아이폰을 재현했다고 주장하지 않는다.

| 계정/화면 | 추가 지연 전→후 | 지연 없음 전→후 |
| --- | --- | --- |
| 인도자 상세 첫 진입 | 1,097 → 446 | 366 → 184 |
| 인도자 상세 재진입 | 231 → 232 | 112 → 114 |
| 인도자 나의 봉사 첫 진입 | 812 → 692 | 299 → 264 |
| 인도자 나의 봉사 재진입 | 47 → 48 | 47 → 46 |
| 일반 성원 상세 첫 진입 | 247 → 246 | 115 → 114 |
| 일반 성원 나의 봉사 첫 진입 | 615 → 599 | 263 → 263 |
| 데모 개발자 상세 첫 진입 | 232 → 248 | 별도 비교 안 함 |

- 인도자 상세는 지연 조건에서 11건/20,208B → 6건/11,308B. 직접 제거된 것은
  지역·카드·카드 집계·방문 이력·봉사 세션 재조회 5건이다.
- 인도자 나의 봉사 자료의 범위와 양은 줄이지 않았다. 지연 없는 측정은 전후 모두
  14건/46,937B였다. 지연 조건에서는 부가 요청을 포함해 14건/46,937B →
  16건/48,244B였다. 나의 봉사의 전체 트래픽까지 줄었다고 주장하지 않는다.
- 일반 성원은 기존 제한 조회 경로를 유지한다. 유의미한 속도 개선이 입증되지 않았다.
  반복 진입의 기존 재사용도 유지된다. 작은 표본이며 실제 운영 지연을 보장하지 않는다.
- 인도자 측정 계정의 오늘 개인 배정은 0건, 일반 성원은 공유된 배정 1건이다.
  해당 성원의 팀·카드·지도 버튼 표시를 확인했다. 대규모 배정 목록 렌더 성능 시험은 아니다.

  `scratch/speed-{before,after}-native-frame.json`; 재현 도구:
  `scratch/benchmark-service-navigation.mjs` (데모 전용 호스트 제한, 일정/신청 저장 없음).
