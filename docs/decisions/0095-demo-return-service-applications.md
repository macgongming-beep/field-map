# 봉사와 재방·연구 신청 분리, 기존 일정 화면 스타일 유지

- 상태: 데모 적용, 운영 미적용
- 결정일: 2026-11-16
- 관련: 0093/0094 집단봉사, 0022 참석 집계, 0074 신청자 갱신

## 사용자 결정

같은 일정에 `봉사 신청`과 `재방·연구 신청` 버튼을 나란히 둔다.
재방·연구도 전체 신청 인원에 포함하고 별도 명단으로 표시한다.
기본 팀 편성/구역배정에서는 제외한다. 별도 일정이나 방문 대상자 입력은 만들지 않는다.
일정 추가는 기존 앱의 모바일 하단 시트, 디자인 토큰, 간격, 선택 표시를 사용한다.
PC에서는 같은 폼을 가운데 대화창으로 유지한다. 기존 상세 화면에 신청 UI만 연결한다.

## 저장과 갱신

- 기존 `event_participants`의 role/이름/일정 ID 계약을 유지한다.
  `service_activity`는 `service` 또는 `return_visit`, 기존 행은 `service`다.
- 두 종류 모두 `applicants`에 남으며 `returnVisitApplicants`는 그 부분집합이다.
  일반 신청자 명단과 팀 후보는 부분집합을 제외하고, 재방·연구 명단은 따로 표시한다.
- 신규 신청 RPC는 승인/활성 세션의 본인만 신청한다. 신청 마감, 전시대 중복,
  잘못된 종류를 서버에서 거부한다. 같은 종류 재전송은 멱등이며 취소로 뒤집히지 않는다.
- 종류 변경은 취소 후 재신청이다. 이미 배정이 있는 신청을 조용히 재방으로 바꾸지 않는다.
  기존 팀 제거 RPC 및 삭제 정리 트리거를 그대로 사용한다.
- 기존 `event_id,user_name` 유일성 유지. 직접 UPDATE로 종류를 바꾸는 것도 차단한다.
- 참가자와 배정 쓰기는 일정 행 잠금으로 직렬화한다. 재방·연구 참가자의 카드/카드 목록/
  비공식/식당 배정 쓰기는 트리거에서 거부해 오래 열린 화면의 배정도 전체 롤백한다.
- 전체 일정 읽기와 참가자만 갱신하는 경로 모두 종류를 보존한다. 새 폴링/전체 이력 조회 없음.
  종류는 같은 참가자 행에서 바뀌지 않으므로 기존 INSERT/DELETE 수신 확인 계약도 유지한다.

## 집계 의미

0022의 신청자 기반 집계는 그대로다. 재방·연구 신청자도 일정별 전체 인원에 한 번만 포함한다.
별도의 실제 수행/완료 상태나 재방문 기록, 성경 연구 기록을 자동 생성하지 않는다.
이번 변경은 실제 완료 횟수나 방문 대상자를 추정하는 기능이 아니다.

## 데모 경계와 복구

앱 기능/새 열의 명시적 조회는 기존 `groupServiceEnabled()`의 정확한 데모 주소와 플래그로 제한한다.
운영 앱/DB/main 및 실제 일정은 변경하지 않는다. 기존 시험 일정과 사용자가 만든 데모 일정 보존.
`20261116_1100_service_application_activity.sql` 적용 전에 데모 public/private 백업을 만들고,
`psql --single-transaction`으로 적용했다. definer 함수 실행 권한을 명시적으로 회수/부여했다.

복구는 이전 앱 배포 후 `supabase/tools/rollbacks/_ROLLBACK_20261116_service_application_activity.sql`을
단일 트랜잭션으로 실행한다. 신청은 남지만 종류 정보는 사라진다. 0093까지 전부 되돌릴 때는
1100 복구를 먼저 실행한다. 백업과 적용별 rollback은 `backups/group-service-demo-*`에 로컬 보관한다.

## 검증

- 실제 SQL PGlite: 종류 저장, 중복 재전송, 마감/권한/전시대 충돌, 종류 변경 차단,
  배정 4종의 삽입/수정 차단, 반대 순서의 늦은 재방 신청 거부, 롤백 시 신청 보존.
- 배정 차단 조건 제거 변형은 관련 테스트 하나만 실패한다.
- React/갱신: 두 버튼의 정확한 종류 전달, 취소, 중복 클릭 방지, 총 인원과 배정 후보 분리,
  참가자 전용 갱신과 실패 처리, 중국어.
- 실제 데모 API 25개 검사 통과. 재방 신청/재전송/거부/취소 후 봉사 재신청,
  실제 팀 배정 RPC의 재방 거부 포함. 임시 자료는 정리했다.
- Playwright: 모바일 430/320px와 125% 확대, PC 1440px. 종류별 실제 신청/취소,
  관리자 별도 명단, 팀 후보 제외, 중국어 접속 정보와 버튼, 가변 시간대와 함께 수정 확인.
- 전체 249개 파일/2,497개 테스트, 빌드와 lint 통과.
