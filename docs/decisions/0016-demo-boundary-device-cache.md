# 데모 전체 조회의 구역선 기기 보관

- 상태: 승인 (데모 전용, 운영 미적용)
- 결정일: 2026-10-06

## 배경과 범위

메모리 구역선 캐시는 앱 재실행 때 사라진다. 전체 조회 모드의 첫 좌표 다운로드를
다음 실행에도 활용하되, 기기에 남은 좌표를 권한 확인 없이 지도에 표시하지 않는다.
첫 단계는 VITE_DEMO_MODE=true인 전체 store 경로에만 적용한다. 관리자/인도자 등
전체 조회 경로가 대상이며 봉사자 recipient 전용 reader의 범위 좌표 조회는 변경하지 않는다.
전체 조회가 필요한 봉사자 화면도 같은 reader를 사용하면 대상이다.

## 계약

- IndexedDB에는 card_id, points, updated_at 및 저장 시각만 보관한다. 이름/주소/
  방문기록은 보관하지 않는다. 키는 서버 URL과 로그인 토큰의 SHA-256 조합이다.
  토큰 원문은 캐시 키/값에 저장하지 않는다. 이는 암호화가 아니라 캐시 분리다.
- 같은 로그인 세션의 재실행에서만 재사용한다. 캐시 재사용 가능 기간은 7일이다.
  기간 만료는 읽기 거부이며, 자동 물리 삭제 타이머를 의미하지 않는다.
- 서버의 최신 ID/updated_at 목록을 먼저 읽는다. 삭제된 좌표는 제거하고 새 좌표와
  변경 좌표만 읽는다. 버전 NULL은 반드시 재조회한다. 서버 확인 없이 오프라인 캐시를
  표시하지 않는다. 최신 목록/변경 조회가 실패하면 전체 조회하고, 전체도 실패하면 오류다.
- 첫 실행/캐시 손상/저장소 차단/용량 부족은 기존 전체 조회로 동작한다.
  IndexedDB 열기 제한 시간은 1.5초다. 수동 전체 새로고침은 좌표 전체를 다시 받는다.
- 로그아웃 시 세션 저장소 정리 함수에서 전체 좌표 캐시를 비운다. 동기적인 epoch
  변경과 세션 확인으로 늦은 쓰기가 로그아웃 뒤 캐시를 다시 채우지 않게 한다.
  저장소 자체가 접근 불가한 경우 삭제 성공을 보장하지 못하지만 캐시 사용도 하지 않는다.
- 회중/계정 전환은 서로 다른 서버/세션 키로 분리된다. 읽기 진행 중 세션 변경은 결과를
  버린다. 기존 서버 권한, 구역선 저장 경로, DB 스키마는 변경하지 않는다.

## 검증

- IndexedDB API 시험은 fake-indexeddb 개발 의존성으로 수행한다. 앱 런타임에 포함하지 않는다.
- 재실행, 변경/삭제, 수동 전체 갱신, 운영 게이트, 세션/서버 분리, 로그아웃 정리,
  만료/잘못된 좌표/저장소 장애와 계정 변경을 시험했다.
- 재실행 최적화와 로그아웃 정리를 제거한 변형에서 관련 3개 시험만 실패, 원복 후 13개
  집중 시험 통과. 전체 1243개/175파일 통과, lint/build 통과.
- 데모 API 실측(06:55 UTC), 실제 useStore + IndexedDB 에뮬레이션:
  첫 전체 실행 21요청/9921B, 캐시 있는 전체 재실행 21요청/9752B.
  구역선 응답만 317B에서 148B로 감소. 두 실행 자료 필드 일치 확인.
  복귀 21요청/6396B, 같은 건물 부분 갱신 3요청/696B는 두 경우 동일했다.
- 이 수치는 작은 데모의 압축 HTTPS 본문이다. 브라우저 Transferred나 운영 청구량이
  아니며 지도/알림/채팅/정적 파일을 포함하지 않는다. 요청 수는 줄지 않았다.
  운영의 구역선 크기를 섞어 월 절감량이나 5GB 충족을 단정하지 않는다.
