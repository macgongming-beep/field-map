## 범위

집단/회중 구분, 대상 집단 코드, 두 타임 묶음 표시, 날짜별 주 인도자,
화상 모임 접속 정보, 시간 중복 신청 안내를 기존 캘린더와 상세 일정에 연결한다.
운영 앱/DB/main 및 실제 11~12월 일정은 변경하지 않는다.
자동 배정, 균형 추천, 실제 수행 통계, 불참 이력, 관리자 엑셀 붙여넣기 화면은 후속이다.

## 불변 계약

- 동탄/신갈/처인/동백은 `dongtan/singal/cheoin/dongbaek` 코드로 저장한다.
  기존 사용자 중국어 집단명은 표시 우선순위 연결에만 매핑한다. 소속 없거나 다른 집단이어도 신청 가능하다.
- 같은 날짜와 대상 집단을 화면에서 묶지만 신청/취소/팀/구역배정은 `event_id`별로 독립이다.
- 14:30~16:30과 17:00~19:00 반복 일정은 서로 다른 `series_id`를 가진다.
  반복 생성은 인도자 미지정으로 하고 이후 날짜별로 지정한다. 기존 주 인도자 배정을 반복 수정으로 덮어쓰지 않는다.
- 주 인도자는 사용자 ID이며, 활성/승인/leader·admin·developer 역할과 `leader_name` 포함을 서버에서 검사한다.
  기존 일정에는 주 인도자를 추정해 넣지 않는다. 주 인도자 교체는 이전 주 인도자를 제거하고 다른 공동 인도자는 보존한다.
- 두 타임 함께 수정은 선택한 정확한 ID와 열 당시 `edit_version`을 전송한다. 전체 권한/버전 검사 후 하나의 트랜잭션으로 저장한다.
  `updated_at` 대신 모든 행 수정에 증가하는 단조 버전을 사용한다. 배정 수정도 오래된 일정 편집창을 무효화한다.
- 시간 겹침은 서버에서 본인의 신청을 조회한다. 안내 후 추가 신청을 허용하고 기존 신청을 취소하지 않는다.
  시각이 비었거나 해석 불가하면 판단 불가 안내를 한다. 종료와 시작이 맞닿은 일정은 겹치지 않는다.
- 접속 정보는 `event_meeting_access`에만 저장한다. 직접 SELECT/쓰기 권한이 없고 Realtime publication에 넣지 않는다.
  승인된 활성 로그인 사용자는 신청 여부와 무관하게 조회 RPC로 읽는다. 공개 일정·알림·푸시에 링크/비밀번호를 넣지 않는다.
- 저장 결과 불명 시 같은 요청 ID로 재시도한다. 별칭 추정, 비활성 계정 복구, 권한 없는 직접 쓰기 fallback은 없다.
- 알림은 변경된 미래 일정의 기존/새 인도자, 일반/전시대 신청자 합집합에 한 번씩 발송한다.
  종료 시각과 접속 정보 변경을 포함하며 메모만 바뀌면 발송하지 않는다. 기존 전시대 반복 설정도 보존한다.

## 구현과 비용

기존 구독과 월별 캘린더 조회를 이용하며 새 폴링/전체 이력 조회는 없다.
추가 읽기는 신청 전 중복 확인과 화상 일정 상세/편집 진입 시 접속 정보 조회다.
홈/PC/모바일은 같은 묶음 함수를 사용한다. 기존 메타데이터 없는 일정 편집은 기존 편집기를 유지한다.
새 일정 편집기는 집단/회중 봉사 데모에 집중한다. 신규 전시대 일정 작성 UI 확장은 이번 범위가 아니다.

기능은 `VITE_DEMO_MODE=true`와 정확한 데모 Supabase 주소에서만 켜진다.
`VITE_GROUP_SERVICE_ENABLED=false`로 UI를 끌 수 있다. 이는 DB 롤백을 대신하지 않는다.

## 가져오기

`scripts/importServiceScheduleDemo.mjs`는 엑셀 CSV 내보내기를 읽는 **데모 전용 CLI**다.
기본은 미리보기이며 날짜/구분/집단/인도자/시작/종료 열을 검사한다.
정확한 이름·역할·활성·승인·중복을 검사하고 확인 해시를 넘겼을 때만 한 번에 저장한다.
집단 행에서 시작/종료가 모두 비어 있으면 두 타임으로 확장한다. 부분 입력은 오류다.
실제 엑셀 파일은 가져오지 않았다. 기존 반복 일정 삭제도 하지 않았다.

## 검증

- PGlite에서 실제 마이그레이션 실행: 원자성, 버전 충돌, 권한, 주 인도자, 별도 series,
  기존 전시대 반복 수정/알림, 비공개 읽기, 중복 시간 경계, 재시도/중복 등록.
- React/API: 코드 기반 그룹핑, 타임별 진입, 날짜별 버전 고정, 실패 후 재시도,
  주 인도자 교체, 미지정 반복 생성, 중국어, 계정/일정 전환 시 비밀정보 격리, 중복 확인/취소.
- 버전 검사 제거와 세션 검사 제거 변형으로 관련 회귀 테스트가 실패함을 확인한다.
- 실제 데모 API: 생성/재시도, 익명 조회 거부, 소속 없는 비신청자의 접속 정보 조회,
  타임별 신청/팀/카드 공유, 한 타임 취소 시 다른 타임 보존, 인도자 교체/알림 중복 방지,
  새 인도자 배정 수정 성공과 이전 인도자 거부. 일회용 테스트 자료는 정리한다.
- Playwright: 모바일 430px, 320px·125% 확대, PC 1440px. 묶음/상세/접속 정보/함께 저장 확인.

실행 결과: 전체 247개 파일/2,483개 테스트 통과, 빌드/린트 통과.
두 변형 검사는 각각 해당 테스트 1개만 실패했다. 실제 API 검증 16개 통과.
소속 없는 봉사자 계정의 실제 신청/취소와 중국어 화상 정보 표시도 브라우저에서 확인했다.

사용자 확인용으로 11/25 연합 한 곳, 11/28 단일 집단 한 곳에 두 타임씩 시험 일정을 유지한다.
화상 링크는 `example.com` 시험 주소다. 실제 Zoom 정보나 실제 담당자를 넣지 않았다.

## 배포와 복구

데모 Supabase: `itjlykpjmlcvanqpmkmc`.
데모 Vercel: `chinese-territory-app-demo` (`prj_txJm1ruq4OiRnZi3cjz9IXLkGKPG`).
운영 ref/다른 프로젝트는 도구가 거부한다. `--linked`는 사용하지 않는다.
이번 CLI 환경의 Vercel env pull에서는 Supabase 두 값이 비어 있어, 검증된 데모 env의
공개 URL/anon 키를 이 배포의 `--build-env`로 명시했다. 프로젝트 공통 변수는 수정하지 않았다.

적용 SQL: `20261116_1000`, `1010`, `1020`, `1030` 순서.
적용마다 public/private custom-format 백업 후 `psql --single-transaction`으로 적용했다.
1010은 실제 API에서 지연된 SQLSTATE 40001 충돌을 명시적 HTTP 409(PT409)로 바꾼다.
백업은 `backups/group-service-demo-*`에 로컬 보관하고 배포/커밋에서 제외한다.

전체 복구는 이전 앱 배포 후 `_ROLLBACK_20261116_group_service.sql`을 단일 트랜잭션으로 실행한다.
새 메타데이터/화상 정보/가져오기 재시도 기록은 제거되지만 일정과 신청은 유지된다.
부분 적용 도구가 만든 rollback은 해당 추가 마이그레이션만 되돌린다.

운영 승격 전에는 Claude 리뷰, 실제 사용자 역할/이름 대조, 실제 시간표 미리보기,
실제 인도자의 카드 목록과 배정 화면 확인, 운영 백업 및 별도 승인이 필요하다.
