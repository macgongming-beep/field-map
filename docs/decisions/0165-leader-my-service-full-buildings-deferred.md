# 인도자 나의 봉사 건물 전체 조회: 분리 보류

- 상태: 보류 (코드 변경 없음)
- 날짜: 2026-11-23
- 범위: 모바일 인도자·관리자 `/territory`의 `full` 건물 조회 (`buildingDemandForRoute`)

## 질문

인도자 나의 봉사(`/territory`)만 건물을 메모까지 받는 `full` 모드로 읽는다.
지도(`/map`)처럼 메모 없는 `map` 요약으로 읽고 본문은 상세 진입 때 받으면 첫 진입이 가벼워지는가?

## 소비자 표 (코드로 확인)

`MobileTerritory`가 `/territory`에서 건물 자료를 쓰는 곳:

| 소비자 | 쓰는 칸 | `map` 요약에 있나 |
|---|---|---|
| 카드별 건물 수 (`cardBuildingTypeCounts`) | `cardId`, 종류(usage) | 있음 |
| 정기방문 목록 (`myRegularVisits`) | 건물명·종류, 세대 번호, `regular_visits` | 있음 |
| 정기방문 관리 화면 (`MobileTerritory.tsx:733`) | **세대 메모** | **없음** |
| 오늘 배정의 식당 행 (`:821`) | 건물명 | 있음 |
| 재방문 연결 (`findReturnVisitBuilding`) | 건물·세대 ID, 주소 | 있음 |
| 재방문 추가 주소 맞춤 (`matchingBuildingsForAddress`) | 주소·이름 | 있음 |
| 지도 중심 (`:670`) | 좌표 | 있음 |
| 식당 봉사 시트 (`RestaurantServiceSheet`) | 식당 표시, 이름. 메모는 방문 기록 쪽 | 있음 |

- `/territory`에는 `FullBuildingGate`·`BuildingDetailGate` 소비자가 없다. 저장 경로는 재방문·식당 요청 자체 메모만 쓰고, 건물·세대 메모를 다시 쓰지 않는다.
- 데스크톱 `/territory`(`DesktopMyService`)는 `map` 모드 대상이 아니다(모바일 전용).

## 측정 (데모, 읽기 전용, 직접 실행)

같은 데모 자료로 두 열 목록의 응답(압축 전)을 비교했다. 도구: `scratch/perf-0164-0166/demo-building-cols.mjs`.

| | 건물 | 세대 | 응답 |
|---|---|---|---|
| `full` | 45 | 74 | 32,115 B |
| `map` | 45 | 74 | 28,239 B |
| 차이 | | | 3,876 B (12.1%) |

차이는 전부 메모 글자다(세대 1,440 B, 건물 840 B, 출입 기록 64 B, 나머지는 JSON 키).
운영 메모 크기는 재지 못했다. 운영 읽기 전용 집계가 권한 판단 단계에서 거부됐다.

## 보류 이유

1. **절감이 작다.** 인도자의 세션당 첫 진입 한 번, 데모 기준 응답의 12%다. 대상은 인도자뿐이다.
2. **뒤로 옮긴 비용이 더 클 수 있다 (코드로 판단).**
   - 지금은 나의 봉사 → 지도로 가면 `full` 자료를 그대로 써서, 세대 상세가 추가 요청 없이 바로 열린다.
   - `map` 요약으로 바꾸면 지도에서 건물을 열 때마다 `ensureBuildingDetail` 요청 1건과 대기가 생긴다.
   - 정기방문 관리 화면도 메모를 보이려면 건물별 상세 요청이 필요하다. 지금 API는 건물 하나씩이라 요청이 건물 수만큼 늘어난다.
3. 정상 전체 사용 흐름(나의 봉사 → 지도 → 세대 상세 여러 개)의 사용량이 오히려 늘 가능성이 높다.

## 다시 볼 조건

- 운영 집계에서 `buildings.memo`·`units.memo` 합이 건물 응답의 30% 이상으로 크게 나올 때.
- 여러 건물 상세를 한 요청으로 받는 API(`ensureBuildingDetails(ids)`)가 생겨, 정기방문 화면이 1건으로 끝날 때.
- 그때도 지도 세대 상세의 대기 추가는 따로 재야 한다.

운영 집계에 쓸 읽기 전용 SQL(숫자만 출력, 실행하지 않음): `scratch/perf-0164-0166/prod-restaurant.sql`의 `buildings`/`units` 줄.
