# 시작 로고와 화면 이동 대기 분리

- 상태: 데모 검증, 운영 미적용
- 결정일: 2026-11-18
- 관련: 0124, 0125

## 배경

0124의 정적인 로고를 공통 AppLoading에 넣어 최초 실행뿐 아니라 화면 이동,
로그인 후 자료 대기에도 로고가 반복됐다. 사용자는 아이폰의 짧은 깜빡임도 보고했다.
공통 로고 재등장은 코드로 확인했지만, 실제 아이폰 OS/PWA 시작 화면의 깜빡임까지
동일 원인이라고 확정하지 않는다.

## 결정과 구현

- App이 최초 화면 준비 여부를 보관한다. 사용자별로 다시 생성되는 AppSession보다
  위에 두므로 로그인, 로그아웃, 사용자/권한/조회 범위 변경으로 로고가 다시 켜지지 않는다.
- 로그인 또는 앱 화면의 Suspense 안에서 AppScreenReady가 실제로 커밋됐을 때만
  초기 표시를 끝낸다. 자료만 준비되고 화면 코드가 아직 준비되지 않은 사이에 끄지 않는다.
- AppLoading은 기본적으로 로고 없는 안내다. 최초 단계에서만 startup을 명시한다.
  자동 로그인 확인, 첫 자료 조회, 화면 코드 대기는 같은 초기 로고로 이어진다.
- 부트 HTML 배경도 앱 배경과 같게 지정한다. 임의 지연, 최소 표시 시간, 페이드,
  별도 이미지/글꼴 요청, 데이터 조회 변경은 없다.
- 12초 안내, 수동 다시 불러오기, 실패 문구, 접근성 이름은 유지한다.
- 새로고침으로 문서 자체를 다시 열면 처음부터 시작한다. 앱 안에서 이동하는 것과 구분한다.

## 검증

- 전체 267파일 / 2,612시험 통과, lint 및 데모 설정 build 통과.
- 최초 인증/자료 대기에는 startup이 유지되고, 홈을 보인 뒤 자료 대기와 사용자 교체에서
  재등장하지 않는다. 로그인 화면을 먼저 보인 경우도 검사한다.
- 실제 lazy/Suspense를 보류해 첫 화면 커밋 전 준비 표시가 실행되지 않는지 검사한다.
- 변이: AppSession에 startup=true를 항상 전달하면 새 통합 시험 2개가 실패한다.
- Chromium/WebKit 각각 390px, 320px(150% 확대/동작 줄이기), 1365px 통과.
  부트/React 로고 좌표 일치, 회전 없음, 추가 이미지/글꼴 요청 없음, 12초 복구,
  로그인 뒤 오류 안내에 로고 없음, 로그인 뒤 로고 삽입 0회를 검사했다.
- 자동 로그인 재실행의 프레임 샘플에서 첫 로고 이후 화면 메뉴가 나타날 때까지
  로고도 화면도 없는 샘플은 0개였다. 이는 브라우저 DOM/렌더 프레임 검사이지
  실제 휴대폰 OS 시작 화면의 촬영 결과가 아니다.
- 원본: scratch/startup-startup-once-{chromium,webkit}-ui.json 및 해당 스크린샷.
- 도구 첫 실행은 홈에 없는 선택자를 기다려 중단했다. 실제 홈 메뉴 선택자로 고쳐
  재실행했다. 앱 장애로 해석하거나 첫 실행을 성공으로 계산하지 않는다.
- 실제 아이폰 PWA 재확인, 실제 안드로이드 기기는 미검증이다.

## 조회 비교

이전 정적 로고 데모 빌드와 새 빌드를 REST 120ms 지연, 역할별 1회로 비교했다.
성능 우월성 통계가 아니라 불필요한 재조회 유무 확인이다.

| 역할 | 앱 재실행 요청 전/후 | 캘린더 전/후 | 홈 복귀 전/후 | 홈 준비 전/후 |
| --- | --- | --- | --- | --- |
| 봉사자 | 39 / 39 | 17 / 17 | 3 / 3 | 2297 / 2361ms |
| 인도자 | 29 / 29 | 6 / 6 | 3 / 3 | 1160 / 1178ms |
| 관리자(실제 admin) | 29 / 29 | 6 / 6 | 3 / 3 | 1167 / 1156ms |

9구간 모두 요청 대상 목록도 같다. 응답 원문은 봉사자 앱 재실행만 41272→41273B:
territory_sync_clock의 시각 응답 33→34B 차이이며 추가 조회가 아니다.
나머지 8구간은 응답 바이트도 같다. 시간을 강제로 늘리는 코드는 없지만
실측 시간이 정확히 동일하다고 주장하지 않는다. 정적 JS/HTML 자체의 변경 크기는 별도다.
원본: scratch/speed-startup-once-{before,after}.json.

## 배포 범위

기능 브랜치와 데모만 대상. main, 운영 배포/환경변수/DB는 변경하지 않는다.
데모 로그인/자동 세션 처리 외 일정·신청·배정 쓰기는 검증 도구에서 차단한다.
