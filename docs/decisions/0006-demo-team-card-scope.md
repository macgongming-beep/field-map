# 팀별 카드 봉사 형태: 실제 데모 연결

- 상태: 데모 검증 중, 운영 미적용
- 결정일: 2026-09-30
- 범위: 카드 봉사 선택/공유/재진입/나의 봉사 지도. 비공식·식당 저장 및 통계 개편은 후속.

기존 카드 구성 조회와 달리 주택·상가 선택은 팀 배정 속성이다. UI는 세 개의
선택 버튼만 표시하고 팀을 바꾸면 그 팀의 값을 표시한다. 대상 없는 배정 카드는
확인 후 제외하며 취소하면 그대로 남긴다. 혼합 카드는 세대 단위로 판단한다.

이번 작은 연결 단계에서는 새 팀 테이블 대신 calendar_events.assignment_team_scopes에
불투명한 team_key별 값을 저장한다. 개인 행마다 scope를 독립 저장하지 않는다.
새 공유 RPC는 같은 팀의 카드/범위 일치를 검사하고 기존 카드 RPC 구현과 동일 트랜잭션으로
메타데이터를 저장한다. 기존 키는 복원 시 재생성하지 않는다. 빈 팀의 이름/색/순서와
비공식의 팀 모델 영속은 여전히 후속이며 전체 팀 모델 완성이라고 부르지 않는다.

구버전 RPC는 좁은 배정이 있는 일정을 수정하지 못한다. 해당 일정의 직접 카드 표 쓰기도
restrictive INSERT/UPDATE/DELETE 정책으로 차단한다. SELECT는 변경하지 않는다.
새 클라이언트는 새 RPC가 없거나 세션이 없으면 실패하며 직접 저장으로 우회하지 않는다.
처음 공유시각이 null인 초안도 동시 공유 충돌을 검출한다.

나의 봉사 지도는 URL에 scope를 믿고 쓰지 않고 일정+현재 사용자 배정으로 다시 계산한다.
없는 배정은 빈 지도로 유지한다. 범위는 화면 문맥이지 접근 권한/RLS 격리가 아니다.
기존 개별 카드 진행률은 좁은 배정 요약에서 숨긴다. 전체 카드의 완료 상태는 수정하지 않는다.
실제 방문 이력의 용도 스냅샷과 다중 카드 세션 연결은 이번 UI 연결만으로 완료되지 않는다.
따라서 봉사 형태별 실적/시간 통계는 아직 제공하지 않는다.

백업은 기존 calendar_events JSON/전체 pg_dump에 새 메타데이터가 포함된다.
복원은 trusted service role/DB 연결을 쓰며 restrictive 정책을 우회한다.
운영 전에는 공유 알림의 범위 변경 표현, 팀 메타데이터/비공식/식당 원자성,
다중 카드 방문 세션과 실적 스냅샷 및 구버전 수신자 화면을 추가 검토해야 한다.

데모 환경 플래그에서만 실제 봉사 형태 UI/신규 공유를 사용한다. 운영 배포는 별도 승인.
