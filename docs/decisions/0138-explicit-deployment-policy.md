# 자동 중복 배포 차단과 명시적 배포

- 결정일: 2026-11-19
- 상태: 프로젝트 설정 적용, 앱 신규 배포 없음
- 범위: 배포 시작 조건과 배포 도구. 앱 코드, DB, 환경변수, 현재 별칭은 변경하지 않는다.

## 배경

운영/데모 프로젝트가 같은 GitHub 저장소의 모든 브랜치를 자동 배포하고 있었다.
작업 브랜치 push, main push, 별도 CLI 데모 업로드가 겹쳤다. 최근 24시간 조사에서
운영 5건, 데모 30건, 미리보기 92건(취소 1건 포함)이 확인됐다.
이는 API의 배포 기록 집계이며 Vercel 제한의 내부 집계와 같다고 단정하지 않는다.

Ignored Build Step은 취소된 빌드도 배포 제한에 포함될 수 있어 이번 해결책으로 쓰지 않는다.
공식 설명: https://vercel.com/docs/monorepos#skipping-unaffected-projects

## 결정

1. 두 프로젝트의 `gitProviderOptions.createDeployments`를 `disabled`로 설정한다.
2. `vercel.json`에도 `git.deploymentEnabled: false`를 기록한다. Git 연결 자체는 유지한다.
3. 모든 브랜치와 main push는 코드 보관/CI만 수행한다. 문서 변경은 앱을 배포하지 않는다.
4. 앱 변경은 로컬 검증을 끝낸 묶음만 데모에 올린다. 데모 업로드는
   `npm run deploy:demo -- --artifact <verified-prebuilt-directory> --publish`만 사용한다.
5. 운영은 사용자 승인 후 검증한 main 버전과 운영 설정으로 별도 배포한다.
   자동 배포를 재활성화하거나 미리보기 결과물을 운영으로 바로 승격하지 않는다.

`deployDemo.mjs`는 빌드하지 않는다. 기존 빌드 환경과 결과물을 그대로 사용하고, 데모
프로젝트/팀, prebuilt 구조, 원격 자동 배포 OFF를 확인한다. 기본 모드는 읽기 전용이다.
출력 파일의 경로와 내용 해시가 이미 서비스 중인 배포와 같으면 업로드하지 않는다.
첫 도구 배포 전의 결과물은 해시 메타정보가 없으므로 중복 여부를 자동 확정할 수 없다.
다시 빌드한 결과물의 시각 등 내용이 달라지면 다른 결과물로 본다.
따라서 문서만 수정했을 때는 빌드/업로드 명령을 실행하지 않는 규칙도 유지한다.
동시 로컬 업로드는 Git 공통 폴더의 잠금으로 막는다. 다른 머신과의 분산 잠금은 아니다.

## 현재 버전 보존

설정 변경 전 백업: `backups/deployment-policy-20261119/before.json` (Git 제외).
설정 변경 직후 다시 읽어 아래 배포 ID가 같음을 확인했다.

| 대상 | 유지된 배포 |
| --- | --- |
| 운영 | `dpl_4aj7JX9mms1cfoDvaGBaU3DQV7TL` (`1c3a18b`) |
| 데모 | `dpl_9wfuijbUzpt3XcYa744VXMSwN33r` |

즐겨찾기 복구 등 `0137`의 운영 반영 대기는 이번 설정 변경으로 배포되지 않는다.
이번 작업을 기록한 커밋도 운영 앱에 반영하지 않는다.

## 검증

- 독립 Node 시험: 자동 배포 OFF, 기본 검사 모드, 운영 프로젝트 거부, 자동 배포 재활성화 거부,
  같은 결과물 중복 제외, 출력 밖 문서 변경 무시, 명시적 단일 업로드, 잘못된 인수 거부.
- GitHub CI에 배포 없이 위 시험만 추가한다. 비밀값/배포 권한을 추가하지 않는다.
- 현재 프로젝트 설정 재조회와 운영/데모 별칭 ID 유지 검사를 수행한다.
- 실제 신규 배포는 만들지 않는다. 업로드 시험은 대체 호출로 명령을 검증한다.

실행 결과: 독립 시험 8개 통과, lint/TypeScript/앱 빌드 통과. 별도 임시 복사본에서
운영 프로젝트 검사 제거, 동일 결과물 차단 제거, 명시적 publish 조건 제거를 각각 적용했을 때
시험이 실패했다. 기존 `scratch/nov18-demo-release` 결과물은 검사 모드로 확인했고 업로드하지 않았다.
빌드에는 기존 큰 청크 경고와 inlineDynamicImports 폐기 예정 경고가 남아 있다.

## 복구

과거 자동 배포로 돌아가려면 사용자 승인 후 저장소 `git.deploymentEnabled`와 프로젝트
`gitProviderOptions`를 함께 복구해야 한다. 원래 값은 두 프로젝트 모두 `enabled`였다.
복구 push가 앱을 배포할 수 있으므로 운영 후보/설정/DB 호환성을 먼저 확인한다.
현재 앱을 되돌릴 필요는 없다. 이번 변경은 현재 배포/별칭/환경변수를 건드리지 않는다.
