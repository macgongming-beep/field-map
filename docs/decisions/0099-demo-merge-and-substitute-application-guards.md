# 관리 병합을 보존하고 대신 신청에도 마감과 전시대 중복을 검사한다

- 상태: 데모 검증·배포 완료. 운영 미적용.
- 결정일: 2026-11-17
- 관련: [0098](0098-demo-assignment-revision-maintenance.md), [0097](0097-demo-all-leader-assignment-permissions.md)

## 사용자 결정

인도자가 대신 신청자를 추가할 때도 일반 신청처럼 마감과 같은 일정의 전시대 신청을
확인한다. 관리자도 예외로 두지 않는다. 기존 전시대 신청을 자동으로 취소하지 않는다.
거절 이유를 한국어/중국어/영어로 안내하고, 마감 후 본인 신청 취소는 계속 허용한다.
사용자가 선택한 "일반 신청처럼 마감과 카트 중복 모두 확인"에 따라, 게스트 추가도
마감 검사 대상이다. 늦게 온 사람/게스트를 인도자가 마감 후 예외 추가하는 정책은 채택하지 않았다.

## 보완 내용

1. `merge_duplicate_buildings_tx`의 현재 설치 본문을 비공개 core로 복사한다. 기존 권한,
   주소 후보 처리, 방문 기록 보존을 유지하며 wrapper에서만 관리 작업 표시를 켠다.
   식당 배정의 중복 삭제/기준 건물 이동은 허용하고 해당 일정의 배정 버전을 올린다.
   `merge_selected_duplicate_buildings_tx`도 기존 호출 관계로 이 보호를 받는다.
   다른 작업 폴더에서 진행 중인 병합 변경은 수정하거나 되돌리지 않았다.
2. 봉사 세션 종료와 기존 세션 일괄 종료는 반환된 ID를 확인한다. 권한으로 0행 또는 일부만
   처리되면 성공 기록/안내를 남기지 않는다. 구 참가자 제거 경로는 먼저 자동 세션 ID를
   읽고, 존재한 세션을 모두 삭제했는지 확인한 뒤 나머지 정리를 한다. 처음부터 세션이
   없는 정상 사례는 허용한다. 구 경로 전체를 원자적 RPC로 바꾼 것은 아니다.
3. 대신 신청 RPC는 기존 일정 행 잠금 뒤 `allow_applications`와 같은 `event_id`의
   `event_cart_applications`를 검사한다. 이름은 기존 정규화 규칙과 계정 이름으로
   비교한다. 다른 일정의 전시대 신청은 이 중복 검사 대상이 아니다. 신원·권한·버전
   검사는 유지하며 거절 시 참가자, 기존 전시대 신청, 배정 버전을 바꾸지 않는다.
4. 배정 표 네 개를 참조하는 definer의 실제 `pg_proc` 목록 13개와 공개 실행권한을 고정했다.
   읽기 함수도 보수적으로 포함하며 각 보호 방식을 명시한다. 목록/권한 변경 시
   `auditAssignmentReviewDemo.mjs`가 실패한다. 임의 동적 SQL까지 분석하는 보안 증명은
   아니며, 표를 직접 참조하지 않는 wrapper는 별도 SQL 동작시험으로 확인한다.

## 검증

- 실제 데모 관리/신청 검증 30개 통과. rename/deactivate/FK 삭제 기존 18개에
  마감·전시대 중복·관리자 예외 없음·마감 후 취소·실제 병합/선택 후보 병합을 추가했다.
  한 트랜잭션 안에서 모두 롤백했다. 병합 후 옛 배정 초안 저장도 충돌로 거절된다.
- 실제 API 권한/동시 저장 검증 21개 통과.
- 실제 DB definer 목록과 anon/authenticated 실행권한 감사 통과.
- SQL 단위시험에서 신청 검사 또는 병합 관리 표시를 제거하면 각각 관련 시험이 실패한다.
  세션의 0행 검사를 제거해도 해당 시험이 실패함을 확인하고 즉시 복원했다.
- 전체 자동시험 2,554개, lint 및 TypeScript/배포 빌드 통과.
- 배포된 데모 Playwright 11개 시나리오 통과, 화면 오류 0개. 모바일 430px,
  320px/125%, PC 1440px에서 기존 신청·취소·타 집단 인도자 배정·공유·동시 저장 충돌을
  재검증했다. 마감/전시대 중복 거절 응답을 주입한 화면 시험에서 이유 표시, 입력창 유지,
  신청자 미추가도 확인했다. 실제 서버 거절은 앞의 롤백 검증으로 별도 확인했다.
- 이번 성능 측정도 데모 10개 배정/33개 세션이다. 운영 규모를 대표하지 않는다.

- 운영 적용 전 별도 전환안과 운영 사본 규모 성능 검증은 아직 필요하다.

## 재리뷰와 전환 선행 조건

2026-11-17 후속 코드 재리뷰에서 새 치명적/필수 결함은 보고되지 않았다. 이는 운영
전환 준비가 끝났다는 의미는 아니다. 이번 후속 반영은 문서/작업 규칙에 한정한다.

1. **실제 DB 감사:** 단위시험은 목록 비교기의 동작만 확인한다. 실제 함수 구성은
   DB 감사 스크립트로 전환 단계마다 대조한다. 운영은 데모 reset 항목을 분리한
   단계별 목록을 준비해야 하며, 현재 데모 전용 도구를 운영에 그대로 실행하지 않는다.
2. **관리 함수 유지보수:** 감싸개가 설치된 환경의 rename/purge/merge 본문은 비공개
   core에서 수정한다. 원래 인증 검사와 닫힌 실행권한을 유지하고 공개 wrapper의
   관리 작업 표시도 확인한다. `CLAUDE.md` 협업 규칙에 이를 명시했다.
3. **옛 제외 경로 제거:** 직접 쓰기 차단을 운영에 적용하기 전에, 앱의 기능 플래그
   의존성과 여러 표를 따로 삭제하는 옛 참가자 제외 경로를 제거한다. 현재 데모 코드에
   이 구 경로가 남아 있으므로 제거 완료로 간주하지 않는다. 새 RPC를 사용하지 못하면
   중단/업데이트 안내로 처리해야 하며, RPC 경로 보급 후 엄격 단계로 넘어간다.
