  작업 폴더의 로컬 main/미커밋 작업을 가져오지 않는다. 강제 갱신하지 않는다.

## 설정과 순서

1. 기존 프로젝트/배포/설정 정보를 `backups/nov18-evening-release/`에 로컬 보관했다.
   민감 파일 0600, 폴더 0700이며 Git에 포함하지 않는다.
2. `VITE_SERVICE_CALENDAR_REUSE_ENABLED=true`,
   `VITE_RECIPIENT_INITIAL_PARALLEL_ENABLED=true`를 production에만 추가한다.
   기존 설정의 ID/값/대상과 읽을 수 있는 VITE 값이 그대로인지 대조한다.
3. 민감 설정 5개는 Vercel이 다운로드 시 비워 돌려준다. 이를 운영 설정 누락으로
   오해해 덮어쓰지 않는다. 운영은 Git 기반 Vercel 빌드로 기존 서버 저장 값을 사용한다.
   로컬 데모 검증에서만 데모 DB·키·푸시 키를 쓰고 오류 보고 전송을 끈다.
4. 원격 main을 검증한 후보로 fast-forward한 뒤 운영 프로젝트/커밋/대표 주소 연결을
   확인한다. 다른 작업 폴더의 로컬 main 위치는 바꾸지 않는다.
5. 운영 비로그인 모바일/PC의 로그인 화면·앱 파일·로고 해제를 검사한다.
   운영 성원의 신청/배정/댓글을 시험 목적으로 수정하지 않는다.

설정 추가의 첫 API 요청은 JSON 형식 오류(400)로 거부됐다. 새 키가 0개임을 다시
읽어 확인한 뒤, 프로젝트를 고정한 Vercel env add로 두 키를 각각 추가했다.
실패한 요청을 성공 기록에 포함하지 않는다.
