# 신청 마감 후에도 인도자와 관리자는 참가자를 추가할 수 있다

- 결정일: 2026-11-17
- 상태: 데모 DB·화면 검증 완료. 운영 미적용.
- 대체: [0099](0099-demo-merge-and-substitute-application-guards.md)의 대신 신청 마감 차단만 대체한다.

## 사용자 결정

마감은 일반 성원의 본인 신청을 제한한다. 활성·승인된 인도자/관리자/개발자는
마감 후에도 등록된 봉사자와 계정 없는 게스트를 추가할 수 있다. 일정 인도자 목록에
이름이 있는지와 무관하며, 회중·집단 봉사 모두 같은 배정 관리 권한을 사용한다.
대신 추가한다고 일정의 `allow_applications`를 다시 켜지 않는다.

데모의 전시대 기능은 유지한다. 같은 일정의 전시대 신청과 일반 봉사 신청을 중복으로
만들지 않는다. 기존 화면에서 명시적으로 확인받는 신청 종류 변경은 별도 경로이며,
이번 변경은 그 전환 경로나 전시대 기능 설정을 수정하지 않는다.

## 변경 범위

- 새 마이그레이션 `20261117_1300_allow_staff_add_after_closing.sql`에서
  `manage_event_participant_versioned_tx`의 마감 검사만 제거한다.
- 현재 함수에 관리 권한 검사와 전시대 중복 검사가 있는지 확인하고 기존 마감 검사
  본문이 정확히 맞을 때만 변경한다. 기존 인증, 일정 잠금, 신원 검사, 배정 버전 검사,
  중복 신청 거절과 취소 동작은 유지한다.
- `apply_service_activity_tx`는 변경하지 않는다. 마감 후 일반 봉사/재방·연구 본인 신청은
  계속 차단되며 일반 성원이 관리자용 추가 RPC를 직접 호출해도 권한 검사에서 거절한다.
- UI 코드와 기능 환경변수는 변경하지 않았다. 이미 배포된 추가 화면이 새 서버 정책을 사용한다.

## 적용과 검증

- 데모 프로젝트만 허용하는 `groupTabsDemo.mjs apply-staff-closing --confirm-demo` 사용.
- DB 백업/직전 함수 복원 SQL: `backups/group-tabs-demo-1794879944494/`.
- `psql --single-transaction`으로 적용. 운영 DB·운영 배포·main 미변경.
- 실제 데모 롤백 검증 34개 통과: 마감 후 인도자/관리자의 봉사자/게스트 추가,
  성원 본인 신청 차단, 관리 RPC 우회 차단, 전시대 중복 보존, 마감 후 본인 취소 포함.
- 실제 DB definer 목록과 실행권한 감사 통과. 목록/권한 변경 없음.
- SQL 관련 단위시험 19개 통과. 이번 마이그레이션을 생략하면 관련 2개 시험이 실패한다.
- 전체 자동시험 2,555개, lint 통과.
- 배포된 데모 Playwright 12개 시나리오 통과, 화면 오류 0개. 마감된 실제 검증 일정에서
  이름에 없는 인도자가 봉사자와 게스트를 화면으로 추가한 후, DB의 두 참가자 행과
  `allow_applications=false` 유지를 확인했다. 검증 일정은 삭제했다. 기존 모바일/PC
  탭·신청·취소·공유·동시 저장 충돌 시나리오도 재검증했다.

운영 적용은 0098/0099의 단계별 전환·운영용 DB 감사·복구·운영 사본 성능 검증과
별도 사용자 승인 조건을 그대로 유지한다.
