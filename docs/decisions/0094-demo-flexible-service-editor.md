# 봉사 일정 입력 단순화: 데모

- 상태: 데모 적용, 운영 미적용
- 결정일: 2026-11-16
- 대체 범위: 0093의 두 타임 기본 생성과 주/공동 인도자 입력 구분

## 결정

- 새 회중/집단 일정은 시간대 하나로 시작한다. 시작/종료 시각을 직접 바꾸거나
  시간대를 추가/제거할 수 있다. 최소 하나를 유지하며 기존 일정 삭제와는 별개다.
- 자주 쓰는 시간은 기존 `calendar_time_presets` 설정을 이용한다. 없으면 기기 설정과
  기존 기본값을 이용한다. 이 화면은 선택 기능을 복구하며 프리셋 관리 체계를 새로 만들지 않는다.
- 인도자는 한 목록에서 선택한다. 선택 순서를 보존하고 첫 번째 정확 일치 계정을
  내부 `primary_leader_user_id`로 저장한다. 주/공동 인도자 별도 입력은 없앤다.
- 기존 일정에서 인도자 목록을 건드리지 않으면 기존 primary ID/null을 보존한다.
  과거 일정의 주 인도자를 추정해 채우지 않는다. 인도자 목록을 수정하면 첫 선택을 반영한다.
- 화상 참여 링크, 회의 번호, 비밀번호는 각각 선택사항이며 모두 비어 있어도 저장한다.
  입력된 링크의 HTTPS 검사와 길이 제한은 유지한다. 상세에서는 빈 상태를 표시한다.

## 유지할 계약

각 시간대는 별도 event ID와 반복 series를 가진다. 신청/취소/팀/카드 배정은 독립이다.
함께 수정은 선택한 ID/버전을 검사하고 한 트랜잭션으로 처리한다.
인도자 권한/활성/승인/목록 포함 검사는 서버에서 유지한다.
화상 정보는 비공개 표와 승인 세션 RPC로만 접근하며 알림/Realtime에 노출하지 않는다.
운영 앱, 운영 DB, main, 실제 담당자 및 기존 사용자 일정은 이번 작업으로 바꾸지 않는다.

## 마이그레이션과 복구

`20261116_1040_optional_meeting_access.sql`은 기존 private 검증 함수의
링크/회의 번호 중 하나 필수 조건만 제거한다. 예상 원문이 없으면 실패한다.
데모 전용 도구로 public/private 백업과 함수 rollback을 만든 후 단일 트랜잭션 적용했다.
복구 파일은 해당 실행의 `backups/group-service-demo-*/rollback.sql`에 로컬 보관한다.
다시 필수로 돌리면 이미 빈 정보로 생성한 일정은 다음 저장 때 접속 정보가 필요하다.

## 검증

- 전체 247개 파일, 2,486개 테스트 통과. 빌드와 lint 통과.
- 필수 조건 제거 마이그레이션을 제외한 변형은 새 선택사항 SQL 테스트 하나만 실패.
- React: 기본 한 타임, 추가/제거, 공유 시간 프리셋, 인도자 선택 순서,
  기존 별도 series 반복, 빈 화상 정보 저장과 상세 빈 상태 검증.
- 실제 데모 API 18개 검사 통과: 단일 타임/빈 화상 정보 저장 및 재조회 포함.
  익명 거부, 독립 신청/배정/취소, 교체 권한과 알림도 재검증. 임시 자료는 정리했다.
- Playwright 모바일 430px, 320px/125% 확대, PC 1440px 통과. 한 타임 기본값,
  추가/제거, 시간 선택, 인도자 한 목록, 화상 선택사항, 함께 수정 확인.
  소속 없는 봉사자의 신청/취소와 중국어 상세도 재검증했다. 긴 이름은 좁은 화면에서 줄바꿈한다.
