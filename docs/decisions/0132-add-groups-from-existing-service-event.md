# 기존 집단 봉사 수정에서 집단 추가

- 상태: 승인, 데모 적용 / 운영 미적용
- 결정일: 2026-11-18
- 선행: [0131 집단 목록 연동](0131-stable-service-group-directory.md)

## 변경

기존 독립 집단 일정은 소속 집단을 바꾸면 신청자·배정의 의미가 달라지므로 대상 집단을 잠가 두었다.
이 보호는 유지하면서 수정 화면에 **집단 추가** 선택란을 제공한다.

- 현재 일정의 집단은 읽기 전용으로 유지한다.
- 같은 날짜·시작 시각에 아직 일정이 없는 활성 집단을 선택할 수 있다.
- 선택한 집단은 수정 화면의 날짜·시간·제목·인도자·모임 정보로 **별도 일정**을 만든다.
- 기존 일정 ID와 대상 집단은 그대로다. 기존 신청자·팀·구역배정을 복사하거나 이동하지 않는다.
- 기본은 현재 시간대 하나만 추가한다. 다른 시간대도 `함께 수정`으로 선택하면 해당 시간대에도 추가한다.
- 해당 집단의 다른 시간대 일정이 이미 있으면 그대로 두고, 중복 생성·덮어쓰지 않는다. 시작 시간이 같지만 종료 시간이 다르면 저장 전에 확인 오류를 낸다.
- 다른 집단의 기존 일정은 수정하지 않는다. 다른 날짜나 주간 반복 전체에 자동 확장하지 않는다.
- 기존 연합 일정의 최대 두 집단 수정 방식은 이번에 바꾸지 않았다.

## 저장 계약

기존 `save_service_events_tx` 한 번에 기존 일정 수정 행과 새 일정 생성 행을 같이 보낸다.
DB 마이그레이션, 권한 변경, 새 RPC는 없다. 관리자 일정 수정 권한, 기존 버전 검사, 중복 시간대 방지, 요청 ID 재시도 보호를 그대로 사용한다.
오래된 버전이나 중복 일정 충돌은 전체 저장을 취소한다. 실패하면 입력과 추가 집단 선택을 유지한다.
새 집단에 기존 반복 `series_id`를 재사용하지 않는다.
새 주기 조회나 화면 진입 조회는 추가하지 않는다. 저장 후 갱신도 기존 경로다.

## 검증

- 화면 시험: 한 시간대/함께 선택한 두 시간대 추가, 기존 ID·버전·집단 고정, 다른 집단 일정 제외, 기존 추가 대상의 저녁 일정 보존, 종료 시간 불일치 차단, 실패 후 선택과 동일 요청 ID 유지.
- SQL 시험: 기존 신청자·배정 보존, 새 집단 생성, 같은 요청 재시도 무중복, 중복 생성 실패 시 앞선 수정 롤백, 오래된 버전에서 전체 취소.
- 변이: 새 일정 행을 실제 저장 목록에 넣지 않으면 새 화면 시험 2개가 실패한다. 변이 복구 후 전체 시험 통과.
- 전체 273개 파일 / 2,669개 시험 통과. lint·TypeScript 포함 데모 빌드 통과.
- `scripts/serviceGroupDirectoryDemo.mjs --verify`에 실제 데모의 신청·배정이 있는 일정 확장 검사를 추가했다.
  실제 anon 역할과 승인 관리자 세션으로 수정+추가, 재시도, 충돌을 검사했고 기존 신청·배정 내용 해시가 같았다.
  모든 시험 변경은 한 트랜잭션에서 롤백했다. 전체 사용자·설정·일정·신청·배정의 전후 해시도 같았다.
- 배정 definer 13개와 strict 실행 권한 감사 통과. 운영 DB는 접근하지 않았다.
- Chrome에서 실제 편집기 컴포넌트를 격리된 로컬 화면으로 열고 390px 폭에서 새 집단 선택과 두 시간대 저장을 확인했다. 결과는 기존 ID 1/5 유지 + 새 집단 두 일정 생성 요청이었다. 이 화면은 DB에 저장하지 않는 시험 화면이며, 실제 DB 저장은 위 롤백 검증과 구분한다.
