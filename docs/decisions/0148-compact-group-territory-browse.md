# 집단 구역 관리의 간결한 지도와 큰 목록

- 상태: 데모 적용 및 배포 후 검증 완료, 운영 미적용
- 결정일: 2026-11-20
- 선행: [0147 집단 일정의 구역 범위와 지도 선택](0147-event-group-territory-map.md)

## 변경 이유와 범위

모바일 배정 화면에는 상단 제목과 본문의 큰 제목이 중복되고, 지도에서도
목록 검색칸이 공간을 차지했다. 운영 규모의 수백 구역을 한번에 목록으로
그리는 대신 선택 범위를 좁힐 수 있어야 한다.

- 모바일 호출에서만 `compact`를 전달하여 본문 큰 제목과 이중 여백을 없앤다.
  PC는 본문 제목을 유지하고 화면 읽기용 section 이름도 유지한다.
- 목록/지도 아이콘을 집단/전체 탭 옆으로 옮긴다. 검색은 목록에서만 표시한다.
- 지도 진입 때 검색어를 지운다. 숨은 검색 조건으로 구역이 사라지지 않으며,
  이미 보이는 결과에서 선택한 구역은 지도/목록 왕복에도 유지한다.
- 전체 구역은 지역과 동으로 좁힌다. 필터는 저장된 `region`/`area` 값을 사용하며
  번역된 라벨과 비교하지 않는다. 지역 변경 시 동 선택을 초기화한다.
- 지역/동/검색/집단/탭 변경은 이전 선택을 초기화하여 다른 범위의 구역을
  실수로 저장하지 않게 한다. 저장 중에는 이 선택기와 화면 전환을 잠근다.
- 목록은 처음 50개만 그리고 `더 보기`로 50개씩 늘린다. 표시/총 결과 수를
  함께 표시한다. 서버 페이지 조회가 아니라 이미 받은 자료의 표시 분할이다.
- 목록의 `전체 선택`은 기존처럼 **현재 필터에 맞는 모든 결과**를 선택한다.
  처음 표시한 50개만 고르는 것이 아니다. 선택 숫자와 기존 1000개 상한을
  유지한다. 지도에는 전체 선택을 두지 않고 구역선을 직접 고른다.
- 경계선 없는 구역은 기존처럼 목록에서 선택한다. 공동 담당, 권한, 리비전,
  저장 RPC, 일정 배정 범위, GPS와 개인별 구역 범위는 변경하지 않는다.

## 지도 위치

같은 집단/지역/동에서 지도와 목록을 오갈 때에는 줌과 위치를 유지한다.
집단/탭/지역/동을 명시적으로 바꾸면 새 범위에 맞춘다. 각 범위에 별도 위치
기억 객체를 사용한다. 떠나는 MapCanvas가 unmount 중 이전 위치를 저장하므로,
같은 ref를 null로만 초기화하면 새 범위에 이전 위치가 다시 들어갈 수 있었다.
이 충돌은 별도 객체로 막으며 공통 MapCanvas 자체는 수정하지 않는다.

## 검증

- 전체 시험 292개 파일 2,906개 통과. 지도 기억 객체를 scope key와 묶어
  lint 경고 없이 보존한 뒤 집단 관련 시험 82개도 재통과했다.
- 609개 자동 시험: 최초 50행, 더 보기 100행, 검색 시 페이지 초기화,
  지역/동의 지도·목록 일치, 필터된 구역만 정확한 그룹/수정번호로 저장,
  필터 변경 시 선택 초기화, 모바일 제목 제거/PC 제목 유지 확인.
- 변이: 표시 분할 제거 -> 3개 실패, 지역 조건 제거 -> 1개 실패,
  지도 진입 검색어 초기화 제거 -> 1개 실패, 모든 범위의 지도 기억 공유 ->
  1개 실패. 마지막 시험은 같은 범위 왕복의 줌 유지도 함께 확인한다.
- 실제 데모의 기존 화면과 새 정적 파일을 같은 데모 주소에서 비교했다.
  WebKit 390px 지도 시작 위치 378 -> 254px, 320px 424 -> 254px,
  390px 아주 큰 글씨 530 -> 317px. 상태 표시줄 제외.
  Chromium 1440px는 305 -> 251px. 가로 넘침과 화면 오류 없음.
- 실제 지도 SDK로 가상 구역선 609개를 표시하고 지역 선택 후 203개,
  동 선택 후 102개로 줄어드는 것을 WebKit/Chromium에서 확인했다.
  가상 자료는 운영 자료가 아니며 DB에 넣지 않는다. 원격 운영 성능 측정으로
  해석하지 않는다. SDK/지도 타일 통신은 있으며 추가 DB 요청은 0건이다.
- 실제 데모의 집단 배정 지도 선택, 목록 왕복, 이벤트 집단 범위도 재검증했다.
  테스트 도중 업무 자료 저장은 막았다. 앞서 사용자가 요청한 동탄 테스트
  구역 5개는 유지한다.

## 재현

- `node scripts/buildGroupTerritoryBrowseFixture.mjs`: 데모 지도 키로 가상 자료 화면 빌드.
  `BROWSE_BUILD_ENV`는 데모 `VITE_*` 값이 담긴 JSON 경로를 받을 수 있다.
- `BROWSE_FIXTURE=true LABEL=compact-browse-609-camera node scripts/smokeGroupTerritoryBrowse.mjs`
- `LOCAL_ARTIFACT=<검증 산출물> LABEL=compact-browse-after node scripts/smokeGroupTerritoryBrowse.mjs`
- 기존 화면 비교: `BEFORE=true LABEL=compact-browse-before node scripts/smokeGroupTerritoryBrowse.mjs`
- 이전 기능 확인: `LOCAL_ARTIFACT=<검증 산출물> LABEL=compact-browse-regression node scripts/smokeGroupEventMap.mjs`

실제 앱 검사에는 데모 관리자 로그인을 사용한다. 모든 도구는 운영 Supabase
연결을 거부하고, 업무 저장 RPC와 직접 쓰기를 금지한다. 가상 자료 검사에서는
Supabase 연결 자체를 거부한다. 기록은 위 LABEL의 scratch JSON/PNG에 남긴다.

## 후속: 집단 구역 보기 아이콘

사용자가 예시의 두 번째 구역선 모양(Lucide land-plot)을 선택했다. 공통
`useGroupMapScope`의 접힌 지도 아이콘만 교체하여 PC/모바일을 맞춘다.
아이콘은 Lucide ISC 라이선스의 정적 경로이며 외부 요청이나 의존성을 추가하지 않는다.
안내는 기존처럼 버튼 아래에 겹쳐 표시하고 1800ms 뒤 숨긴다. 헤더 공간을
늘리거나 지도 필터, 조회, 권한, GPS 동작을 변경하지 않는다.

관련 UI/화면 시험 20개와 lint, 데모 빌드가 통과했다. 아이콘 경로를 다른
모양으로 바꾼 변이는 새 시험 1개가 실패하여 검출했다. 브라우저 확인 도구는
`scripts/smokeGroupMapIcon.mjs`이며 운영 연결/업무 쓰기를 거부한다.

앱 소스 `a1f4011`, 산출물 `scratch/group-territory-release-landplot`을 데모에
1회 배포했다(`dpl_VsWb3iETFPy95WtKTaE2E3fTxeZq`, READY). 로컬 산출물과
배포된 데모 양쪽에서 WebKit 390/320px, 390px 큰 글씨 및 Chromium 1440px를
확인했다. 안내는 버튼 아래/화면 안에 표시되고 사라지며, 표시 전후 헤더 높이는
같다. 결과는 `scratch/group-map-landplot-local.json`과
`scratch/group-map-landplot-deployed.json`. 최초 PC 검사는 토글 후 버튼 이동으로
포인터가 벗어나 안내가 닫혀 대기 실패했다. PC에서는 키보드 포커스로 안내를
확인하도록 검사만 수정하여 재통과했다. 운영 앱/DB는 변경하지 않았다.

## 재리뷰 후 선택 보호 시험 보강

Claude의 `a4b6f18` 리뷰는 필수 기능 결함을 찾지 못했으나 서로 다른 보호가
겹쳐 가려진 시험 공백 네 가지를 지적했다. 다음 시험만 추가하고 앱 코드는
그대로 유지했다. 운영/데모 DB 접근 및 배포는 하지 않았다.

| 새 시험 | 보호를 제거했을 때의 결과 |
| --- | --- |
| 첫동에서 선택 후 둘동으로 갔다가 첫동으로 복귀하면 선택 없음 | 동 변경의 `resetFilter()` 제거: 이 시험만 실패 |
| 선택 후 다른 구역을 검색하고 검색어를 지워도 선택 없음 | 검색 변경의 `setChecked(new Set())` 제거: 이 시험만 실패 |
| 체크한 두 구역 중 하나가 자료 갱신으로 현재 지역 밖으로 이동한 뒤 저장 | `targets`를 `filtered` 대신 `cards`로 계산: 이 시험만 실패, 숨은 구역이 저장 인자에 섞임 |
| 범위 밖 지도 콜백 후 담당 자료가 갱신되어 그 구역이 보이더라도 선택 없음 | `visibleIds` 검사 제거: 이 시험만 실패, 숨었던 체크가 나타남 |

저장 시험은 유효한 구역 하나를 계속 선택해 두므로 저장 자체를 막는 코드로
통과할 수 없다. 저장 인자에는 화면에 남은 구역과 최신 수정번호만 포함되어야
한다. 지도 콜백 시험도 잘못된 콜백을 무시한 뒤 정상 클릭/해제 저장이 되는지
확인한다. 자료 갱신은 필터 변경 없이 `rerender`로 전달하여 선택 초기화에
기대지 않는다. 서버 동시성 시험이 아니라 화면의 저장 인자 검증이다.

각 변이는 두 시험 파일의 15개 시험 전체를 실행했으며 매번 해당 새 시험
1개만 실패하고 14개는 통과했다. 변이 원복 후 집단 구역 관련 10개 파일
87개 시험, TypeScript 및 변경 시험 파일 lint 통과. 앱 코드 diff는 0이다.
전체 시험과 브라우저/사용량 측정은 이번 시험 전용 변경에서 다시 실행하지
않았다. 기존 실물 기기/실제 공유 저장 검증의 한계도 그대로 남는다.
