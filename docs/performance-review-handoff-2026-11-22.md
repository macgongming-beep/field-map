## 재현 방법

1. `CLAUDE.md`를 읽고 브랜치/HEAD/작업 파일 상태를 확인한다. 원본 폴더에서 checkout,
   switch, reset, merge를 하지 않는다. 이전 리뷰에서 원본 HEAD가 옮겨진 사고가 있었다.
2. 격리된 임시 복사본에 리뷰 기준을 추출하고 그곳에서 시험/변이를 돌린다. 라이브 앱에
   접속하는 도구는 먼저 코드와 쓰기 차단을 읽고 실행한다. `smoke:*` 중 쓰기를 허용하는
   명령, `backup`, `restore`, SQL 적용 명령은 이번 리뷰에 필요 없다.
3. `npm test`, `npx tsc -b`, `npm run lint`. 화면 build는 검증한 데모 설정을 명시해서 한다.
4. 성능 측정은 역할/버전을 번갈아 순차 실행한다. 시험/변이/build와 동시에 실행하지
   않는다. 요청 완료/조용한 구간까지 기다리고 중간 실패 결과는 별도 보관한다.

로컬 전용 증거/도구는 원본 폴더에 있으며 Git에는 전부 들어 있지 않다.
같은 Mac의 격리 복사본에서 필요 파일만 읽거나 복사한다. 다른 기기로 비밀 파일을 옮기지 않는다.

| 묶음 | 기록과 도구 |
| --- | --- |
| 홈 선로딩 | `scratch/home-preload-nov22/`, `scratch/measure-home-preload.mjs`, `scratch/mutate-home-preload.mjs` |
| OFF 보강 | `scratch/sections-nov22/optout-*`, `scratch/mutate-discovery-optout-nov22.mjs` |
| 홈 조회 | `scratch/home-demand-nov22/`, `scratch/measure-home-demand-nov22.mjs`, `scratch/mutate-home-demand-nov22.mjs` |

`measure-*`는 이미 준비된 before/after 산출물을 읽는다. 해당 `build-*` 명령은 **현재
checkout을 지정한 라벨로 빌드**하므로, before라고 입력한다고 과거 소스가 되는 것은 아니다.
기존 before를 덮어쓰지 말고 과거 기준 소스로 분리 빌드한다. 도구의 로컬 경로도 확인한다.
개인 식별자/쿼리가 있는 원본 로그, 환경 값, PIN, 토큰은 최종 보고서/공개 저장소에 넣지 않는다.

## 후속 작업 순서

1. 네 미리뷰 묶음을 각각 승인/보완/보류로 판단하고, 최신 통합 상태의 회귀도 확인한다.
   중요도·파일/줄·재현 조건·영향·시험 공백을 우선 보고한다. 기록만 읽은 것과 직접
   실행한 것을 구분한다. 통과한 시험 수만으로 승인하지 말고 주요 보호를 변이로 확인한다.
2. 필수 문제는 작은 변경으로 보완하고 다시 검증한다. 해결 후 나의 봉사 **첫 표시 전**
   일정 색인→일정→공유 팀 배정의 직렬 구간부터 분석한다. 개인 범위 확인/삭제 일정 제외/
   같은 팀 공유 범위를 생략하거나 캐시 유효시간을 늘려 숫자만 줄이지 않는다.
3. 다음으로 인도자 건물/세대 상세를 조사한다. 첫 화면/식당/재방문/지도/상세 편집의
   실제 소비자를 나누고, 미뤄도 되는 자료만 별도 대기/실패·재시도 보호와 함께 분리한다.
4. 개선은 한 묶음씩 데모에서 전후 요청 수·응답 원문·첫 표시·전체 완료·재진입을
   측정하고 사용자에게 결과를 알린다. 효과 없거나 시간 편차면 그대로 보고한다.

## 배포와 설정 주의

- 최신 데모 build 프로필은 `backups/sections-optin-20261122/build-values.json`이다.
  `VITE_RECIPIENT_DISCOVERY_REUSE_ENABLED=true`, `VITE_ROUTE_LIGHTWEIGHT_ENABLED=true`.
  이 파일은 비밀 값 포함이며 Git/보고서/외부 전송 금지다.
- 두 설정은 운영에서는 OFF다. 원격 데모 환경변수만 그대로 받아 build하면 검증한
  프로필과 달라질 수 있다. 예전 demo-production-sync 프로필로 되돌리지 않는다.
- 운영 main 병합/push, 운영 배포/승격, DB 변경, 운영 환경변수 수정 금지.
  운영 반영은 사용자가 리뷰 결과를 보고 별도로 결정한다.
- 리뷰만 하거나 문서/시험만 바꿨다면 배포하지 않는다. 앱을 실제 보완해 데모 배포가
  필요할 때만 0138의 `deploy:demo` 공식 단일 경로로 검증된 산출물 1회를 올린다.
  `scratch/release-service-entry-nov22.mjs`는 이번 기준에 묶인 도구이므로 그대로 재실행하지
  말고 source/대상/사전 상태/출력 폴더를 확인한다.
- 현재 Codex는 이 문서 전달 뒤 앱 코드 변경을 계속하지 않는다. Claude가 작업을 맡으면
  동시 수정 없이 이어간다. 이 파일은 인계 준비이며 Claude에게 자동 전송된 증거는 아니다.
